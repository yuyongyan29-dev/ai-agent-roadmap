# U5.6 · 小程序（14 小时）

**这个单元解决什么问题**

把你的 Agent 装进微信，让别人在微信里就能用。

**技术选型：[Taro](https://taro-docs.jd.com/)。** 它用 React 语法写小程序，U5.2 学的 React 能直接复用，同一套代码还能编译到多端。

**如果只做微信一端且要求极致性能**，用微信原生开发也行，但你要多学一套语法。

**学完你能做到**：一个能在真机上跑、能调通你线上 Agent 的微信小程序。

---

## 步骤 0 · 先了解限制

### 这一步在做什么

**小程序的限制会直接影响你的设计，先知道再动手，别做完了才发现要重写。**

### 五个硬限制

| 限制 | 具体 | 影响 |
|---|---|---|
| **域名白名单** | 只能请求配置在后台的域名，**必须 HTTPS，不能用 IP** | 本地开发要用内网穿透或勾选「不校验域名」 |
| **包体积** | 主包通常 2MB 上限 | 图片要压缩或放 CDN |
| **没有 DOM** | 不能用 `document`、`window`、浏览器 API | 很多 npm 包用不了 |
| **`request` 不支持标准 SSE** | 流式输出是个坑 | 见步骤 4 |
| **审核** | 上架要审核，AI 类目可能需要资质 | 本单元不要求上架 |

### 账号注册

去 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册小程序账号。

**个人主体可以注册**，但**不能做某些类目**（涉及内容发布、社交等）。**如果你的项目涉及这些，提前查清楚。**

拿到 AppID，后面配置要用。

### 可能卡在哪

**个人主体不能做我的类目**

**本单元的目标是「真机能跑」，不是「上架」。** 开发和真机预览不需要类目审核，先做出来再说。

## 步骤 1 · 环境和项目

### 这一步在做什么

跑起来 Hello World。

### 怎么做

**装微信开发者工具**：官网下载，登录你的微信。

**建 Taro 项目**：

```bash
cd s5-frontend
pnpm create taro@latest miniapp
```

选：React、TypeScript、pnpm、模板选默认。

```bash
cd miniapp
pnpm install
pnpm dev:weapp          # 编译成微信小程序，产物在 dist/
```

**在微信开发者工具里**：导入项目 → 选择 `dist` 目录 → 填 AppID。

**开发时勾上「不校验合法域名」**（在开发者工具的详情 → 本地设置里），否则连不上你的本地后端。

### 可能卡在哪

**编译报错**

Taro 对 Node 版本有要求。用 `fnm` 切到 LTS 版本（U5.1 装的）。

**开发者工具打不开项目**

确认导入的是 `dist` 目录（编译产物），不是项目根目录。

**改了代码没更新**

`pnpm dev:weapp` 要一直跑着（它是 watch 模式）。开发者工具会自动检测 dist 的变化。

## 步骤 2 · Taro 和 React 的差异

### 这一步在做什么

搞清楚哪些 React 知识能直接用，哪些要改。

### 能直接用的

- 组件、props、`useState`、`useEffect`
- 列表渲染、条件渲染
- TypeScript

**U5.2 学的心智模型完全适用。**

### 要改的

**一、标签不一样**

```tsx
// Web
<div>...</div>
<span>...</span>
<input />
<img src="..." />

// Taro
import { View, Text, Input, Image } from "@tarojs/components";
<View>...</View>
<Text>...</Text>
<Input />
<Image src="..." />
```

**记住四个就够开始了**：`View`（相当于 div）、`Text`（相当于 span，**文字必须包在 Text 里**）、`Input`、`ScrollView`。

**「文字必须包在 Text 里」是最容易忘的**。写 `<View>你好</View>` 在小程序里可能不显示。

**二、样式单位**

小程序用 `rpx`（响应式像素），750rpx = 屏幕宽度。

```css
.box { width: 750rpx; }     /* 满屏宽 */
.item { padding: 20rpx; }
```

**Tailwind 在 Taro 里能用**（需要配置），但要注意单位转换。**如果配置麻烦，直接写 CSS 模块也行。**

**三、路由**

```tsx
import Taro from "@tarojs/taro";

Taro.navigateTo({ url: "/pages/chat/index?id=123" });     // 跳转
Taro.navigateBack();                                       // 返回
Taro.redirectTo({ url: "..." });                          // 替换当前页

// 取参数
const { id } = Taro.getCurrentInstance().router?.params ?? {};
```

**页面要在 `app.config.ts` 里注册**：

```typescript
export default {
  pages: [
    "pages/index/index",
    "pages/chat/index",
    "pages/settings/index",
  ],
  window: { navigationBarTitleText: "我的助手" },
};
```

**四、网络请求**

```tsx
const r = await Taro.request({
  url: "https://你的域名/api/tasks",
  method: "POST",
  data: { 输入 },
  header: { "Content-Type": "application/json" },
});
console.log(r.data);
```

**注意**：不是 `fetch`，返回结构也不同（`r.data` 而不是 `await r.json()`）。

**五、存储**

```tsx
Taro.setStorageSync("token", token);
const token = Taro.getStorageSync("token");
```

**相当于 localStorage，但是同步 API。**

### 可能卡在哪

**很多 npm 包用不了**

因为它们依赖 DOM。**装之前先查有没有小程序版本**，或者找纯 JS 的替代。

**样式和 Web 不一样**

小程序的 CSS 支持是子集。**不支持的**：部分选择器、部分属性。遇到不生效的先查文档。

## 步骤 3 · 微信登录

### 这一步在做什么

打通账号，和 U5.5 的 Web 账号体系用同一套。

### 流程

```
小程序调 Taro.login() 拿到 code
        ↓
把 code 发给你的后端
        ↓
后端用 code + AppID + AppSecret 调微信接口，换到 openid
        ↓
后端根据 openid 找到或创建用户，签发你自己的 token
        ↓
小程序存下 token，之后的请求都带上
```

### 前端

```tsx
async function 登录() {
  const { code } = await Taro.login();
  const r = await Taro.request({
    url: "https://你的域名/api/auth/wechat",
    method: "POST",
    data: { code },
  });
  Taro.setStorageSync("token", r.data.token);
  return r.data.用户;
}
```

### 后端（在你的 Next.js 里加一个路由）

```typescript
// src/app/api/auth/wechat/route.ts
export async function POST(req: Request) {
  const { code } = await req.json();

  const r = await fetch(
    `https://api.weixin.qq.com/sns/jscode2session?appid=${process.env.WX_APPID}` +
    `&secret=${process.env.WX_SECRET}&js_code=${code}&grant_type=authorization_code`,
  );
  const { openid, errcode, errmsg } = await r.json();
  if (errcode) {
    return Response.json({ 错误: errmsg }, { status: 400 });
  }

  const 用户 = await 找到或创建用户({ 微信openid: openid });
  const token = await 签发token(用户);
  return Response.json({ token, 用户 });
}
```

**`WX_SECRET` 绝对不能出现在小程序端**，只能在服务端。

### 可能卡在哪

**`code` 只能用一次**

每次调 `Taro.login()` 拿到的 code 只能换一次 openid，而且有效期很短（5 分钟）。**不要缓存 code。**

**openid 和 unionid**

- `openid`：同一个用户在不同小程序里的 id 不同
- `unionid`：同一个微信开放平台下的所有应用共享

**如果你的 Web 端也要用微信登录，需要 unionid 才能关联同一个人。** 这需要在微信开放平台绑定。

**练手阶段用 openid 就够。**

## 步骤 4 · 流式输出（这是最大的坑）

### 这一步在做什么

**小程序的 `Taro.request` 不支持标准 SSE。** 这一步解决怎么让用户看到进度。

### 三种方案

**方案一：轮询（最简单，先用这个）**

```tsx
function useTaskPolling(taskId: string | null) {
  const [状态, 设状态] = useState<任务状态 | null>(null);

  useEffect(() => {
    if (!taskId) return;
    let 停止 = false;

    const 轮询 = async () => {
      while (!停止) {
        const r = await Taro.request({
          url: `https://你的域名/api/tasks/${taskId}`,
          header: { Authorization: `Bearer ${Taro.getStorageSync("token")}` },
        });
        设状态(r.data);
        if (["completed", "failed", "cancelled"].includes(r.data.状态)) break;
        await new Promise(res => setTimeout(res, 1500));
      }
    };
    轮询();

    return () => { 停止 = true; };
  }, [taskId]);

  return 状态;
}
```

**你的 `GET /tasks/{id}` 接口（U4.3 做的）已经返回了「已完成的步骤」**，所以轮询能拿到进度。

| 优点 | 缺点 |
|---|---|
| 简单，一定能跑通 | 有延迟（1.5 秒） |
| 不依赖特殊能力 | 请求次数多 |

**方案二：`onChunkReceived`（需要较新的基础库）**

微信的 `wx.request` 在较新的基础库版本支持 `enableChunked` 和 `onChunkReceived`，可以接收分块传输。

**需要自己解析 SSE 格式**，而且要处理基础库版本兼容。

**方案三：WebSocket**

```tsx
const socket = Taro.connectSocket({ url: "wss://你的域名/ws/tasks/xxx" });
socket.onMessage(({ data }) => { ... });
```

**需要后端额外实现 WebSocket 接口。**

### 建议

**先用轮询跑通整个流程**，功能完整了再考虑优化。

**1.5 秒的延迟在小程序场景下是可以接受的**——用户预期本来就没有 Web 那么高。

### 可能卡在哪

**轮询太耗流量**

优化：任务刚提交时轮询快（1 秒），跑久了变慢（3 秒、5 秒）。

**页面切走了还在轮询**

用 Taro 的生命周期：

```tsx
import { useDidHide, useDidShow } from "@tarojs/taro";

useDidHide(() => 暂停轮询());
useDidShow(() => 恢复轮询());
```

## 步骤 5 · 页面实现

### 这一步在做什么

做出三个核心页面。

### 页面清单

**首页 `pages/index/index`**

- 会话列表
- 新建对话按钮
- 下拉刷新

**对话页 `pages/chat/index`**

- 消息列表（用 `ScrollView`）
- 执行过程展示（U5.4 的简化版）
- 输入框 + 发送
- 停止按钮

**设置页 `pages/settings/index`**

- 用户信息
- 剩余额度
- 退出登录

### 小程序特有的交互

```tsx
// 下拉刷新（要在页面配置里开启）
import { usePullDownRefresh } from "@tarojs/taro";
usePullDownRefresh(async () => {
  await 刷新();
  Taro.stopPullDownRefresh();
});

// 触底加载更多
import { useReachBottom } from "@tarojs/taro";
useReachBottom(() => 加载更多());

// 提示
Taro.showToast({ title: "已发送", icon: "success" });
Taro.showLoading({ title: "处理中" });
Taro.hideLoading();

// 确认对话框（可以用于 U4.4 的人工确认）
const { confirm } = await Taro.showModal({
  title: "确认操作",
  content: "将删除 12 条草稿，此操作不可撤销",
});
```

**`Taro.showModal` 正好可以实现人工确认。** 比 Web 端还简单。

### 可能卡在哪

**ScrollView 滚动不了**

必须给它固定高度：

```tsx
<ScrollView scrollY style={{ height: "calc(100vh - 200rpx)" }}>
```

**输入框被键盘遮挡**

小程序的 `Input` 有 `adjust-position` 属性（默认 true）会自动上推。如果还有问题，用 `cursor-spacing` 调整。

**滚动到底部**

```tsx
<ScrollView scrollY scrollIntoView={最后一条消息的id}>
  {消息.map(m => <View key={m.id} id={`msg-${m.id}`}>...</View>)}
</ScrollView>
```

## 步骤 6 · 真机预览

### 这一步在做什么

**在开发者工具里能跑，不代表真机能跑。**

### 怎么做

1. 开发者工具里点「预览」，生成二维码
2. 手机微信扫码
3. **完整走一遍所有功能**

### 真机上常见的问题

| 问题 | 原因 |
|---|---|
| **网络请求失败** | 真机会校验域名白名单（开发者工具的「不校验域名」只对工具生效） |
| 样式错乱 | 不同机型的屏幕比例、安全区域 |
| 性能卡顿 | 列表太长没做虚拟滚动、图片太大 |
| **键盘遮挡输入框** | 真机键盘和模拟器不同 |

**第一条是最常见的。** 真机预览前必须在小程序后台配好 request 合法域名，且域名必须是 HTTPS + 已备案。

### 本地开发怎么真机测

用内网穿透工具（ngrok、cpolar 等）把本地服务暴露成 HTTPS 域名，然后配到白名单里。

**或者直接连你 U4.7 部署的线上服务** —— 这是更简单的做法，反正你已经部署好了。
