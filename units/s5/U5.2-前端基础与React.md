## 步骤 1 · HTML/CSS 够用就行

### 这一步在做什么

只学你会用到的那部分。

### 需要掌握的 HTML

就这些标签，别的用到再查：

```html
<div>      通用容器
<span>     行内容器
<button>   按钮
<input>    单行输入
<textarea> 多行输入
<form>     表单
<ul><li>   列表
<a>        链接
<img>      图片
<pre><code> 代码块
```

### 需要掌握的 CSS：只有布局

**现代布局基本就靠两个：Flexbox 和 Grid。**

**Flexbox（一维布局，最常用）**：

```css
/* 对话界面外层就是这种纵向 flex；下面四个属性放在一起，是为了对照主轴和交叉轴各归谁管 */
.chat-container {
  display: flex;
  flex-direction: column;      /* row 横向，column 纵向 */
  gap: 12px;                   /* 子元素间距 */
  align-items: center;         /* 交叉轴对齐 */
  justify-content: space-between;  /* 主轴对齐 */
}
/* flex: 1 让它吃掉剩余空间，兄弟元素保持自己的固定高度 */
.flex-item { flex: 1; }
```

**理解 Flexbox 的关键**：先确定 `flex-direction`（主轴方向），然后 `justify-content` 管主轴，`align-items` 管交叉轴。**搞混这两个是最常见的困惑。**

**Grid（二维布局）**：

```css
/* 侧边栏 + 主区这种两栏结构，用 grid 比嵌套 flex 更直接 */
.grid-layout {
  display: grid;
  grid-template-columns: 200px 1fr;   /* 左边固定 200px，右边占剩余 */
  gap: 16px;
}
```

**你的对话界面大概是这个结构**：

```
外层 flex column（占满高度）
├── 顶栏（固定高度）
├── 消息区（flex: 1，可滚动）
└── 输入区（固定高度）
```

### 用 Tailwind 而不是手写 CSS

```html
<!-- 布局直接写在 class 里，不需要另起类名、也不用切到 CSS 文件 -->
<div class="flex flex-col gap-3 p-4">
  <!-- flex-1 + overflow-y-auto 两个必须成对出现，只有一个不会滚动 -->
  <div class="flex-1 overflow-y-auto">...</div>
  <input class="border rounded px-3 py-2 w-full" />
</div>
```

**Tailwind 的原子类对应关系**：

| Tailwind | CSS |
|---|---|
| `flex flex-col` | `display:flex; flex-direction:column` |
| `gap-3` | `gap: 0.75rem` |
| `p-4` | `padding: 1rem` |
| `flex-1` | `flex: 1` |
| `overflow-y-auto` | `overflow-y: auto` |
| `md:flex-row` | 屏幕宽于 md 时改成横向 |
| `dark:bg-gray-800` | 暗色模式下的背景色 |

**为什么用 Tailwind**：不用起类名、不用在两个文件之间跳、不会有全局样式冲突。**对不擅长 CSS 的人尤其友好。**

### 可能卡在哪

**布局出来不是我想的样子**

用浏览器开发者工具（`Cmd+Option+I`），选中元素看它实际的盒模型和 flex 属性。**不要靠猜。**

**内容溢出了**

滚动容器要同时有：固定的高度（或 `flex: 1`）和 `overflow-y: auto`。**只有一个不行。**

**想学系统的 CSS**

**现在不要。** 遇到具体问题再查。系统学 CSS 是另一条学习路径，会吃掉你几周时间。

## 步骤 2 · React 的心智模型

### 这一步在做什么

**在写代码之前，先建立正确的思维方式。这比语法重要得多。**

### 核心：UI 是状态的函数

```
UI = f(state)
```

**你永远不直接改界面，你改状态，React 负责重新渲染界面。**

对比两种思维：

```javascript
// 传统（命令式）：自己找到节点、自己算出新内容、自己写回去，
// 界面和数据是两份，一旦漏改一处就不一致
document.getElementById("count").innerText = count + 1;

// React（声明式）：只改数据，谁该重画由 React 决定
setCount(count + 1);
// 界面自动更新
```

**这个转变是学 React 最大的门槛。** 如果你发现自己想「怎么让这个元素变红」，停下来，改成想「什么状态决定它是红的」。

### 组件就是函数

```tsx
// role 只允许两个字面量值，写错拼写 TS 直接报错，不用等到运行时才发现
function MessageBubble({ content, role }: { content: string; role: "user" | "assistant" }) {
  return (
    // 用户消息靠右、助手消息靠左：外观由数据决定，不是手动加 class
    <div className={role === "user" ? "text-right" : "text-left"}>
      {content}
    </div>
  );
}

// 用它
<MessageBubble content="你好" role="user" />
```

**props 是参数，返回值是界面。** 就是一个函数。

**命名约定**：组件名用 PascalCase（`MessageBubble`），props 和普通变量用 camelCase（`content`、`role`）。React 靠首字母大小写区分组件和 HTML 标签，小写开头会被当成原生标签。

## 步骤 3 · useState 和状态设计

### 这一步在做什么

学会管理会变化的数据。

### 基本用法

```tsx
import { useState } from "react";

function Counter() {
  // useState(0) 里的 0 只在首次渲染生效，之后重渲染不会把 count 重置回 0
  const [count, setCount] = useState(0);

  return (
    // onClick 里要传函数本身，不能写成 setCount(count + 1) 直接调用，
    // 否则渲染时就执行了，会触发无限重渲染
    <button onClick={() => setCount(count + 1)}>
      点了 {count} 次
    </button>
  );
}
```

**`useState` 返回一个数组：当前值 + 修改函数。**

### 三条重要规则

**一、不要直接改状态，要创建新的**

```tsx
// 错误：直接改数组
messages.push(newMessage);
setMessages(messages);              // React 看不出变化，不会重渲染

// 正确：创建新数组
setMessages([...messages, newMessage]);
```

**为什么**：React 用引用比较判断有没有变化。改了内容但引用没变，它认为没变。

**这是 React 新手第一大坑。**

**二、连续更新用函数式写法**

```tsx
// 有问题
setCount(count + 1);
setCount(count + 1);           // 只加了 1，因为两次读到的都是本次渲染里那个旧的 count

// 正确
setCount(c => c + 1);
setCount(c => c + 1);          // 函数式写法拿到的是上一次更新后的值，加了 2
```

**三、状态要放在合适的层级**

如果两个组件都需要某个状态，把它提升到它们共同的父组件里。**这叫「状态提升」。**

### 状态设计：想清楚需要哪些

对话界面需要的状态：

```tsx
const [messages, setMessages] = useState<Message[]>([]);   // 整个对话历史
const [input, setInput] = useState("");                    // 输入框当前内容（受控组件）
const [loading, setLoading] = useState(false);             // 请求进行中，用来禁用输入和按钮
const [error, setError] = useState<string | null>(null);   // null 表示无错误，字符串就是要显示的提示
```

**四个状态就够了。**

**避免「派生状态」**：

```tsx
// 不好：消息数量是可以算出来的，不该单独存
const [messageCount, setMessageCount] = useState(0);

// 好：每次渲染直接算，永远不会和 messages 不同步
const messageCount = messages.length;
```

**能算出来的就不要存。** 存了就要同步，同步就会出 bug。

## 步骤 4 · 列表渲染和 key

### 这一步在做什么

**`key` 用错是 React 第二大坑，单独讲。**

### 怎么做

```tsx
{/* key 放在 map 直接返回的那个元素上，不是它内部的子元素上 */}
{messages.map(m => (
  <MessageBubble key={m.id} content={m.content} role={m.role} />
))}
```

### key 的作用

React 用 `key` 判断「这次渲染的这一项，和上次渲染的哪一项是同一个」。

**用数组下标当 key 会出问题**：

```tsx
{items.map((item, i) => <Item key={i} ... />)}     // 危险
```

假设列表是 `[A, B, C]`，你删掉 A，变成 `[B, C]`。

- 用下标：B 的 key 从 1 变成 0，React 认为「key=0 的东西内容从 A 变成了 B」，会复用 A 的 DOM 节点和状态
- 用稳定 id：B 的 key 一直是 `id_b`，React 知道 A 被删了，B 没变

**后果**：输入框里的内容跑到别的项上、动画错乱、组件内部状态串了。

**规则：key 必须是数据本身的稳定唯一标识。** 消息用消息 id，用户用用户 id。**实在没有 id 就在创建数据时生成一个。**

### 可能卡在哪

**没有 id 怎么办**

创建时生成：

```tsx
const newMessage = { id: crypto.randomUUID(), content, role };
```

`crypto.randomUUID()` 是浏览器内置的，不用装库。

## 步骤 5 · useEffect

### 这一步在做什么

**React 里最容易出错的 hook，慢慢来。**

### 它是干什么的

处理「渲染之外的事」：订阅、定时器、手动操作 DOM、和外部系统同步。

```tsx
useEffect(() => {
  // 渲染后执行
  const timer = setInterval(() => console.log("tick"), 1000);

  return () => {
    // 清理函数：组件卸载或依赖变化时执行。
    // 不清理的话，每次依赖变化都会新起一个定时器，旧的还在跑
    clearInterval(timer);
  };
}, []);          // 依赖数组
```

### 依赖数组的三种写法

| 写法 | 什么时候执行 |
|---|---|
| `[]` | 只在组件挂载时执行一次 |
| `[a, b]` | 挂载时 + a 或 b 变化时 |
| 不写 | **每次渲染都执行**（几乎总是错的） |

### 常见错误

**忘记清理**：

```tsx
useEffect(() => {
  const t = setInterval(...);
  // 忘了 return 清理函数 → 组件卸载后定时器还在跑，内存泄漏
}, []);
```

**依赖数组漏了东西**：

```tsx
useEffect(() => {
  fetchData(userId);
}, []);              // 漏了 userId！用户切换时不会重新取
```

**装 ESLint 的 react-hooks 插件**，它会自动检查依赖数组。

**用 useEffect 做本不该它做的事**：

```tsx
// 不好：用 effect 同步派生状态，多渲染一轮，中间还有一帧是旧值
const [total, setTotal] = useState(0);
useEffect(() => { setTotal(items.length); }, [items]);

// 好：直接算
const total = items.length;
```

### 你的对话界面会用到的一个 effect

自动滚动到底部：

```tsx
// useRef 存的是一个跨渲染保持不变的容器，改它不会触发重渲染，
// 正适合放「指向某个 DOM 节点」这种和渲染无关的东西
const bottomRef = useRef<HTMLDivElement>(null);

useEffect(() => {
  // ?. 是因为首次渲染完成前 current 还是 null
  bottomRef.current?.scrollIntoView({ behavior: "smooth" });
}, [messages]);       // 消息变化时滚动

// JSX 里：放在消息列表最后，作为「底部」这个位置的锚点
<div ref={bottomRef} />
```

### 可能卡在哪

**effect 执行了两次**

开发模式下 React 会故意执行两次来帮你发现清理逻辑的问题。**生产环境只执行一次。**

如果两次执行导致问题（比如发了两次请求），说明你的清理逻辑不对。

**什么时候需要 useEffect**

**大多数时候不需要。** 判断：这件事是不是「和外部系统同步」？不是的话多半不需要 effect。

计算派生值、响应用户事件，都不需要 effect。

## 步骤 6 · 实战：对话界面

### 这一步在做什么

把前面的东西用起来。

### 建项目

```bash
cd s5-frontend
# react-ts 模板自带 TypeScript 配置，不用自己拼 tsconfig
pnpm create vite chat-ui --template react-ts
cd chat-ui
pnpm install
# Tailwind 只在构建时用，装成 devDependency
pnpm add -D tailwindcss @tailwindcss/vite
```

（Tailwind 的接入方式按官方文档当前版本来，v4 和 v3 的配置方式不同。）

```bash
pnpm dev
```

### 要实现的

```
┌─────────────────────────┐
│ 顶栏：标题 + 清空按钮      │
├─────────────────────────┤
│                         │
│  消息列表（可滚动）        │
│  用户消息靠右             │
│  助手消息靠左             │
│  加载中显示占位            │
│  错误显示错误条            │
│                         │
├─────────────────────────┤
│ 输入框 + 发送按钮         │
└─────────────────────────┘
```

**数据先用假的**，模拟一秒后返回：

```tsx
// 先用假数据把界面的加载态和错误态都跑通，接真接口时只换这个函数
const fakeReply = async (text: string): Promise<string> => {
  // 延迟一秒，否则加载态一闪而过，看不出禁用输入框有没有生效
  await new Promise(r => setTimeout(r, 1000));
  // 留一个能主动触发失败的开关，用来验证错误提示和重试
  if (text.includes("错误")) throw new Error("模拟错误");
  return `你说的是：${text}`;
};
```

### 检查清单

- [ ] 消息能增加
- [ ] 加载中禁用输入框和按钮
- [ ] 出错显示错误提示，且能重试
- [ ] 新消息自动滚到底部
- [ ] 输入框回车发送，Shift+回车换行
- [ ] 空输入不能发送
- [ ] 清空按钮能清空
- [ ] **没有直接操作 DOM 的代码**（`document.getElementById` 之类）

### 可能卡在哪

**回车发送怎么做**

```tsx
onKeyDown={(e) => {
  // 只有不按 Shift 的回车才算发送，Shift+回车留给换行
  if (e.key === "Enter" && !e.shiftKey) {
    // 拦掉默认的插入换行，否则发送完输入框里还留着一个空行
    e.preventDefault();
    send();
  }
}}
```

**为什么我改了状态界面没更新**

九成是直接改了数组或对象（步骤 3 的规则一）。检查有没有用展开运算符创建新的。
