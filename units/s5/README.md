# Stage 5 · 产品外壳：Web / 小程序 / App（W29–W35，96 小时）

**目标**：给你的 Agent 做出别人愿意用的界面，三端都能上线，并且知道先做哪一端、为什么。

**这一阶段的代码几乎全部由 agent 写。** 你的工作是选型、写验收、审 diff、上线。但有两处你必须自己读懂，因为 agent 在这两处最容易写出「能跑但会出事」的代码：U5.3 的 Server/Client 区分（密钥会不会漏到浏览器）和 U5.5 的数据隔离（用户 A 会不会看到用户 B 的数据）。

## 心理准备

**有了 Python 基础后读 TypeScript 会比想象中快**，很多概念是相通的。

**但 CSS 和布局是另一套思维，不要低估。** 这七周的目标是「能做出可用的界面」，不是「成为前端工程师」。CSS 交给 agent，你只管在真机上看效果，**不要系统学**——那会吃掉你好几周。

**三端不是三倍工作量。** React 组件、状态管理、调后端的逻辑三端共用，真正不同的是路由、打包和上线渠道。U5.0 会让你先想清楚顺序，通常是先一端拿到真实用户，再开第二端。

## 四个关键认知

**U5.3 的 Server/Client Component 区分是最核心的概念。** 搞懂它，其余都简单。原则：**默认写 server，只把需要交互的那一小部分标成 client。** agent 为了「让它先跑起来」会把整页标成 client，密钥就跟着到了浏览器——这是你验收时第一个要看的地方。

**U5.4 是 Agent 产品和聊天框的分水岭。** 让用户看到「正在搜索…找到 23 条…正在分析…」，而不是一个转了 30 秒的圈。

**U5.5 的重点不是「怎么接登录」，而是「怎么保证数据不串」。** 三层隔离里，数据库的行级安全是兜底的那一层——它让「忘记加 WHERE user_id」这个错误在数据库层被挡住。越权测试你要自己跑，不能只看 agent 说通过。

**U5.7 的部署矩阵是选择题，不是全做题。** Vercel、腾讯云 CloudBase、自建 Docker 三条路各有适合的场景，走通两条、知道第三条什么时候用，就够了。
