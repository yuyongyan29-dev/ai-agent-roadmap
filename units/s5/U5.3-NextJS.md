# U5.3 · Next.js App Router（12 小时）

**这个单元解决什么问题**

U5.2 的界面是纯前端，所有代码都跑在浏览器里。**这意味着你的 API 密钥没法用**——放进去就等于公开。

Next.js 让你在同一个项目里同时写前端和服务端代码，**模型调用留在服务端**。

**版本基线**（2026-09-09 从 npm 实测）：Next.js 16.3.4、React 19.2.8。**动手前再核一次。**

**学完你能做到**：界面能真实调用你的 Agent；浏览器里搜不到任何密钥。

## 步骤 1 · 建项目并理解目录结构

### 这一步在做什么

跑起来，认识文件路由。

### 怎么做

```bash
cd s5-frontend
pnpm create next-app@latest web
```

选项选：TypeScript ✓、Tailwind ✓、**App Router ✓**、src 目录 ✓。

```bash
cd web && pnpm dev
```

打开 http://localhost:3000。

### 文件路由

**目录结构就是路由。**

```
src/app/
├── layout.tsx           → 全局布局（所有页面共享）
├── page.tsx             → /
├── globals.css
├── chat/
│   ├── page.tsx         → /chat
│   └── [id]/
│       └── page.tsx     → /chat/任意值（动态路由）
├── api/
│   └── tasks/
│       └── route.ts     → /api/tasks（API 端点）
└── (auth)/              → 括号表示「分组」，不出现在 URL 里
    └── login/
        └── page.tsx     → /login
```

**特殊文件名**：

| 文件 | 作用 |
|---|---|
| `page.tsx` | 这个路径的页面 |
| `layout.tsx` | 包裹子页面的布局，**切换页面时不重新渲染** |
| `loading.tsx` | 加载中显示的内容 |
| `error.tsx` | 出错时显示的内容 |
| `not-found.tsx` | 404 |
| `route.ts` | API 端点（不是页面） |

### 可能卡在哪

**`page.tsx` 必须默认导出**

```tsx
export default function Page() { ... }     // 必须是 default export
```

**动态路由的参数怎么拿**

```tsx
export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;         // Next.js 15+ 之后 params 是 Promise
  ...
}
```

**注意 `params` 现在是 Promise，要 await。** 这是相对旧版本的变化，老教程会误导你。

## 步骤 2 · Server Components vs Client Components

### 这一步在做什么

**这是 App Router 最核心也最容易搞混的概念。搞懂它，其余都简单。**

### 两种组件

**默认是 Server Component**：

- 在服务器上渲染，**代码不会发到浏览器**
- **可以直接读数据库、可以用密钥、可以读文件**
- **不能**用 `useState`、`useEffect`、事件处理（`onClick`）
- 可以是 `async` 函数，直接 `await` 取数据

**加 `'use client'` 才是 Client Component**：

- 代码会发到浏览器
- 能用 hooks 和事件处理
- **不能**直接访问服务端资源

### 判断标准

**需要交互的才是 client，其余都是 server。**

```tsx
// Server Component（默认）
async function 会话列表() {
  const 会话 = await db.query("SELECT * FROM sessions");    // 直接查库
  return <ul>{会话.map(s => <li key={s.id}>{s.标题}</li>)}</ul>;
}

// Client Component
"use client";
function 输入框() {
  const [值, 设值] = useState("");                          // 需要 useState
  return <input value={值} onChange={e => 设值(e.target.value)} />;
}
```

### 组合的正确方式

**Server Component 可以渲染 Client Component，反过来不行。**

```tsx
// app/chat/page.tsx —— Server Component
import 对话界面 from "./对话界面";       // 这个是 client

export default async function Page() {
  const 历史 = await 从数据库取历史();    // 服务端取数据
  return <对话界面 初始历史={历史} />;     // 通过 props 传给 client
}
```

**这个模式很重要**：**服务端取数据，客户端做交互。**

### 常见错误

**在 Server Component 里用 useState**

```
Error: useState only works in Client Components.
Add the "use client" directive at the top of the file.
```

**加 `'use client'` 就行**，但先想想：这个组件真的需要交互吗？

**把整个页面标成 client**

这样就失去了 Server Component 的好处（密钥安全、减少发到浏览器的代码）。

**正确做法：只把真正需要交互的那一小部分标成 client。**

**给 Client Component 传函数**

```tsx
// 错误：函数不能序列化，没法从服务端传到客户端
<客户端组件 回调={() => {...}} />
```

**要么用 Server Action（步骤 4），要么在客户端内部定义回调。**

### 可能卡在哪

**分不清该用哪个**

**默认写 server**，遇到需要 `useState` 或 `onClick` 时，把那部分抽成一个小的 client 组件。

**'use client' 会传染吗**

会。一个 client 组件里 import 的所有组件都会变成 client。

**所以要在树的尽量深处标 client**，而不是在根部。

## 步骤 3 · API 路由

### 这一步在做什么

写服务端接口，对接你 S4 部署的 Agent 后端。

### 怎么做

```tsx
// src/app/api/tasks/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
  const body = await req.json();

  const r = await fetch(`${process.env.AGENT_API}/tasks`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${process.env.AGENT_API_KEY}`,   // 密钥在服务端
    },
    body: JSON.stringify(body),
  });

  if (!r.ok) {
    return NextResponse.json({ 错误: "提交失败" }, { status: r.status });
  }
  return NextResponse.json(await r.json(), { status: 202 });
}
```

**环境变量的关键规则**：

| 前缀 | 可见性 |
|---|---|
| `AGENT_API_KEY` | **只在服务端可见** |
| `NEXT_PUBLIC_XXX` | **会打包进浏览器代码，任何人都能看到** |

**密钥绝对不能用 `NEXT_PUBLIC_` 前缀。** 这是最容易犯的致命错误。

### 为什么要在 Next.js 里再包一层

你的 Agent 后端（S4 做的）已经有 API 了，为什么不让浏览器直接调？

三个理由：

1. **密钥不能给浏览器**
2. **可以做鉴权**：Next.js 这层验证用户身份，再用服务端密钥调后端
3. **可以做适配**：后端的接口格式不一定适合前端直接用

### 可能卡在哪

**CORS 报错**

如果浏览器直接调你的 Agent 后端会有跨域问题。**通过 Next.js 的 API 路由转发就没有这个问题**（服务端到服务端没有 CORS）。

**流式怎么转发**

见 U5.4。

## 步骤 4 · Server Actions

### 这一步在做什么

**Next.js 最方便的一个特性：在组件里直接定义服务端函数，前端当普通函数调。**

### 怎么做

```tsx
// src/app/actions.ts
"use server";

export async function 提交任务(输入: string) {
  const 用户 = await 取当前用户();
  if (!用户) throw new Error("未登录");

  const r = await fetch(`${process.env.AGENT_API}/tasks`, {
    method: "POST",
    headers: { "Authorization": `Bearer ${process.env.AGENT_API_KEY}` },
    body: JSON.stringify({ 输入, 用户id: 用户.id }),
  });
  return r.json();
}
```

在客户端组件里：

```tsx
"use client";
import { 提交任务 } from "./actions";

function 输入框() {
  const [输入, 设输入] = useState("");

  const 发送 = async () => {
    const 结果 = await 提交任务(输入);       // 像调普通函数一样
    ...
  };
  ...
}
```

**Next.js 自动帮你处理了网络请求。** 你不用写 fetch、不用定义 API 路由、不用管序列化。

### 什么时候用 Action，什么时候用 API 路由

| 场景 | 用什么 |
|---|---|
| 你自己的前端调用 | **Server Action**（更简洁） |
| 需要给外部调用（小程序、第三方） | **API 路由**（标准 HTTP 接口） |
| 流式响应 | **API 路由**（Action 不适合流式） |

**你的项目两个都要有**：Web 前端用 Action，小程序（U5.6）用 API 路由。

### 安全提醒

**Server Action 是一个可以被调用的端点。** 不要以为「只有我的前端会调它」。

**每个 Action 里都必须自己做鉴权和参数校验**，就像写 API 一样。

```tsx
"use server";
export async function 删除会话(会话id: string) {
  const 用户 = await 取当前用户();
  if (!用户) throw new Error("未登录");

  const 会话 = await 取会话(会话id);
  if (会话.用户id !== 用户.id) throw new Error("无权限");    // 归属校验，不能省

  await 删除(会话id);
}
```

## 步骤 5 · 加载、错误、Suspense

### 这一步在做什么

处理「数据还没来」和「出错了」两种状态。

### 文件约定

```
src/app/chat/
├── page.tsx           # 页面
├── loading.tsx        # 加载中自动显示
└── error.tsx          # 出错时自动显示
```

```tsx
// loading.tsx
export default function Loading() {
  return <div className="p-8 text-center">加载中...</div>;
}

// error.tsx —— 必须是 client component
"use client";
export default function Error({ error, reset }: { error: Error; reset: () => void }) {
  return (
    <div className="p-8">
      <p>出错了：{error.message}</p>
      <button onClick={reset}>重试</button>
    </div>
  );
}
```

**Next.js 自动把它们套上去**，你不用手写 try/catch 和加载状态。

### Suspense：局部加载

页面里某一块数据慢，不要整页等：

```tsx
import { Suspense } from "react";

export default function Page() {
  return (
    <div>
      <h1>会话</h1>                    {/* 立刻显示 */}
      <Suspense fallback={<div>加载会话列表...</div>}>
        <会话列表 />                    {/* 慢的部分单独加载 */}
      </Suspense>
    </div>
  );
}
```

**这就是「流式渲染」**：页面骨架先出来，慢的部分后到。

### 可能卡在哪

**error.tsx 没生效**

它只捕获它所在层级及以下的错误。**根级的错误要用 `global-error.tsx`。**

**loading.tsx 一闪而过**

数据太快了。这是好事。如果想看效果，在数据获取里加个 `await sleep(2000)` 测试。

## 步骤 6 · 迁移你的对话界面

### 这一步在做什么

把 U5.2 的界面搬过来，接上真实后端。

### 步骤

1. 把 U5.2 的组件复制到 `src/app/chat/`
2. 在需要交互的组件顶部加 `'use client'`
3. 把假数据换成 Server Action 调用
4. 页面本身改成 Server Component，服务端取初始数据

```tsx
// src/app/chat/page.tsx —— Server Component
import 对话界面 from "./对话界面";
import { 取会话历史 } from "@/lib/db";

export default async function Page() {
  const 历史 = await 取会话历史();
  return <对话界面 初始消息={历史} />;
}
```

### 验证密钥安全

**这一步必须做**：

1. `pnpm build && pnpm start`（用生产模式，不是 dev）
2. 打开浏览器开发者工具
3. **Sources 面板**：搜索你的 API key 的前几个字符
4. **Network 面板**：看所有请求的 header 和 body

**任何地方能搜到密钥就是失败。**

常见泄露原因：

- 用了 `NEXT_PUBLIC_` 前缀
- 在 Client Component 里 import 了包含密钥的模块
- 密钥被打进了某个传给客户端的 props 里

### 可能卡在哪

**build 报错「模块只能在服务端使用」**

说明你在 Client Component 里 import 了服务端的东西（数据库客户端之类）。

**解法**：把服务端逻辑抽到单独的文件，只在 Server Component 或 Action 里 import。

**开发模式正常，build 之后出错**

Next.js 在 build 时会做静态分析和预渲染，暴露出开发模式下不明显的问题。

**每次做完一个功能都 build 一次**，不要攒到最后。
