# U5.8 · App 与 Expo（10 小时）

**这个单元解决什么问题**

到上一个单元为止，你的 Agent 有了网页版（U5.3–U5.5）和小程序版（U5.6）。这个单元把它装进手机：一个真正的 App，图标在桌面上，能推送、能离线看历史、能发给朋友装。

用 **Expo**（React Native 的官方工具链）。理由只有一个：**S5 前面学的 React、U5.4 的流式界面、U5.5 的认证，全部直接复用**。你不需要学 Swift 或 Kotlin，一套 TypeScript 代码同时出 iOS 和 Android。

**学完你能做到**：把同一个后端接进 App，真机上跑通一次完整的 Agent 对话并看到流式过程，打出一个能装到别人手机上的安装包。

**这个单元的姿态**：每一步都是 **让 agent 做 → 你验收 → 你读懂**。代码由 Claude Code 或 Codex 写，你负责给清楚的指令、在真机上验证、然后把关键代码读懂到能口头解释。文档里贴的代码片段是给你对照用的，不是让你抄。

**版本基线**（2026-09-10 用 `npm view <包> version` 实测）：

| 包 | 版本 |
|---|---|
| expo | 57.0.21 |
| expo-router | 57.0.20 |
| react-native | 0.87.1 |
| react | 19.3.0 |
| eas-cli | 24.0.0 |

Expo 每年发两个大版本，SDK 号和 `expo-*` 系列包的主版本号一致。**动手前再核一次**，跨 SDK 版本的报错是这个生态最常见的坑。

## 步骤 1 · 建项目，真机上看到第一个页面（1 小时）

### 这一步在做什么

建一个 Expo 项目，用手机上的 Expo Go 扫码预览。**不需要 Xcode，不需要 Android Studio**，这是 Expo 相比原生开发最大的省事之处。

### 怎么做

**让 agent 做**：

> 在 `s5-frontend/app/` 下用 `npx create-expo-app@latest` 建一个 Expo 项目，模板选带 Expo Router 和 TypeScript 的默认模板。项目名 `agent-app`。建完把默认的示例页面清空，只留一个首页显示「Agent App」和当前时间。启动开发服务器，把终端里的二维码和局域网地址告诉我。不要装任何额外依赖。

**你验收**：

1. 手机装 Expo Go（App Store / 应用商店搜 Expo Go）
2. 手机和电脑连同一个 WiFi
3. iPhone 用相机扫终端里的二维码，Android 在 Expo Go 里扫
4. 屏幕上出现「Agent App」和时间

然后**在 VS Code 里把「Agent App」改成任何别的字，保存**。手机上应该在一秒内自动刷新。这叫 Fast Refresh，是你后面所有调试的基础。

**你读懂**（能口头回答）：

1. `app/_layout.tsx` 和 `app/index.tsx` 各是什么？删掉 `_layout.tsx` 会怎样？
2. `npx expo start` 启动的开发服务器叫什么名字，它和手机之间传的是什么？
3. Expo Go 是怎么在不安装你的 App 的情况下运行你的代码的？

### 可能卡在哪

**扫码后一直转圈，或者报 `Could not connect to development server`**

九成是手机和电脑不在同一个 WiFi，或者路由器开了「AP 隔离」（公司和酒店 WiFi 常见）。三个解法按顺序试：

1. 确认两边 WiFi 名字完全一样，不是 2.4G 和 5G 两个名字
2. 终端里按 `s` 切换到 Expo Go 模式，再按 `?` 看选项，选 **tunnel**（`npx expo start --tunnel`）。它走 Expo 的中转服务器，不依赖局域网，慢一点但一定通
3. 用手机热点，电脑和手机都连热点

**改了代码手机没反应**

Metro（打包器）的缓存偶尔会坏。`Ctrl+C` 停掉，`npx expo start -c` 清缓存重启。**这条命令你以后会经常用。**

**agent 建项目时报 Node 版本不够**

Expo SDK 57 要求 Node 20 以上。U5.1 装的应该够，`node -v` 确认一下。

### 背后的逻辑

**Expo Go 是一个「壳」。** 它已经把 React Native 的原生运行时和一批常用原生模块预先编译好了，你的 JavaScript 代码通过 Metro 打包后传给它执行。所以你改代码不需要重新编译原生部分，秒级刷新。

代价是**只能用 Expo Go 预装的那些原生模块**。需要用它没有的原生能力时（比如某些支付 SDK、蓝牙），就得走步骤 6 的 EAS Build 打一个自己的「壳」，叫 development build。**这个单元的功能都在 Expo Go 范围内**，不用担心。

## 步骤 2 · 页面结构：Expo Router 文件路由（1.5 小时）

### 这一步在做什么

搭出 App 的骨架：底部两个 Tab（对话、历史），对话页能进到具体某一次会话。

### 怎么做

**让 agent 做**：

> 用 Expo Router 搭页面结构：底部 Tab 导航，两个 Tab 是「对话」和「历史」。「对话」Tab 是新建会话的入口，点开始后跳到 `/chat/[id]` 动态路由，`id` 先用时间戳占位。「历史」Tab 先放一个空列表和「暂无记录」提示。所有页面先用最简单的样式，不要引入 UI 库。每个页面顶部显示自己的路由路径，方便我核对。

**你验收**：

- 底部有两个 Tab，切换时顶部路径分别显示 `/` 和 `/history`
- 在「对话」页点「开始」，跳到 `/chat/1725...`（一串时间戳），有返回按钮
- **手机上的返回手势（iOS 右滑、Android 返回键）能正常回到 Tab**

**你读懂**：

1. 为什么文件叫 `app/(tabs)/_layout.tsx`，括号是什么意思？
2. `app/chat/[id].tsx` 里怎么拿到 `id`？和 U5.3 的 Next.js 动态路由比，写法差在哪？
3. 从 Tab 页跳到 `/chat/xxx` 时，Tab 栏为什么消失了？想让它保留该怎么改？

对照的目录结构：

```
app/
├── _layout.tsx           # 根布局：Stack 导航，包住所有页面
├── (tabs)/
│   ├── _layout.tsx       # Tab 导航：定义底部两个 Tab
│   ├── index.tsx         # 「对话」Tab → /
│   └── history.tsx       # 「历史」Tab → /history
└── chat/
    └── [id].tsx          # 会话详情 → /chat/:id
```

### 可能卡在哪

**跳转后页面是空白的**

`[id].tsx` 里用了 `useLocalSearchParams()` 但没处理 `id` 可能是数组的情况。Expo Router 的参数类型是 `string | string[]`，agent 常忘了这一点。

**Tab 图标不显示**

模板自带 `@expo/vector-icons`，但图标名写错就什么都不显示，也不报错。让 agent 用 `Ionicons` 里确定存在的名字，比如 `chatbubble-outline` 和 `time-outline`。

### 背后的逻辑

**Expo Router 和 Next.js App Router 是同一个思路：文件即路由。** 你在 U5.3 建立的直觉这里全部有效。`_layout.tsx` 对应 Next.js 的 `layout.tsx`，`[id].tsx` 对应 `[id]/page.tsx`。

差别在于**导航模型**。网页是「一个 URL 一个页面」，手机 App 是「一叠页面」（Stack）加「几个并列入口」（Tab），返回手势要能一层层退回去。Expo Router 用目录结构表达这个叠放关系，`(tabs)` 这种括号目录叫 group，只影响布局不影响 URL。

## 步骤 3 · 接后端：创建任务，密钥不出客户端（1.5 小时）

### 这一步在做什么

App 调用你在 U5.3 部署的 Next.js 后端，创建一个 Agent 任务。**模型 API 密钥只在服务端**，App 里一个密钥都没有。

### 怎么做

**让 agent 做**：

> 在 `src/lib/api.ts` 里封装后端调用。后端地址从环境变量 `EXPO_PUBLIC_API_URL` 读取，开发时指向我电脑的局域网 IP（不是 localhost）。实现 `createTask(prompt)`，POST `/api/tasks`，请求体和 U5.3 的 Web 端一致，返回 `{ id }`。在 `/chat/[id]` 页面顶部加一个输入框和发送按钮，发送后调用 `createTask`，把返回的 id 显示出来。带上 U5.5 的认证头，token 先硬编码一个测试用的，下一步再换成安全存储。

**你验收**：

1. 电脑上后端跑着（`s5-frontend/web` 里 `npm run dev`），终端能看到局域网地址如 `http://192.168.1.8:3000`
2. `.env` 里 `EXPO_PUBLIC_API_URL=http://192.168.1.8:3000`
3. 手机上输入一句话点发送，页面显示一个任务 id
4. **电脑上后端的终端里出现这次请求的日志**，Langfuse（S3 建的）里出现一条新 trace

**证明密钥没有泄漏**：

```bash
cd s5-frontend/app
grep -rn "sk-\|ANTHROPIC\|OPENAI\|DEEPSEEK" --include='*.ts' --include='*.tsx' --include='.env*' .
```

只应该匹配到 `EXPO_PUBLIC_API_URL` 所在的那一行，不应该有任何密钥。

**你读懂**：

1. 为什么环境变量名必须以 `EXPO_PUBLIC_` 开头？没有这个前缀会怎样？
2. 为什么开发时不能写 `localhost`？`localhost` 在手机上指向谁？
3. 这个 App 里完全没有模型密钥，那它是怎么用上模型的？画出请求经过的三个节点。

### 可能卡在哪

**`Network request failed`**

按顺序查：手机浏览器直接打开 `http://192.168.1.8:3000`，打不开就是网络问题（回步骤 1 的 WiFi 排查）；打得开但 App 里失败，检查 `.env` 改完有没有重启 `npx expo start -c`——**环境变量是构建时注入的，改了必须重启**。

**iOS 上 http 被拒绝**

Expo Go 开发阶段允许 http。但步骤 6 打正式包后，iOS 默认禁止明文 http，到时候后端必须是 https。**U5.7 部署到 Vercel 之后自然就是 https，这里先记住。**

**CORS 报错**

App 不是浏览器，没有同源策略，不会有 CORS 问题。如果你看到 CORS 字样，说明你在 Web 预览（`npx expo start` 按 `w`）里测的，换真机。

### 背后的逻辑

**App 是一个不可信的客户端，和浏览器一样。** 任何打进安装包的东西都能被解包读出来，`EXPO_PUBLIC_` 前缀就是在提醒你「这个值会出现在客户端代码里」。

所以密钥必须留在服务端，App 只带**用户自己的**认证 token。这套结构和 U5.3 一模一样：**浏览器 / 小程序 / App 都只是不同的前端壳，后端一套**。这就是完成判据里「后端零改动」那一条的来源，也是为什么 S5 先做 Web 再做 App——后端在 U5.3 就已经设计成多端共用了。

## 步骤 4 · 流式：让用户看到 Agent 每一步（2 小时）

### 这一步在做什么

把 U5.4 的流式界面搬到手机上。**这是整个单元技术上最难的一步**，因为 React Native 的 `fetch` 长期不支持流式读取响应，浏览器里能用的 `EventSource` 在 RN 里也没有。

### 怎么做

**让 agent 做**：

> 实现 SSE 流式接收。用 `expo/fetch`（不是全局 fetch）请求 `/api/tasks/[id]/events`，通过 `response.body.getReader()` 逐块读取，手写一个最小的 SSE 解析器：按空行切分事件，解析 `event:` 和 `data:` 两个字段。事件类型沿用 U5.4 定义的那几种（thinking、tool_call、tool_result、message、done、error）。用 `FlatList` 渲染事件流，每种事件一种卡片样式，新事件到达时自动滚到底部。组件退出时要中止请求。另外实现一个降级方案：如果流式读取在 3 秒内没收到任何字节，切换成每 2 秒轮询 `/api/tasks/[id]` 拿全量状态。

**你验收**：

- 发送一句会触发工具调用的话（比如你 Agent 的典型任务）
- 手机上**逐条**出现「正在思考 → 调用 xx 工具 → 工具返回 → 回答」，不是等 30 秒后一次性全出来
- 在流还没结束时按返回，后端终端里应该能看到连接断开（U5.4 的 cancel 逻辑生效）
- **验证降级**：临时把 `expo/fetch` 换回全局 `fetch`，应该看到 3 秒后切到轮询模式，界面仍然能拿到最终结果，只是不再逐条出现

对照的核心片段：

```ts
// src/lib/sse.ts
import { fetch } from "expo/fetch";   // 关键：Expo 自带的 fetch 支持流式读取，全局 fetch 不支持

export async function streamEvents(
  url: string,
  headers: Record<string, string>,
  onEvent: (type: string, data: unknown) => void,
  signal: AbortSignal,
) {
  const res = await fetch(url, { headers, signal });
  const reader = res.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = "";                     // 半截事件先攒着，等到空行再解析

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    // SSE 用空行分隔事件，一次 read 可能带回多个事件或半个事件
    const parts = buffer.split("\n\n");
    buffer = parts.pop() ?? "";        // 最后一段可能不完整，留到下一轮
    for (const part of parts) {
      let type = "message", data = "";
      for (const line of part.split("\n")) {
        if (line.startsWith("event:")) type = line.slice(6).trim();
        else if (line.startsWith("data:")) data += line.slice(5).trim();
      }
      if (data) onEvent(type, JSON.parse(data));
    }
  }
}
```

**你读懂**：

1. 为什么要维护 `buffer`，直接把每次 `read()` 到的内容 `JSON.parse` 会出什么问题？
2. `decoder.decode(value, { stream: true })` 里的 `stream: true` 解决什么问题？（提示：中文是多字节的）
3. 组件卸载时不中止请求会怎样？在手机上这个后果比网页上更严重，为什么？

### 可能卡在哪

**流式不生效，所有事件在结束时一起到**

三层排查，从近到远：

1. **确认用的是 `expo/fetch`**，`import { fetch } from "expo/fetch"`，不是全局的。这是最常见的原因
2. 后端响应头有没有 `X-Accel-Buffering: no`（U5.4 步骤 2）。如果 Web 端流式正常而 App 不正常，不是这个原因
3. 中间有没有代理。用手机热点直连测一次，排除公司网络的干扰

**`TextDecoder is not defined`**

老版本 RN 没有内置。Expo SDK 57 已经有了，报这个错说明 SDK 版本不对，`npx expo install --check` 看哪个包版本不匹配。

**Android 上流式比 iOS 慢很多**

Android 的网络栈默认有较大的接收缓冲。这是平台特性，不是你的 bug。如果体验不可接受，让后端每个事件后追加一段注释填充（`: padding\n\n`）撑过缓冲阈值，或者接受降级到轮询。

**FlatList 自动滚动抖动**

`onContentSizeChange` 里调 `scrollToEnd` 是常见写法，但事件密集时会抖。让 agent 改成用 `maintainVisibleContentPosition` 或者节流。

### 背后的逻辑

**为什么 RN 的 fetch 不支持流式？** 因为 RN 的网络层是桥接到原生实现的，早期设计时把整个响应体读完再一次性传回 JS 侧。Expo 在 SDK 52 提供了自己的 `expo/fetch`，基于新架构重新实现，才支持 `ReadableStream`。

**这一步的通用教训**：换一个运行环境（浏览器 → RN），你依赖的「标准 API」可能不存在或行为不同。**先写降级方案再写主方案**是真实项目里的常规做法。你在 U4.3 学的「长任务架构」里状态是持久化的，所以轮询才有东西可查——S4 的设计在这里又一次兑现。

## 步骤 5 · 本地存储：token 安全存放，历史离线可看（1 小时）

### 这一步在做什么

把步骤 3 硬编码的 token 换成安全存储，把会话历史存在手机本地，让「历史」Tab 有内容，断网也能翻。

### 怎么做

**让 agent 做**：

> 两件事。一，用 `expo-secure-store` 存认证 token，写一个 `getToken / setToken / clearToken` 模块，`api.ts` 从这里读 token。加一个最简单的登录页，输入 U5.5 那套认证的凭据换 token 后存起来，没有 token 时自动跳登录页。二，用 `expo-sqlite` 建一张 `sessions` 表（id、标题、创建时间、最终回答），每次任务 done 时写入。「历史」Tab 从这张表读，按时间倒序显示，点击进入 `/chat/[id]` 显示存下来的最终回答。

**你验收**：

- 杀掉 App 重开，不需要重新登录
- 「历史」Tab 里有你刚才的会话
- **开飞行模式**，历史仍然能打开、能看到最终回答
- 登出后再进，历史列表清空（或按你的产品判断保留，但必须是有意识的决定）

**你读懂**：

1. token 为什么不能存在 `AsyncStorage` 或 SQLite 里，`SecureStore` 底层用的是什么？
2. 历史为什么存在本地而不是每次从后端拉？各自的取舍是什么？
3. 用户换手机，历史怎么办？这个问题现在不解决，但你要能说出两种方案。

### 可能卡在哪

**SecureStore 在 Android 模拟器上报错**

部分模拟器镜像没有 Keystore。换真机测，或者换一个带 Google API 的镜像。

**SQLite 表结构改了，老数据读不出来**

开发阶段最简单的办法是加一个版本号，不匹配就删表重建。上线后要写迁移，U0.8 学的 migration 思路在这里完全一样。

### 背后的逻辑

**手机上的存储分三档**：`SecureStore` 走系统的 Keychain（iOS）/ Keystore（Android），加密且其他 App 读不到，只放凭据；SQLite 放结构化数据，量大也不怕；`AsyncStorage` 放几个简单的偏好设置。**选错档位是移动端安全审计最常见的发现项**——token 放在明文存储里，越狱手机上一个命令就能读出来。

## 步骤 6 · EAS Build：打出能装的包，发给别人测（2 小时）

### 这一步在做什么

Expo Go 只能你自己扫码看。要发给别人，得打一个真正的安装包。用 EAS（Expo 的云构建服务），**不需要自己装 Xcode 和 Android Studio**。

### 怎么做

**让 agent 做**：

> 配置 EAS Build。装 `eas-cli`，`eas login` 后 `eas build:configure` 生成 `eas.json`，里面定义三个 profile：`development`（带开发工具，装到我自己手机上替代 Expo Go）、`preview`（内测包，Android 出 APK，iOS 出 ad hoc）、`production`（正式包）。`app.json` 里把 `name`、`slug`、`bundleIdentifier`、`package`、图标和启动图配好。先跑 `eas build --profile preview --platform android`，把构建链接给我。

**你验收**：

1. `eas build` 提交后终端给一个 expo.dev 的链接，能看到构建进度
2. 构建完成，页面上有 APK 下载二维码
3. **用另一台 Android 手机**（借一台）扫码下载安装，能打开、能登录、能跑一次对话
4. 桌面上的图标是你配的那个，不是 Expo 默认图标

iOS 的 preview 包需要先在 Apple Developer 后台注册测试设备的 UDID，`eas device:create` 会给你一个链接让测试者自己注册。**这一步需要 Apple 开发者账号（每年 99 美元）**，没有的话 iOS 部分先跳过，Android 走通就算过。

**你读懂**：

1. `eas.json` 三个 profile 的区别是什么？为什么 preview 的 Android 要出 APK 而不是 AAB？
2. `bundleIdentifier` 和 `package` 一旦发布就不能改，为什么？
3. development build 和 Expo Go 的区别是什么？什么情况下你会需要前者？

### 可能卡在哪

**免费额度排队**

EAS 免费计划的构建排在付费用户之后，高峰期等 30 分钟到一小时是正常的。**提交后去做别的事**，不要盯着。急的话 `eas build --local` 在本机构建，但那就需要装 Xcode / Android SDK 了。

**`Invalid bundleIdentifier`**

格式是反域名，比如 `com.你的名字.agentapp`，全小写，不能有连字符。

**Android 构建成功但安装时提示「解析包时出现问题」**

手机架构不匹配的概率很低，更常见的是下载不完整。重新下载。

**iOS 构建卡在凭据**

第一次会让 EAS 帮你管理证书和 provisioning profile，选「让 EAS 管理」。自己管证书是另一门手艺，现在不要碰。

### 背后的逻辑

**Expo Go 是共享的壳，EAS Build 是给你专门编译一个壳。** 编译在 Expo 的云机器上做，产物是标准的 iOS / Android 安装包。所以 EAS 出来的包和原生开发出来的包没有本质区别，可以上架任何商店。

**TestFlight 和 preview profile 是两回事。** preview 出的 iOS 包是 ad hoc 分发，最多 100 台注册过 UDID 的设备。TestFlight 是 App Store 的正式内测渠道，最多 1 万人，需要走 `eas submit` 提交到 App Store Connect 再开内测。**产品要给几十上百人试用时走 TestFlight，只是给三五个朋友看走 preview**。

## 步骤 7 · 国内分发的现实（1 小时）

### 这一步在做什么

弄清楚你的 App 在国内怎么到达用户。**这一步没有代码，但决定你做不做 App 这件事本身。**

### 怎么做

**让 agent 做**：

> 帮我整理一份国内 App 分发的清单：iOS 上架 App Store 需要什么（开发者账号、审核要点、ICP 备案对 App 的要求）；Android 主流商店（华为、小米、OPPO、vivo、应用宝）各自的入驻要求，特别是软件著作权证书是不是必需、办理周期和费用；不上商店直接分发 APK 的限制。每一条标注信息来源和你查到的日期。**只要官方页面或近 6 个月内的一手信息，不要引用二手教程。**

**你验收**：

- 清单里每一条都有链接，你随机点开三条确认是官方页面
- 你能回答：**如果下周要让 50 个国内用户装上这个 App，最快的路径是什么，要花多少钱、等多少天**

**你读懂**：

1. 软著和 ICP 备案分别是什么，哪个是 Android 商店要的、哪个是 iOS 要的？
2. 为什么国内 Android 没有一个统一的商店？这对你的分发成本意味着什么？
3. 对照 U5.6 的小程序：**同样的功能，小程序和 App 在「到达用户」这件事上差多少？** 这个答案会影响你后面的产品决策。

### 可能卡在哪

**agent 给的信息互相矛盾或明显过时**

这类政策信息变动频繁，AI 训练数据里的版本大概率过时。**这一步的重点就是训练你不信 AI 直接给的答案，逼它给来源，你再核。** S3 学的「LLM 输出必须可验证」在这里是真金白银的事。

**软著办理周期**

自己走官方渠道免费但慢（通常一到两个月），代办加急要花钱。**如果你打算做 App，软著现在就该开始办**，不要等到要上架了才发现卡在这。

### 背后的逻辑

**技术上打出包只是分发的开始。** 国内 App 分发的成本主要在合规和渠道，不在代码。这也是为什么 S5 把小程序排在 App 前面：**对国内用户，小程序的到达成本远低于 App**。App 的优势在于推送、后台能力、系统级集成，以及海外市场。

**做产品决策时把这一步的答案摆在桌上**：如果你的用户在国内、功能不依赖 App 特有能力，小程序加网页可能已经够了。这个单元让你有能力做 App，不等于每个产品都该做 App。

## 这个单元之后

U5.7 会把 Web、小程序、App 三端一起上线，你会看到**部署矩阵**：同一个后端，三个前端各自走不同的发布渠道。到那时候回头看这个单元的步骤 7，分发清单就是你上线计划的一部分。

App 这条线继续往深走的话：推送通知（`expo-notifications`）、深链接（Universal Links / App Links）、OTA 更新（EAS Update，改 JS 不用重新上架）。这三样都不在计划内，但都是 Expo 生态里现成的，需要时让 agent 查官方文档接入，每个大约半天。
