# U5.1 · TypeScript 基础（10 小时）

**这个单元解决什么问题**

前端和小程序必须用 JavaScript/TypeScript。这个单元让你从 Python 平滑过渡过去。

**好消息**：有了 Python 基础（尤其是 U0.4 学的类型注解），TypeScript 会比想象中快。**很多概念是相通的，只是语法不同。**

**学完你能做到**：读懂也能写 TypeScript；严格模式下零类型错误。

## 步骤 1 · 装 Node 环境

### 这一步在做什么

装好 JS 生态的基础工具。

### 怎么做

```bash
brew install fnm            # Node 版本管理器，类似 Python 的 pyenv
```

把这行加进 `~/.zshrc`（U0.1 学的）：

```bash
eval "$(fnm env --use-on-cd --shell zsh)"
```

然后：

```bash
source ~/.zshrc
fnm install --lts           # 装最新的 LTS 版本
fnm default lts-latest      # 设成默认版本，否则新开的终端里 node 又找不到了
node --version              # 能打出版本号才算装好
```

装包管理器：

```bash
corepack enable             # 启用 Node 自带的包管理器代理，不用单独 npm i -g
pnpm --version              # 能打出版本号说明 pnpm 可用了
```

### Python 和 Node 的工具对照

| 用途 | Python | Node |
|---|---|---|
| 版本管理 | pyenv / uv | **fnm** |
| 包管理 | uv / pip | **pnpm** / npm |
| 项目配置 | pyproject.toml | **package.json** |
| 锁文件 | uv.lock | **pnpm-lock.yaml** |
| 虚拟环境 | .venv/ | **node_modules/**（每个项目独立，天然隔离） |
| 运行脚本 | uv run | **pnpm run** |
| 格式化 | ruff format | **prettier** |
| 检查 | ruff check | **eslint** |

**注意 `node_modules/` 相当于虚拟环境**，每个项目一份，天生隔离。**它必须进 `.gitignore`**（U0.2 学的），因为它可能有几万个文件。

### 可能卡在哪

**`pnpm: command not found`**

`corepack enable` 没生效，或者需要 sudo。也可以直接 `npm install -g pnpm`。

**为什么用 pnpm 不用 npm**

pnpm 用硬链接共享依赖，磁盘占用小得多、安装快得多。**对你的直接影响是：开十个项目不会占掉 10GB。**

### 这一步在做什么

**不要系统学 JavaScript**，只补写 TypeScript 会用到的部分。

### 需要掌握的

```javascript
// 变量：只用 const 和 let，永远不用 var
// var 的作用域是整个函数而不是花括号，是老代码里一类难查的 bug 来源
const userName = "小王";      // 不可重新赋值
let count = 0;                // 可以

// 箭头函数。写业务代码只用这一种，省得考虑 this 指向
const add = (a, b) => a + b;
const handle = async (x) => { ... };

// 解构（对应 Python 的元组解包）：从对象或数组里直接取字段，少写一堆 user.xxx
const { name, age } = user;
const [first, second] = items;

// 展开（对应 Python 的 * 和 **）：生成新对象而不是改原来的，
// React 和状态管理都要求不可变更新，这个写法后面天天用
const newItems = [...oldItems, newItem];
const newUser = { ...oldUser, age: 29 };

// 模板字符串（对应 f-string）
const message = `${userName}有${count}条消息`;

// 数组方法（对应列表推导式）：都返回新数组，不改原数组
const doubled = numbers.map(x => x * 2);
const evens = numbers.filter(x => x % 2 === 0);
const total = numbers.reduce((a, b) => a + b, 0);
const firstBig = numbers.find(x => x > 10);   // 找不到时返回 undefined，记得判空

// async/await（和 Python 几乎一样）
const data = await fetch(url).then(r => r.json());

// 可选链和空值合并（Python 没有直接对应）：
// 中间任何一层是 null/undefined 都不会抛错，整条链直接得 undefined，再由 ?? 兜底
const city = user?.address?.city ?? "未知";
```

**最后一行值得单独说**：

- `?.` 是「如果前面是 null 或 undefined 就返回 undefined，不报错」
- `??` 是「如果左边是 null 或 undefined 就用右边」

**这两个在处理 API 返回的数据时极其有用**，比 Python 写一堆 `if x is not None` 简洁得多。

### 三个和 Python 不同的坑

**一、`==` 和 `===`**

```javascript
"1" == 1      // true！会做类型转换
"1" === 1     // false，严格比较
```

**永远用 `===` 和 `!==`。** 这是铁律。

**二、`null` 和 `undefined` 是两个东西**

| | 含义 |
|---|---|
| `undefined` | 从来没赋过值 |
| `null` | 明确赋值为「空」 |

Python 只有一个 `None`。**JS 有两个，但实践中用 `?? ` 和 `?.` 就能一起处理。**

**三、`this` 的绑定**

普通函数里的 `this` 取决于怎么调用的，箭头函数继承外层的 `this`。

**规避方法：永远用箭头函数。** 这样就不会遇到这个问题。

### 可能卡在哪

**看到 `function` 关键字的老代码**

老写法，等价于箭头函数（除了 `this` 的行为）。**你自己写的时候用箭头函数就行。**

**Promise 和 async/await 的关系**

`async` 函数返回的就是 Promise。`await` 就是等一个 Promise 完成。**和 Python 的 asyncio 是一个概念。**

## 步骤 3 · TypeScript 类型系统

### 这一步在做什么

学 TS 相比 JS 多出来的部分。

### 基础类型（和 Python 对照）

```typescript
// 这些字面量的类型 TS 都能自己推出来，写出来只是为了和 Python 的写法对照；
// 实际项目里变量声明大多不用手写类型，函数签名才必须写

// Python: user_name: str = "小王"
const userName: string = "小王";
const age: number = 28;                 // TS 只有 number，没有 int/float 之分
const isStudent: boolean = false;

// Python: tags: list[str]
const tags: string[] = ["a", "b"];
// 或者（两种写法完全等价，团队里统一一种就行）
const tags2: Array<string> = ["a", "b"];

// Python: counts: dict[str, int]
const counts: Record<string, number> = { a: 1 };

// Python: note: str | None
const note: string | null = null;

// 函数：参数和返回值的类型一定要写，这是给调用方和编辑器提示用的
function listFiles(path: string, limit: number = 10): string[] {
  return [];
}
```

### interface 和 type

```typescript
interface User {
  id: number;
  name: string;
  email?: string;             // ? 表示可选，对应 Python 的 str | None
  readonly createdAt: string; // 只读：创建后不允许再改，改了编译期就报错
}

// 字面量联合类型：状态只能是这三个字符串之一，拼错一个字母就编译不过。
// 这比在代码里到处写裸字符串安全得多，也让编辑器能自动补全
type Status = "pending" | "running" | "done";
type Result = User | null;
```

**`interface` 和 `type` 的区别**：

| | interface | type |
|---|---|---|
| 定义对象结构 | ✓ | ✓ |
| 定义联合类型 | ✗ | ✓ |
| 可以重复声明合并 | ✓ | ✗ |

**实践建议**：对象结构用 `interface`，其他用 `type`。**不用纠结，两个都能用的时候随便选。**

### 类型收窄（narrowing）

**这是 TS 最常用也最容易懵的概念。**

```typescript
function describe(x: string | number) {
  // 这里 x 是 string | number，不能直接用 .length
  // 因为 number 上没有这个属性，联合类型只允许访问所有成员共有的东西
  if (typeof x === "string") {
    console.log(x.length);       // 这里 TS 知道 x 一定是 string
  } else {
    console.log(x.toFixed(2));   // 这里 TS 知道 x 一定是 number
  }
}
```

**TS 会跟踪你的判断，自动缩小类型范围。**

```typescript
// 处理可能为 null 的值
function displayName(user: User | null) {
  // 提前 return 是最常用的收窄手段：把空值挡在门口，后面的代码就不用再判空
  if (!user) return "未登录";
  return user.name;              // 这里 TS 知道 user 不是 null
}
```

### 泛型

**先会用，再会写。**

```typescript
// 会用就行：尖括号里填的是「容器里装的是什么类型」
const names: Array<string> = [];
const scores: Map<string, number> = new Map();
const userPromise: Promise<User> = fetchUser();

// 自己写泛型函数：不写死类型，调用时传什么进来就返回什么，
// 这样一个函数能服务所有数组，又不用退回 any 丢掉类型
function first<T>(items: T[]): T | undefined {
  // 返回类型带 undefined，是因为空数组取 [0] 拿到的就是 undefined
  return items[0];
}
const x = first([1, 2, 3]);       // TS 推断出 x 是 number | undefined
```

**`T` 就是「某个类型，调用时才确定」**，和 Python 的 `TypeVar` 一个意思。

### `unknown` vs `any`

```typescript
// 典型场景：接口返回、JSON.parse 的结果，编译期确实不知道是什么类型
let a: any = fetchData();
a.whatever();                  // 编译通过，运行时可能崩

let b: unknown = fetchData();
b.whatever();                  // 编译报错，必须先收窄类型
if (typeof b === "string") {
  b.toUpperCase();             // 现在可以了
}
```

**永远不要用 `any`。** 它关掉了所有类型检查，等于你写 TS 但没得到任何好处。

**不知道类型时用 `unknown`**，它强制你先做判断。

### 可能卡在哪

**类型错误看不懂**

TS 的错误信息有时很长（尤其是泛型嵌套时）。**读第一行和最后一行**，中间的推导过程可以跳过。

**外部库没有类型**

装 `@types/包名`。大多数流行库都有。

**类型体操写不出来**

**别写。** 复杂的类型技巧对你现在没价值。**能表达清楚意图就够了。**

## 步骤 4 · 配置项目

### 这一步在做什么

建一个标准的 TS 项目。

### 怎么做

```bash
mkdir -p s5-frontend/llm-kit-ts && cd s5-frontend/llm-kit-ts
pnpm init                                    # 生成 package.json，相当于 uv init
# -D 装成开发依赖：这三个只在写代码和编译时用，上线的产物里不需要它们
# @types/node 提供 process、fs 这些 Node 内置 API 的类型，缺了它 process.env 就报错
pnpm add -D typescript @types/node tsx
pnpm tsc --init                              # 生成 tsconfig.json，下一步就改它
```

**改 `tsconfig.json`，最重要的是开严格模式**：

```json
// tsconfig.json 允许写注释，这是 TS 特意支持的，不是标准 JSON
{
  "compilerOptions": {
    "target": "ES2022",              // 编译产物的语法级别，Node 18+ 都吃得下
    "module": "ESNext",              // 用 ESM（import/export），别退回 CommonJS
    "moduleResolution": "bundler",   // 按打包器的规则找模块，省掉手写 .js 后缀的麻烦
    "strict": true,                  // 一整组严格检查的总开关，必开
    "noUncheckedIndexedAccess": true, // 数组下标取值自动带 undefined，逼你处理越界
    "esModuleInterop": true,         // 让 import 老的 CommonJS 包不报错
    "skipLibCheck": true,            // 不检查第三方 .d.ts，编译快很多且不背别人的锅
    "outDir": "dist"                 // 编译产物单独放一个目录，方便 gitignore
  },
  "include": ["src/**/*"]            // 只编译源码目录，别把测试脚本和配置一起卷进来
}
```

**`"strict": true` 从一开始就要开。** 后期再开会痛苦十倍——你会面对几百个错误。

**`noUncheckedIndexedAccess`** 让 `items[0]` 的类型变成 `T | undefined`，强制你处理越界。**一开始会觉得烦，但它能挡住一整类 bug。**

### 加脚本

```json
{
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsc",
    "check": "tsc --noEmit"
  }
}
```

（`package.json` 是严格 JSON，写不了注释，所以三个脚本在这里说明：`dev` 用 `tsx` 直接跑 TS 源码并监听改动，不用先编译；`build` 编译到 `dist/`；`check` 只做类型检查不产出文件，**这条是你提交前和 CI 里要跑的那条**。）

### 可能卡在哪

**`import` 报错说找不到模块**

ESM 和 CommonJS 的模块系统之争，这是 Node 生态最烦人的地方。

**简单的规避方法**：`package.json` 里加 `"type": "module"`，全用 ESM 语法（`import`/`export`），用 `tsx` 跑。

**遇到必须用 CommonJS 的老库时再单独处理。**

## 步骤 5 · 实战：重写 llm_kit

### 这一步在做什么

用真实项目练手，而不是做玩具练习。

### 目标

把 S1 的 `llm_kit` 用 TypeScript 重写一个精简版，只要两个能力：

1. **多模型切换**（对应 U1.2）
2. **结构化输出 + 校验**（对应 U1.3）

### 关键技术点

**用 Zod 做运行时校验**（对应 Python 的 Pydantic）：

```bash
pnpm add zod
```

```typescript
import { z } from "zod";

// schema 只写一份：既是运行时校验规则，也是编译时类型的来源
const noteInfoSchema = z.object({
  title: z.string().min(1),                    // min(1) 挡掉空字符串，它在类型上也是合法 string
  likes: z.number().int().min(0),
  tags: z.array(z.string()).default([]),       // 模型漏了 tags 就给空数组，省掉下游判空
});

// 从 schema 推导出 TS 类型（这一步很优雅）：
// 类型跟着 schema 走，以后改字段只改上面一处，不会出现两边对不上
type NoteInfo = z.infer<typeof noteInfoSchema>;

// 用 safeParse 而不是 parse：模型输出出错是常态，不该靠 try/catch 处理常态，
// 它返回 { success, data | error } 让你显式分支
const result = noteInfoSchema.safeParse(JSON.parse(rawOutput));
if (!result.success) {
  // issues 里逐条写明哪个字段、错在哪，正好可以回喂给模型让它重试（U1.3 那套）
  console.error(result.error.issues);
}
```

**`z.infer` 让「运行时校验」和「编译时类型」用同一份定义** —— 这和 Pydantic 在 Python 里的作用完全一样。

**调模型**：用 `openai` 包（它也支持所有 OpenAI 兼容的服务，改 `baseURL` 就行）。

### 可能卡在哪

**环境变量怎么读**

Node 里是 `process.env.KEY`。读 `.env` 文件需要 `dotenv` 包，或者 Node 22+ 用 `--env-file` 参数。

**异步的语法差异**

几乎没有差异。`async`/`await` 在两个语言里用法一样。

**没有 Python 的 f-string 那么方便**

模板字符串 `` `${x}` `` 基本等价，只是不支持格式化（`:.2f` 这种）。需要格式化用 `toFixed(2)`。
