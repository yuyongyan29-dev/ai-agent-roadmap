# U5.1 · TypeScript 基础（6 小时）

**这个单元解决什么问题**

前端和小程序必须用 JavaScript/TypeScript。这个单元让你从 Python 平滑过渡过去。

**好消息**：有了 Python 基础（尤其是 U0.4 学的类型注解和 Pydantic），TypeScript 会比想象中快。**很多概念是相通的，只是语法不同。**

**这个单元的姿态**：代码由 agent 写。你要做到的是**读懂它写的 TS、判断它有没有偷懒、用同一组输入对照 Python 版验收**。TS 是 agent 最擅长偷懒的语言——`any` 一写、`strict` 一关，报错全没了，代码也全没保护了。这个单元教你在验收时看出来。

**学完你能做到**：读懂 TypeScript；能判断一份 TS 代码的类型是「真的严格」还是「看起来严格」。

## 步骤 1 · 装 Node 环境

### 这一步在做什么

装好 JS 生态的基础工具，并建立 Python 工具和 Node 工具的对应关系。

### 让 agent 做

```
在我这台 macOS（或 WSL）上装 Node 开发环境：用 fnm 管理 Node 版本，装最新 LTS 并设为默认；
用 corepack 启用 pnpm。把 fnm 的初始化写进 ~/.zshrc（或 ~/.bashrc）。
不要用 brew 直接装 node，不要 npm install -g pnpm。
完成后在一个新终端里跑 node --version 和 pnpm --version 给我看。
```

### 你验收

新开一个终端窗口（**必须新开**，验证的是 shell 配置持久生效）：

```bash
node --version
pnpm --version
which node
```

版本号能打出来，`which node` 的路径里含 `fnm`。

### 你读懂

| 用途 | Python | Node |
|---|---|---|
| 版本管理 | pyenv / uv | **fnm** |
| 包管理 | uv / pip | **pnpm** / npm |
| 项目配置 | pyproject.toml | **package.json** |
| 锁文件 | uv.lock | **pnpm-lock.yaml** |
| 虚拟环境 | .venv/ | **node_modules/**（每个项目独立，天然隔离，不用激活） |
| 运行脚本 | uv run | **pnpm run** |
| 格式化 / 检查 | ruff format / ruff check | **prettier** / **eslint** |
| 类型 | 类型注解 + ty | **TypeScript + tsc** |
| 运行时校验 | Pydantic | **Zod** |

概念一一对应，只是名字不同。**`node_modules/` 必须进 `.gitignore`**（仓库里已有），它可能有几万个文件。

1. `node_modules/` 对应 Python 的什么？（`.venv/`，区别是不用激活。）
2. 为什么 fnm 的那行要写进 shell 配置文件？（否则只在当前终端生效，新开终端 `node` 又找不到——U0.1 的 PATH 问题。）

### 可能卡在哪

**`pnpm: command not found`**

`corepack enable` 没生效或需要 sudo。兜底：`npm install -g pnpm`。

**为什么用 pnpm 不用 npm**

pnpm 用硬链接共享依赖，磁盘占用小得多、安装快得多。**对你的直接影响是：开十个项目不会占掉 10GB。**

## 步骤 2 · JavaScript 必要部分 + TypeScript 类型系统

### 这一步在做什么

**不要系统学 JavaScript**，只补 TS 会用到的部分；然后学 TS 相比 JS 多出来的那一层。这一步以读为主，让 agent 写一份对照样例，你逐行对着 Python 认。

### 让 agent 做

```
在 s5-frontend/ts-basics/ 下建一个 TS 练习项目（pnpm init，tsconfig strict: true，装 tsx），
写一个 src/compare.ts，用 TypeScript 逐条实现下面这些 Python 写法的对应版本，
每条上面用中文注释写清对应的 Python 语法：
1. 变量（const/let）、模板字符串（对应 f-string）
2. 解构和展开（对应元组解包和 *、**）
3. map/filter/reduce/find（对应列表推导式）
4. 可选链 ?. 和空值合并 ??（Python 没有直接对应，说明用途）
5. 一个 interface User {id: number; name: string; email?: string}
6. 一个字面量联合类型 type Status = "pending" | "running" | "done"
7. 一个类型收窄的例子：函数接收 string | number，用 typeof 分支处理
8. 一个泛型函数 first<T>(items: T[]): T | undefined
9. unknown 和 any 的区别，各给一行，注释说明为什么不能用 any
要求：全部用箭头函数，全部用 ===，不许出现 any（第 9 条演示用的除外）。
用 `pnpm tsx src/compare.ts` 跑通，每条打印结果。
```

### 你验收

```bash
cd s5-frontend/ts-basics
pnpm tsx src/compare.ts
grep -n "any\b" src/compare.ts
grep -n "[^=!]==[^=]" src/compare.ts
grep -n "function " src/compare.ts
grep -n "var " src/compare.ts
```

应该看到：脚本跑通；`any` 只出现在第 9 条演示那一行；后三条 grep **没有输出**（没有 `==`、没有 `function` 关键字、没有 `var`）。

### 你读懂

拿 agent 写的文件，逐条对照下面这些，**每条能说出对应的 Python 写法**：

```typescript
// 解构（对应 Python 的元组解包）
const { name, age } = user;
// 展开（对应 * 和 **）：生成新对象而不是改原来的，React 要求不可变更新，后面天天用
const newUser = { ...oldUser, age: 29 };
// 数组方法（对应列表推导式）：都返回新数组，不改原数组
const evens = numbers.filter(x => x % 2 === 0);
// 可选链和空值合并：中间任何一层是 null/undefined 都不抛错，整条链得 undefined，再由 ?? 兜底
const city = user?.address?.city ?? "未知";

// 字面量联合类型：拼错一个字母就编译不过，比到处写裸字符串安全
type Status = "pending" | "running" | "done";

// 类型收窄：TS 会跟踪你的判断，自动缩小类型范围
function describe(x: string | number) {
  if (typeof x === "string") console.log(x.length);   // 这里 TS 知道 x 一定是 string
  else console.log(x.toFixed(2));                      // 这里一定是 number
}

// 泛型：不写死类型，调用时传什么进来就返回什么；返回带 undefined 是因为空数组取 [0] 就是 undefined
const first = <T,>(items: T[]): T | undefined => items[0];

let b: unknown = JSON.parse(raw);
if (typeof b === "string") b.toUpperCase();   // unknown 强制你先收窄；any 则什么都不管
```

三个必须能口头回答的：

1. `"1" == 1` 是 true 还是 false？`===` 呢？（true / false。**永远用 `===`**，这是铁律。）
2. `null` 和 `undefined` 有什么区别？（前者是明确赋值为「空」，后者是从来没赋过值。实践中用 `??` 和 `?.` 一起处理。）
3. `any` 和 `unknown` 的区别？（`any` 关掉所有检查，等于写 TS 但没得到任何好处；`unknown` 强制你先判断类型才能用。**不知道类型时用 `unknown`。**）

### 可能卡在哪

**`this` 的绑定**

普通函数里的 `this` 取决于怎么调用的，箭头函数继承外层的 `this`。**规避方法：永远用箭头函数。** 这就是上面指令要求「全部用箭头函数」的原因。看到老代码里的 `function` 关键字，等价于箭头函数（除了 `this` 的行为）。

**类型错误看不懂**

TS 的错误信息有时很长（尤其泛型嵌套时）。**读第一行和最后一行**，中间的推导过程跳过。

**类型体操写不出来**

**别写，也别让 agent 写。** 复杂的类型技巧对你现在没价值。能表达清楚意图就够了。

## 步骤 3 · 配置项目

### 这一步在做什么

建一个标准的 TS 项目，最重要的是**从第一天就开严格模式**。后期再开会痛苦十倍——你会面对几百个错误。

### 让 agent 做

```
在 s5-frontend/llm-kit-ts/ 建 TS 项目：pnpm init，装 typescript、@types/node、tsx 为开发依赖。
tsconfig.json 要求：target ES2022，module ESNext，moduleResolution bundler，
strict: true，noUncheckedIndexedAccess: true，outDir dist，只 include src/**/*。
package.json 加 "type": "module"，scripts 里加 dev（tsx watch）、build（tsc）、check（tsc --noEmit）。
不许把 strict 关掉或者调低任何一项严格检查。
```

### 你验收

```bash
cd s5-frontend/llm-kit-ts
cat tsconfig.json
pnpm check
```

`tsconfig.json` 里 `"strict": true` 和 `"noUncheckedIndexedAccess": true` 必须都在；`pnpm check` 零报错（现在还没代码，理应零）。

### 你读懂

```json
{
  "compilerOptions": {
    "strict": true,                   // 一整组严格检查的总开关，必开
    "noUncheckedIndexedAccess": true, // 数组下标取值自动带 undefined，逼你处理越界
    "module": "ESNext",               // 用 ESM（import/export），别退回 CommonJS
    "skipLibCheck": true              // 不检查第三方 .d.ts，编译快很多且不背别人的锅
  }
}
```

1. `pnpm check` 干什么，什么时候跑？（只做类型检查不产出文件，**提交前和 CI 里跑这条**。）
2. `noUncheckedIndexedAccess` 让 `items[0]` 的类型变成什么？（`T | undefined`，一开始烦，但挡住一整类越界 bug。）

### 可能卡在哪

**`import` 报错说找不到模块**

ESM 和 CommonJS 之争，Node 生态最烦人的地方。规避：`package.json` 里 `"type": "module"`，全用 `import`/`export`，用 `tsx` 跑。遇到必须用 CommonJS 的老库再单独处理。

## 步骤 4 · 实战：让 agent 重写 llm_kit

### 这一步在做什么

用真实项目练手。把 S1 的 `llm_kit` 用 TS 重写一个精简版，只要两个能力：**多模型切换**（对应 U1.2）和**结构化输出 + 校验**（对应 U1.3）。**验收标准不是「能跑」，是「和 Python 版行为一致」。**

### 让 agent 做

```
读 s1-llm/ 下的 llm_kit（Python），在 s5-frontend/llm-kit-ts/src/ 用 TypeScript 重写精简版：
1. 多模型切换：用 openai 包，通过 baseURL 和 apiKey 切换 OpenAI 兼容服务，配置从 process.env 读
2. 结构化输出：用 zod 定义 schema，用 z.infer 推导类型，用 safeParse 校验模型输出，
   失败时打印 result.error.issues（哪个字段、错在哪）
3. 写一个 src/cli.ts：读入一段文本，抽取结构化信息，打印 JSON
要求：pnpm check 零报错；整个 src/ 不许出现 any；不许改 tsconfig；
schema 字段和 Python 版的 Pydantic 模型逐字段对应。
```

### 你验收

同一段输入，两个版本各跑一次：

```bash
# Python 版
cd ~/ai-agent-roadmap && uv run python -m llm_kit.cli "这台电视 65 寸，用户评价很好，点赞 120" > /tmp/py.json
# TS 版
cd s5-frontend/llm-kit-ts && pnpm tsx src/cli.ts "这台电视 65 寸，用户评价很好，点赞 120" > /tmp/ts.json
diff <(jq -S . /tmp/py.json) <(jq -S . /tmp/ts.json) && echo "两版字段一致"
pnpm check
grep -rn "any\b" src/
grep -n "strict" tsconfig.json
```

应该看到：「两版字段一致」（模型输出的具体值可能略有差异，**字段名和类型必须一致**）；`pnpm check` 零报错；`any` 无输出；`strict` 仍是 `true`。

再故意喂一段抽不出信息的文本，两个版本都应该报**字段级**的校验错误，而不是崩掉。

### 你读懂

```typescript
import { z } from "zod";

// schema 只写一份：既是运行时校验规则，也是编译时类型的来源
const noteInfoSchema = z.object({
  title: z.string().min(1),                    // min(1) 挡掉空字符串，它在类型上也是合法 string
  likes: z.number().int().min(0),
  tags: z.array(z.string()).default([]),       // 模型漏了 tags 就给空数组，省掉下游判空
});
// 类型跟着 schema 走，以后改字段只改上面一处
type NoteInfo = z.infer<typeof noteInfoSchema>;

// safeParse 而不是 parse：模型输出出错是常态，不该靠 try/catch 处理常态
const result = noteInfoSchema.safeParse(JSON.parse(rawOutput));
if (!result.success) console.error(result.error.issues);   // 逐条写明哪个字段错在哪，可回喂给模型重试
```

1. `z.infer` 解决了什么问题？（运行时校验和编译时类型用同一份定义，**和 Pydantic 在 Python 里的作用完全一样**。）
2. 为什么用 `safeParse` 不用 `parse`？（模型输出出错是常态，它返回 `{ success, data | error }` 让你显式分支，而不是抛异常。）
3. `.default([])` 对应 Pydantic 的什么？（`tags: list[str] = []`。）

### 可能卡在哪

**agent 用 `any` 逃避类型，或者悄悄把 `strict` 关了（本单元的 vibe coding 坑）**

这是 TS 里 agent 最常见的偷懒方式，而且**报错确实全消失了**，你会以为它修好了。三种变体：

- `const data: any = await response.json()` —— 一个 `any` 传染整条链路，下游全失去保护
- `// @ts-ignore` 或 `as unknown as Foo` 这种强转
- 把 `tsconfig.json` 里 `strict` 改成 `false`，或删掉 `noUncheckedIndexedAccess`

**识别方法**就是验收里那三条：`grep any`、`grep strict`、加一条 `grep -rn "ts-ignore\|as unknown as" src/`。**规则和 U0.4 一样：任何让报错消失但不改代码的操作，都要问它为什么。** 正确做法是用 `unknown` 接住，再用 Zod 收窄——这正是 Zod 存在的意义。

**环境变量怎么读**

Node 里是 `process.env.KEY`。读 `.env` 文件用 `dotenv` 包，或 Node 22+ 的 `--env-file` 参数。

**没有 f-string 的 `:.2f`**

模板字符串不支持格式化，需要用 `toFixed(2)`。
