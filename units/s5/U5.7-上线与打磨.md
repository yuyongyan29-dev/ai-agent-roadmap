# U5.7 · 三端上线与部署矩阵（14 小时）

**这个单元解决什么问题**

Web、小程序、App 三端的代码都有了，现在要把它们真正发到用户手上，而且发的是同一个后端。这一步把三件事做完：Web 该部署到哪（三条路，各有适用场景）、三端怎么共用一个后端不出安全事故、小程序和 App 各自怎么过审。

**学完你能做到**：一个有域名的 Web 地址，至少两条部署路径走通过；小程序提交过审核；三端打的是同一个后端，CORS 和域名白名单配置正确；三个朋友不用你解释就会用。

**这一单元的代码大部分由 agent 写，但配置类的东西（环境变量、域名、白名单）你必须自己看一遍。** 部署事故十有八九出在配置，而 agent 看不到你的云控制台。

---

## 步骤 1 · Web 部署三条路，先选再动手

### 这一步在做什么

Next.js 的部署不止 Vercel 一条路。三条路的区别不在难度，在**用户在哪、你要不要备案、后端在哪**。

### 决策表

| | 路径一：Vercel | 路径二：腾讯云 CloudBase | 路径三：自建 Docker + VPS |
|---|---|---|---|
| **适合** | 用户在海外或不介意国内访问慢；练手；要 PR 预览环境 | 用户主要在国内；想要国内访问快；不想管服务器 | 后端已经在一台 VPS 上（U4.7）；想把前后端放一起；想完全掌控 |
| **备案** | 不需要（服务器在境外） | **默认域名不需要**，自定义域名需要 | 服务器在国内需要；境外 VPS 不需要 |
| **Next.js 支持** | 完整，SSR / Server Actions / 流式全支持 | 静态导出直接放静态托管；SSR 要走云托管（容器） | 完整，你自己跑 `next start` 或容器 |
| **国内访问** | 慢且不稳定，有时被墙 | 快 | 取决于 VPS 位置 |
| **每次发版** | git push 自动 | CLI 一条命令，或接 GitHub Actions | `docker compose pull && up -d`，或复用 U4.6 的灰度脚本 |
| **免费额度** | 个人项目够用 | 有免费额度，以官网当前为准 | VPS 月费，最便宜的够用 |
| **一句话** | 最省心，国内体验差 | 国内首选，SSR 要多一步 | 最灵活，运维是你自己 |

**建议**：Vercel 和 CloudBase 各走一遍（本单元的完成判据），第三条如果你 S4 的后端在 VPS 上就顺手做了。三条都走过的人，面试时「前端怎么部署」这个问题不会被问住。

### 背后的逻辑

三条路对应三种「谁来运维」：Vercel 是平台全包，CloudBase 是国内平台全包，VPS 是你自己。**你选的不是技术，是把哪部分运维责任交出去。** 交出去越多越省心，代价是控制权和国内访问质量。

## 步骤 2 · 路径一：Vercel

### 这一步在做什么

Next.js 的官方平台，免费额度够个人项目用。

### 让 agent 做

在 Claude Code 里：

```
把 s5-frontend/web 准备好部署到 Vercel。检查三件事并修掉：
1. 本地 pnpm build 能通过（TypeScript 零报错）
2. 所有服务端要用的环境变量都从 process.env 读，列一张清单给我，标明哪些是 build 时需要、哪些是运行时需要
3. 没有任何密钥被写死在代码里或进了 NEXT_PUBLIC_ 前缀的变量
不要帮我在 Vercel 上操作，那部分我自己做。
```

### 你自己做

1. 把 `s5-frontend/web` 推到 GitHub（可以是你学习仓库的一个目录，Vercel 支持指定根目录）
2. 在 [vercel.com](https://vercel.com) 用 GitHub 登录，导入仓库
3. 配置 **Root Directory**：`s5-frontend/web`，Framework 自动识别为 Next.js
4. **配环境变量**（Settings → Environment Variables），对照 agent 给你的清单逐个填：
   - `AGENT_API`：你 U4.7 部署的后端地址
   - `AGENT_API_KEY`
   - 数据库连接串、认证密钥
5. 部署

**之后每次 push 到 main 会自动部署。** PR 会自动生成预览环境——**可以把预览链接发给朋友试用，不影响正式版。**

### 你验收

- 打开线上地址，完整走一遍主流程，流式输出正常
- 打开浏览器开发者工具 → Network，确认没有任何请求直接打到带密钥的地址；密钥只应该在 Vercel 的 Functions 日志里出现
- 故意在 Vercel 上删掉一个环境变量重新部署，看它是在 build 阶段失败还是运行时失败——这决定了以后出问题去看哪个日志

### 你读懂

**`NEXT_PUBLIC_` 前缀的含义**：带这个前缀的变量会被打进浏览器端的 JS，**任何人都能看到**。agent 偶尔为了「方便」把 API key 放进 `NEXT_PUBLIC_`，页面能跑，密钥就泄露了。这是本步骤唯一必须你亲自看的地方。

### 可能卡在哪

**build 失败**：构建日志很详细。常见原因是环境变量缺失、TypeScript 报错、依赖版本问题。**先在本地 `pnpm build`，本地过了再推。**

**部署成功但页面报错**：看 Runtime Logs（Functions 标签页）。通常是运行时环境变量缺失或后端地址不对。

**Vercel 在国内访问慢**：这就是路径二存在的原因。

**长任务不要放在 Vercel 上跑。** 它有函数执行时长限制。你的架构是对的：Vercel 只跑前端和轻量转发，重活在 U4.7 部署的后端。

## 步骤 3 · 路径二：腾讯云 CloudBase

### 这一步在做什么

国内访问快、不用管服务器的选项。**它有两种形态**，取决于你的 Next.js 用不用服务端渲染：

- **静态托管**：Next.js 用 `output: 'export'` 导出纯静态文件，扔到 CloudBase 静态网站托管。最简单，默认域名开箱即用。
- **云托管（容器）**：需要 SSR、Server Actions 或流式转发时，把 Next.js 打成容器跑在 CloudBase 云托管上。

**你的 Agent 界面是流式的，而且密钥不能出服务端**，所以正式版应该走云托管。但先用静态托管把流程跑通，再上云托管。

### 备案这件事，说准确

- CloudBase 给每个环境一个默认域名（形如 `xxx.tcloudbaseapp.com`），**这个域名不需要备案就能用**，适合练手和给朋友试用。
- **绑自己的域名需要该域名已完成 ICP 备案。** 备案走腾讯云的备案入口，审核周期以工信部规定为上限（20 个工作日）。
- 以 [CloudBase 静态网站托管文档](https://cloud.tencent.com/document/product/876) 当前说明为准。

### 让 agent 做

```
把 s5-frontend/web 做成可以部署到腾讯云 CloudBase 的两个版本：
1. 静态版：加一个 next.config 的导出配置（output: 'export'），告诉我哪些页面因为用了服务端能力不能静态导出，先用一个占位页替代
2. 容器版：写 Dockerfile（多阶段构建，standalone 输出）和 .dockerignore，本地 docker build 并跑起来验证
另外写一个 scripts/deploy-cloudbase.sh，用 @cloudbase/cli 把 out/ 目录部署到静态托管，环境 ID 从环境变量 TCB_ENV 读。
不要把任何密钥写进脚本。
```

### 你自己做

1. 在 [console.cloud.tencent.com/tcb](https://console.cloud.tencent.com/tcb) 开通一个环境，记下环境 ID
2. `npm i -g @cloudbase/cli`，`tcb login`，浏览器里扫码
3. 静态版：`pnpm build` 生成 `out/`，跑 agent 写的部署脚本，打开默认域名
4. 容器版：在控制台的云托管里新建服务，选「本地代码」或接 GitHub，用 agent 写的 Dockerfile 构建；环境变量在服务配置里填

### 你验收

- 默认域名在手机上（用流量，不连 WiFi）打开，首屏明显比 Vercel 快
- 容器版的流式输出正常，且 Network 里看不到密钥
- 把 `TCB_ENV` 设成一个错的值跑部署脚本，确认它报错退出而不是静默成功

### 你读懂

**为什么静态版跑不了你的完整功能**：`output: 'export'` 会把所有页面在构建时渲染成 HTML，没有服务端。你的 API 转发、密钥保护、流式都依赖服务端，所以静态版只能当落地页和演示壳，**正式版必须是容器版**。这个区别 agent 通常会说，但它可能把不能导出的页面直接删掉而不是告诉你，验收时要对照页面清单看有没有少。

### 可能卡在哪

**`tcb` 命令找不到**：全局安装的 npm bin 目录不在 PATH 里，回 U0.1 步骤 7。

**静态导出报 `Page ... couldn't be rendered statically`**：这就是上面说的，那个页面用了服务端能力。先占位，正式版走容器。

**容器版启动了但 502**：Next.js 默认监听 `localhost`，容器里必须监听 `0.0.0.0`，端口要和云托管配置的一致。这个坑和 U0.9 Docker 那节一模一样。

**自定义域名绑不上**：先看备案状态。没备案的域名在国内云厂商这里绑不上，这不是配置问题。

## 步骤 4 · 路径三：自建 Docker + VPS

### 这一步在做什么

你在 U4.7 已经有一台跑着后端的服务器。把前端容器放到同一台机器的同一个 compose 里，nginx 统一对外。**这条路的收获是完整地看到「一个产品」在一台机器上是什么样子。**

### 让 agent 做

```
读 s4-production 里现有的 compose.yaml 和 nginx 配置。把 s5-frontend/web 作为一个新服务加进去：
1. 用步骤 3 写的 Dockerfile 构建，服务名 web，只在内网暴露 3000
2. nginx 加一个 server 块：域名 app.example.com 转到 web:3000，/api/ 前缀继续转到后端；流式路径要 proxy_buffering off（参考 U4.0 里那个实验）
3. 前端的 AGENT_API 指向 compose 内网的后端服务名，不走公网
4. 写一条 make deploy-web 命令：拉最新镜像、只重启 web 服务、跑一次健康检查
```

### 你自己做

- 把域名的 A 记录指到这台机器
- 用 U4.7 的方式签 HTTPS 证书（certbot 或 Caddy，你当时用哪个就用哪个）
- 跑 `make deploy-web`

### 你验收

- 用 `docker compose ps` 看 web 服务健康
- 从手机打开域名，流式输出不卡顿（如果一段一段蹦出来，是 nginx 缓冲没关，回去看 U4.0）
- 停掉 web 容器，确认后端 API 还能被小程序正常调用——前后端应该是独立的故障域

### 你读懂

**为什么前端走内网调后端**：省一次公网往返、不暴露后端端口、不用为内部调用配 CORS。**但要注意浏览器端发起的请求走的还是公网**（用户的浏览器在他手里，不在你的内网），所以 nginx 的 `/api/` 转发仍然要在。分清「服务端组件发的请求」和「浏览器发的请求」，是 U5.3 那个 Server/Client 区分在部署层的延伸。

### 可能卡在哪

**改了 nginx 配置忘了 reload**：`docker compose exec nginx nginx -s reload`，或者直接重启 nginx 容器。

**两个容器都健康但页面 502**：nginx 里写的服务名和 compose 里的服务名不一致，或者不在同一个 network。

## 步骤 5 · 三端共用一个后端：CORS、白名单、环境分离

### 这一步在做什么

三端打同一个后端时，会撞上三个配置问题。**这三个都不是代码 bug，agent 修不了，因为它看不到你的域名和控制台。** 这一步你要自己动手。

### 三件事

**一、CORS（浏览器端独有）**

Web 端在浏览器里发请求，浏览器会检查后端是否允许你的前端域名。后端要在响应头里明确列出允许的来源：

```python
# 后端 FastAPI 里：只放行你自己的域名，不要写 "*"
# 放行列表从环境变量读，本地开发、预览环境、正式环境各不一样
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,   # 例：["https://app.example.com", "https://xxx.vercel.app"]
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)
```

**小程序和 App 不受 CORS 约束**（它们不是浏览器），所以 CORS 报错只会出现在 Web 端。反过来说，CORS 也保护不了小程序和 App 的调用，后端的鉴权（U5.5）才是真正的防线。

**二、小程序 request 合法域名**

微信要求小程序只能请求在后台登记过的域名，而且**必须是 HTTPS、必须备案**。在 [微信公众平台](https://mp.weixin.qq.com) → 开发 → 开发管理 → 服务器域名，把你后端的域名填进 `request 合法域名`；用了 WebSocket 就再填 `socket 合法域名`。

- 每月修改次数有限制（以后台当前提示为准），**所以别用会变的域名**（Vercel 的预览域名、CloudBase 默认域名都不行）
- 开发工具里可以勾「不校验合法域名」来本地调试，**真机预览时这个开关无效**，会直接请求失败

**三、环境变量分环境**

三端、三个环境（本地 / 预览 / 正式），后端地址和密钥不能混。约定：

| 环境 | Web 后端地址 | 小程序后端地址 | 数据库 |
|---|---|---|---|
| 本地 | `http://localhost:8000` | 开发工具里关校验，指本地 | 本地 Postgres |
| 预览 | 预览后端（可以和正式共用代码，独立数据库） | 体验版指预览后端 | 预览库 |
| 正式 | `https://api.example.com` | 正式版指正式后端 | 正式库 |

**体验版小程序和正式版小程序必须能指向不同后端**，否则你审核时的测试数据会进正式库。Taro 用 `process.env` 加构建时的环境文件区分。

### 让 agent 做

```
1. 后端：把 CORS 允许列表改成从环境变量 CORS_ORIGINS 读（逗号分隔），并在启动日志里打印当前允许的来源
2. 小程序：把后端地址改成按构建环境读取，给我 .env.development / .env.staging / .env.production 三个文件的模板
3. 写一个 scripts/check-env.sh：检查三端的环境文件里没有出现 localhost 以外的 http:// 地址、没有出现任何看起来像密钥的值
```

### 你验收

- Web 正式版能调后端；把 `CORS_ORIGINS` 里的正式域名删掉重启，Web 立刻报 CORS 错误，说明配置生效
- 小程序真机预览能调后端；在微信后台把域名删掉，真机立刻失败
- 体验版小程序发一条消息，确认它落在预览库而不是正式库

### 你读懂

**CORS 不是安全机制**。它只约束浏览器，`curl` 一下就绕过了。真正拦住越权访问的是 U5.5 的鉴权和数据隔离。很多人把 CORS 配成 `*` 然后以为「反正有 CORS」，两头都错。

## 步骤 6 · 域名和基础配置

### 这一步在做什么

让它看起来像个正经产品。

### 让 agent 做

```
给 s5-frontend/web 补全站点元信息：layout.tsx 里的 metadata（title、description、icons、openGraph），
生成一张 1200x630 的 og.png 占位图放到 public/。产品名和描述用 PROJECT.md 里的。
```

### 你自己做

**域名**：Vercel 在 Domains 里添加，按提示配 DNS，HTTPS 自动；CloudBase 和 VPS 见步骤 3、4。

### 你验收

把线上链接发到微信里给自己，看预览卡片有没有标题、描述和图。**没有图的链接点开率差很多。**

### 你读懂

```tsx
// src/app/layout.tsx
// Next.js 会把这个 metadata 对象渲染成 <head> 里的标签，
// 放在 layout 里是给全站兜底，单页可以再覆盖
export const metadata = {
  title: "你的产品名",
  description: "一句话说明它能做什么",
  icons: { icon: "/favicon.ico" },       // 相对 public/，放错位置不报错，只是静默用默认图标
  // openGraph 是给微信、Twitter 这些抓取方看的，标题描述要能脱离页面单独成立
  openGraph: {
    title: "你的产品名",
    description: "...",
    images: ["/og.png"],                 // 1200x630，尺寸不对会被裁掉或不显示
  },
};
```

## 步骤 7 · 移动端适配

### 这一步在做什么

**大多数人会用手机打开你的链接。**

### 让 agent 做

```
检查 s5-frontend/web 的移动端适配，修掉这四类问题并逐条告诉我改了哪：
1. 输入框被软键盘遮挡（容器高度用 100dvh 而不是 100vh）
2. 页面能横向滚动（找出溢出元素修掉，宽内容放进 overflow-x-auto 容器，不要粗暴 overflow-x: hidden）
3. 可点击元素小于 44x44
4. iPhone 安全区域（env(safe-area-inset-*)）
```

### 你验收

**必须用真机。** 模拟器不模拟真实键盘、浏览器 UI 高度变化、触摸细节和真实网速。在你自己的手机上完整走一遍，四个问题逐个确认。

### 你读懂

```css
/* dvh 会随浏览器地址栏收起/展开而变，vh 不会，所以键盘弹起时 vh 布局会被顶出屏幕 */
.chat-container { height: 100dvh; }

/* env() 在没有刘海的设备上返回 0，不用做机型判断 */
.bottom-bar { padding-bottom: env(safe-area-inset-bottom); }
```

`overflow-x: hidden` 是把症状藏起来，不是修好。agent 喜欢用它一行解决，**你要看它是不是真的找出了溢出的元素**。

## 步骤 8 · 状态完备

### 这一步在做什么

**每个界面都要处理四种状态，缺一个就会有用户困惑。**

| 状态 | 该显示什么 |
|---|---|
| **加载中** | 骨架屏或加载动画，**不要空白** |
| **空** | 「还没有对话，点击下方开始」+ 引导操作 |
| **错误** | 说明问题 + 重试按钮 |
| 正常 | 内容 |

### 让 agent 做

```
遍历 s5-frontend/web 的每个页面和列表组件，确保四种状态都有处理。
空状态必须包含一句具体的示例输入（从 PROJECT.md 的使用场景里取），和一个直接发起操作的按钮。
列一张表：页面 × 四种状态，标出你新增了哪些。
```

### 你验收

- 断网打开页面，看到的是错误状态和重试按钮，不是白屏或转圈到死
- 新建一个账号登录，看到的是空状态，且示例输入是**你的用户真的会问的话**，不是「请输入内容」
- 快速刷新几次，看有没有先闪一下「还没有对话」再出现内容

### 你读懂

```tsx
// 四个分支的顺序不能换：数据还在路上时 conversations 也是空数组，
// 先判空就会闪一下「还没有对话」
if (isLoading) return <Skeleton />;
if (error) return <ErrorState error={error} onRetry={retry} />;
if (conversations.length === 0) return <EmptyState onStartChat={startChat} />;
return <ConversationList items={conversations} />;
```

**「空状态」最容易被忘，也最重要**：新用户第一次打开看到的就是它，这是你唯一的引导机会。给一个具体的例子输入，用户不知道该说什么是最大的流失点。

## 步骤 9 · 性能

### 这一步在做什么

用工具找出明显的问题，修掉。不要过度优化。

### 你自己做

Chrome 开发者工具 → Lighthouse → 选 Mobile → 分析。先看三项：

| 指标 | 含义 | 常见问题 |
|---|---|---|
| **LCP** 最大内容绘制 | 主要内容多久出现 | 图片太大、字体阻塞 |
| **CLS** 累积布局偏移 | 内容有没有跳动 | 图片没设尺寸、字体切换 |
| 首屏 JS 体积 | 要下载多少代码 | 引入了大库 |

### 让 agent 做

把 Lighthouse 报告里 LCP 和 CLS 的具体问题项贴给它：

```
这是 Lighthouse 移动端报告的 LCP 和 CLS 问题项。逐条修：
- 图片改用 next/image 并给出 width/height
- 字体用 next/font 并 display: swap；中文正文优先用系统字体栈
- 用 @next/bundle-analyzer 找出首屏最大的三个包，告诉我能不能换或懒加载
只修这几项，不要为了分数改别的。
```

### 你验收

再跑一次 Lighthouse，LCP 和 CLS 有实质改善即可。**别为了分数优化。** Accessibility 项报的缺 `alt`、缺 `label`、对比度不够值得顺手修，成本低而且真的有用户需要。

### 你读懂

```css
/* 中文字体动辄几 MB，能用系统字体就用系统字体 */
font-family: system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
```

`<Image>` 必须给 width 和 height，否则图片加载前后高度变化，就是 CLS。`display: "swap"` 让文字先用系统字体显示，避免字体加载期间白屏。

### 这一步在做什么

**这一页是你作品集的门面。** 要回答四个问题：这是什么、解决什么问题、怎么用、长什么样。

## 步骤 11 · 小程序上线：体验版 → 审核 → 发布

### 这一步在做什么

U5.6 做出来的小程序目前只在你的开发工具和真机预览里能用。发给别人要过微信的审核。

### 流程

1. **上传代码**：开发工具 → 上传，填版本号和备注。上传后在 [微信公众平台](https://mp.weixin.qq.com) → 版本管理 里出现「开发版本」
2. **设为体验版**：把开发版本设为体验版，生成体验二维码。**把体验二维码发给你的三个测试用户**，他们要先被加为体验成员
3. **提交审核**：填写功能页面、测试账号（**审核员需要能登录进去用**，给一个测试账号密码）、类目
4. **等审核**：通常 1–7 天，以后台当前提示为准。被拒会给原因
5. **发布**：审核通过后手动点发布，或设置定时发布

### 提交审核前的自查

| 检查项 | 为什么 |
|---|---|
| 服务类目和你的功能一致，需要资质的类目资质已传 | 最常见的被拒原因 |
| 后端域名已加到 request 合法域名，且备案、HTTPS | 审核员打开就请求失败等于功能不完整 |
| 给了能用的测试账号 | 审核员进不去直接拒 |
| 页面里没有「测试」「demo」「占位」字样 | 被认为功能不完整 |
| 涉及 AI 生成内容的地方有明确标识，输出有内容安全过滤 | 2024 年后生成式 AI 类小程序的审核重点，具体要求以后台类目说明为准 |
| 没有诱导分享、没有外链到未备案域名 | 平台规则 |

### 让 agent 做

```
给小程序加两样东西：
1. 所有 AI 生成的回复前加一个不可关闭的小标识「AI 生成」
2. 在后端 Agent 输出到小程序之前接一层内容安全检查（先用微信的 msgSecCheck 接口，没有资质就先用关键词表占位，但要留好接口）
```

### 你验收

- 体验版在三个测试用户的手机上都能用，且他们的数据进的是预览库（步骤 5）
- 自查表逐项打勾
- **提交一次审核**。被拒也算完成——把拒绝原因记到笔记里，这是真实世界给你的反馈

### 你读懂

小程序审核的逻辑是「你声称做什么，就得是什么，而且得完整」。类目、资质、测试账号、页面完整度，全是围绕这一条。**AI 对话类产品被拒最多的是类目不符和内容安全**，前者在 U5.0 选类目时就要想清楚，后者是上面让 agent 加的两样东西。

### 可能卡在哪

**审核被拒，原因写得很笼统**：微信的拒绝理由经常只有一句话。在后台的「审核记录」里通常有截图，看截图定位到哪个页面。改完重新提交，不用从头来。

**体验成员加不上**：对方必须先关注/登录过微信开发者相关的授权，让他打开体验二维码时按提示操作。

**真机预览正常，体验版请求失败**：九成是合法域名没配，体验版和正式版都会校验域名。

## 步骤 12 · App 分发与三端发布节奏

### 这一步在做什么

App 的打包、签名、商店提交都在 **U5.8**（Expo 那个单元）里。这里只说三端一起发版时的节奏。

### 三端发布节奏

三端的「发一版」摩擦力差别很大，所以**不要试图三端同步发版**：

| 端 | 发一版要多久 | 节奏建议 |
|---|---|---|
| Web | 几分钟 | 随时发，小步快跑。新功能先在 Web 上验证 |
| 小程序 | 1–7 天审核 | 每 1–2 周攒一版。Web 上验证过的功能才进小程序 |
| App | 商店审核 1–3 天起，加上用户不一定更新 | 每 2–4 周一版；紧急修复用 Expo 的 OTA 更新（U5.8 讲），不用过商店 |

**后端要向后兼容至少一个版本**：用户手里的 App 可能还是上一版，你的后端 API 不能一改就让旧版全挂。这就是 U4.6 灰度与回滚里「接口版本化」在三端场景下的必要性。

### 让 agent 做

```
检查后端 API 有没有版本前缀（/v1/）。没有的话加上，并给出一个「新增字段不算破坏、删字段和改类型算破坏」的兼容性检查清单，
放到 CONTRIBUTING 或 docs 里。
```

### 你读懂

三端共用后端的真正难点不在部署，在**发布节奏不一致**。Web 可以一天发十次，App 用户可能一个月不更新。后端的每一次改动都要问一句「上上版 App 调这个接口还能用吗」。
