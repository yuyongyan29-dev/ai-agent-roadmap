**这个单元解决什么问题**

把 Web 端真正发出去，让别人打开就能用、一眼看懂。

**学完你能做到**：一个有域名的线上地址，手机浏览器打开流畅可用；三个朋友不用你解释就知道怎么用。

## 步骤 1 · 部署到 Vercel

### 这一步在做什么

Next.js 的官方平台，免费额度够个人项目用。

### 怎么做

1. 把 `s5-frontend/web` 推到 GitHub（可以是你学习仓库的一个目录，Vercel 支持指定根目录）
2. 在 [vercel.com](https://vercel.com) 用 GitHub 登录，导入仓库
3. 配置：
   - **Root Directory**：`s5-frontend/web`
   - Framework：Next.js（自动识别）
4. **配环境变量**（在 Vercel 的 Settings → Environment Variables）：
   - `AGENT_API`：你 U4.7 部署的后端地址
   - `AGENT_API_KEY`
   - 数据库连接串
   - 认证相关的密钥

5. 部署

**之后每次 push 到 main 会自动部署。** PR 会自动生成预览环境，这个很好用——**可以把预览链接发给朋友试用，不影响正式版。**

### 可能卡在哪

**build 失败**

Vercel 的构建日志很详细。常见原因：

1. 环境变量缺失（build 时就需要的那些）
2. TypeScript 报错（本地 `pnpm build` 能复现）
3. 依赖版本问题

**先在本地跑一次 `pnpm build`**，本地通过了再推。

**部署成功但页面报错**

看 Vercel 的 Runtime Logs（Functions 标签页）。**通常是环境变量在运行时缺失**，或者后端地址不对。

**Vercel 在国内访问慢**

确实。三个选择：

1. 接自己的域名 + CDN
2. 部署到国内平台（阿里云、腾讯云的静态托管 + 函数计算）
3. 练手阶段先忍受

**长任务不要放在 Vercel 上跑。** 它有函数执行时长限制。**你的架构是对的**：Vercel 只跑前端和轻量的转发，重活在 U4.7 部署的后端。

## 步骤 2 · 域名和基础配置

### 这一步在做什么

让它看起来像个正经产品。

### 清单

**域名**：在 Vercel 的 Domains 里添加，按提示配 DNS。**Vercel 自动配 HTTPS。**

**favicon 和站点信息**：

```tsx
// src/app/layout.tsx
// Next.js 会把这个 metadata 对象渲染成 <head> 里的标签，
// 不用自己写 <title>；放在 layout 里是给全站兜底，单页可以再覆盖
export const metadata = {
  title: "你的产品名",
  description: "一句话说明它能做什么",
  // 图标路径相对 public/ 目录，文件放错位置不会报错，只会静默显示默认图标
  icons: { icon: "/favicon.ico" },
};
```

**OG 标签**（分享到微信、Twitter 时的预览图）：

```tsx
export const metadata = {
  // openGraph 的内容不给自己的页面用，是给微信、Twitter 这些抓取方看的，
  // 所以这里的标题描述要能脱离页面单独成立
  openGraph: {
    title: "你的产品名",
    description: "...",
    // 尺寸是各家平台的通用要求，尺寸不对会被裁掉或者干脆不显示
    images: ["/og.png"],       // 1200x630
  },
};
```

**这个细节很影响第一印象。** 分享出去有预览图和没有，差别很大。

## 步骤 3 · 移动端适配

### 这一步在做什么

**大多数人会用手机打开你的链接。**

### 必查的四个问题

**一、输入框被键盘遮挡**

这是移动端最常见的问题。

```css
/* 用 dvh 而不是 vh，它会考虑动态的浏览器 UI */
.chat-container { height: 100dvh; }
```

**在真机上测**，模拟器测不出来。

**二、横向滚动**

页面不应该能左右滑动。检查：

```css
body { overflow-x: hidden; }
```

但更好的做法是找出溢出的元素修掉。**用开发者工具的移动端模式，逐个元素查。**

宽内容（代码块、表格）要放在自己的滚动容器里：

```tsx
{/* 溢出限制在这一层：外面的 div 自己横向滚，页面 body 就不会被撑宽 */}
<div className="overflow-x-auto">
  <pre>...</pre>
</div>
```

**三、点击区域太小**

按钮的可点击区域至少 44×44 像素。**手指没有鼠标精确。**

```css
button { min-height: 44px; min-width: 44px; }
```

**四、安全区域**

iPhone 有刘海和底部横条：

```css
/* env() 在非刘海设备上返回 0，所以不用做机型判断，写死就行 */
.bottom-bar { padding-bottom: env(safe-area-inset-bottom); }
.top-bar { padding-top: env(safe-area-inset-top); }
```

### 可能卡在哪

**在 Chrome 的移动端模拟器里正常，真机不正常**

模拟器不模拟：真实键盘、真实的浏览器 UI 高度变化、触摸事件的细节、真实的网络速度。

**必须用真机测。** 把你的 Vercel 地址在手机上打开，完整走一遍。

## 步骤 4 · 状态完备

### 这一步在做什么

**每个界面都要处理四种状态，缺一个就会有用户困惑。**

### 四种状态

| 状态 | 该显示什么 |
|---|---|
| **加载中** | 骨架屏或加载动画，**不要空白** |
| **空** | 「还没有对话，点击下方开始」+ 引导操作 |
| **错误** | 说明问题 + 重试按钮 |
| 正常 | 内容 |

**「空状态」最容易被忘。** 新用户第一次打开看到的就是空状态，**这是你唯一的引导机会。**

```tsx
// 四个分支的顺序不能换：数据还在路上时 conversations 也是空数组，
// 先判空就会闪一下「还没有对话」，用户以为真的没内容
if (isLoading) return <Skeleton />;
if (error) return <ErrorState error={error} onRetry={retry} />;
if (conversations.length === 0) return <EmptyState onStartChat={startChat} />;
return <ConversationList items={conversations} />;
```

### 空状态怎么写

```tsx
function EmptyState({ onStartChat }: { onStartChat: () => void }) {
  return (
    <div className="flex flex-col items-center justify-center py-16 gap-4">
      <div className="text-4xl">💡</div>
      <div className="text-lg font-medium">还没有对话</div>
      {/* 这句示例输入是空状态里最值钱的一行：
          它同时告诉用户「能问什么」和「该问多具体」 */}
      <div className="text-sm text-gray-500 text-center max-w-xs">
        试试问它「帮我看看这周家电类目值得做的选题」
      </div>
      {/* 按钮直接发起第一个对话，别让用户回头自己找入口 */}
      <button onClick={onStartChat} className="px-4 py-2 bg-blue-600 text-white rounded">
        开始第一个对话
      </button>
    </div>
  );
}
```

**给一个具体的例子输入。** 用户不知道该说什么是最大的流失点。

## 步骤 5 · 性能

### 这一步在做什么

用工具找出明显的问题，修掉。不要过度优化。

### 跑 Lighthouse

Chrome 开发者工具 → Lighthouse 标签 → 选 Mobile → 分析。

**先看这三项**：

| 指标 | 含义 | 常见问题 |
|---|---|---|
| **LCP** 最大内容绘制 | 主要内容多久出现 | 图片太大、字体阻塞 |
| **CLS** 累积布局偏移 | 内容有没有跳动 | 图片没设尺寸、字体切换 |
| 首屏 JS 体积 | 要下载多少代码 | 引入了大库 |

### 三个最有效的优化

**一、图片**

用 Next.js 的 `<Image>` 组件，它自动做格式转换和尺寸优化：

```tsx
import Image from "next/image";
<Image src="/logo.png" width={200} height={50} alt="logo" />
```

**必须给 width 和 height**，否则会有布局偏移（CLS 变差）。

**二、字体**

```tsx
import { Noto_Sans_SC } from "next/font/google";
const font = Noto_Sans_SC({ subsets: ["latin"], display: "swap" });
```

`display: "swap"` 让文字先用系统字体显示，字体加载完再切换。**避免白屏。**

**中文字体很大**（几 MB），**能用系统字体就用系统字体**：

```css
font-family: system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
```

**三、减少客户端 JS**

回到 U5.3 的原则：**只把需要交互的部分标成 `'use client'`。**

用 `@next/bundle-analyzer` 看看哪个包最大，考虑替换或懒加载。

### 可能卡在哪

**Lighthouse 分数很低**

**别为了分数优化。** 看具体的问题项，只修那些真实影响体验的（LCP、CLS）。

**「Accessibility」项报一堆问题**

大多是缺 `alt`、缺 `label`、对比度不够。**这些值得修**，成本低，而且真的有用户需要。

## 步骤 6 · 落地页

### 这一步在做什么

**这一页是你作品集的门面。**

### 要回答的四个问题

**一、这是什么？** 一句话，不要绕。

**二、能解决什么问题？** 具体的场景，不是抽象的价值。

**三、怎么用？** 三步以内说清楚。

**四、看起来是什么样？** 一张截图或一段演示。

### 结构

```
┌──────────────────────────────────┐
│  产品名                            │
│  一句话描述                         │
│  [开始使用]                        │
│                                  │
│  （产品截图或演示动图）              │
├──────────────────────────────────┤
│  它能做什么                        │
│  · 具体场景 1                      │
│  · 具体场景 2                      │
│  · 具体场景 3                      │
├──────────────────────────────────┤
│  怎么用                            │
│  1. 描述你要什么                    │
│  2. 它会搜索和分析                  │
│  3. 拿到带数据支撑的结果             │
├──────────────────────────────────┤
│  [开始使用]                        │
└──────────────────────────────────┘
```

### 写文案的原则

**说具体的，不说抽象的**：

```
差：「AI 驱动的智能内容助手，提升你的创作效率」
好：「每周帮你看完 200 篇同类笔记，找出值得做的 5 个选题」
```

**第二种能让人立刻判断「这对我有没有用」。** 第一种是废话。

### 可能卡在哪

**不知道写什么**

**去看你的 `PROJECT.md`（U1.8 写的）里的「我为什么会用它」那一段。** 那段话就是最好的落地页文案素材，因为它写的是真实的场景和痛点。

**没有截图**

现在就录一段。用你自己的真实使用场景，跑一遍完整流程，截几张图或者录个 30 秒的动图。

### S5 复盘

在 `logs/` 里写：

1. 学前端最难的一关是什么？
2. Server Component 和 Client Component 的区分，你踩过哪些坑？
3. 三个用户的反馈里，哪一条最出乎意料？
4. 做完界面之后，你对自己 Agent 的哪个设计不满意了？

**第 4 个问题很关键。** 做界面会暴露后端设计的问题——比如「这个数据前端拿不到」「这个状态没法展示」。**这些发现要记下来。**
