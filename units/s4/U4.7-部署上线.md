# U4.7 · 部署上线（12 小时）

**这个单元解决什么问题**

把跑在你笔记本上的东西，变成一个别人打开链接就能用的服务。

**学完你能做到**：一个真实可访问的地址；你故意搞挂它时，手机在两分钟内收到告警。

---

## 步骤 1 · 选平台

### 这一步在做什么

根据你的实际情况选一个，不要纠结。

### 选项

| 平台 | 适合 | 注意 |
|---|---|---|
| **阿里云函数计算 / 腾讯云 SCF** | 国内用户、长任务、按量付费 | 冷启动、单次执行时长上限 |
| **一台轻量云服务器** | 最简单、最可控 | 要自己管运维、监控 |
| **Fly.io / Railway / Render** | 海外、体验好 | 国内访问慢 |
| **Vercel** | 只适合前端和短请求 | **不适合你的长任务后端** |

### 建议

**如果你在国内且用户也在国内**：先用一台 2核4G 的轻量服务器，最简单直接。等有真实流量了再考虑弹性方案。

**长任务的特殊考虑**：函数计算类平台通常有单次执行时长上限。有些平台支持很长的异步执行（阿里云的 AgentRun 基于函数计算的异步调用，支持长时任务和 SSE 流式推送、状态持久化），如果你的任务确实很长，值得研究一下。

**但对你现在的规模，一台服务器 + U4.3 的异步架构就够了。**

### 可能卡在哪

**不知道选哪个**

**选一个，跑通，别纠结。** 换平台的成本主要在于「你的应用有没有和平台绑定」——如果你用的是标准 Docker 镜像加环境变量，换平台是一两个小时的事。

**这也是为什么 U0.9 要学 Docker。**

## 步骤 2 · 生产配置

### 这一步在做什么

生产环境和开发环境的差异要处理掉。

### 必须处理的差异

| 项 | 开发 | 生产 |
|---|---|---|
| 密钥 | `.env` 文件 | **平台的密钥服务** |
| 数据库 | 本地 Docker | **云托管的 Postgres** |
| 日志 | 终端 | **结构化 JSON，输出到日志服务** |
| 调试信息 | 详细 | **关掉，不返回堆栈给用户** |
| CORS | 全放开 | **只允许你的前端域名** |
| 并发 | 1 个 worker | 按 CPU 核数 |

### 密钥管理

**不要用 `.env` 文件部署到生产。** 用平台的密钥服务或环境变量注入。

代码不用改（U0.5 学的 `os.getenv` 两种都能读）。

**做一次密钥轮换演练**：

1. 在提供方控制台生成新密钥
2. 在平台更新环境变量
3. 重启服务
4. 确认可用
5. 作废旧密钥

**记录耗时。** 真的出泄露时，这个流程要能在 10 分钟内走完。

### 结构化日志

```python
import logging, json, sys

class JSON格式化(logging.Formatter):
    def format(self, record):
        数据 = {
            "时间": self.formatTime(record),
            "级别": record.levelname,
            "模块": record.name,
            "消息": record.getMessage(),
        }
        # 关键：带上 trace_id
        if hasattr(record, "trace_id"):
            数据["trace_id"] = record.trace_id
        if record.exc_info:
            数据["异常"] = self.formatException(record.exc_info)
        return json.dumps(数据, ensure_ascii=False)
```

**每条日志带 trace_id**，这样能和 U3.5 的 trace 对上。**排查时这个关联非常关键。**

### 不要把内部错误返回给用户

```python
@app.exception_handler(Exception)
async def 兜底(request, exc):
    错误id = 生成id()
    logger.exception("未处理异常 error_id=%s", 错误id)
    return JSONResponse(
        status_code=500,
        content={"错误": "服务暂时不可用", "错误id": 错误id},
    )
```

**返回一个错误 id 让用户报给你**，而不是返回堆栈（堆栈会泄露内部结构，是安全问题）。

## 步骤 3 · 健康检查

### 这一步在做什么

让平台知道你的服务是不是活着、能不能接流量。

### 两个不同的端点

```python
@app.get("/health")
async def 存活():
    """进程还活着吗。不检查依赖。"""
    return {"status": "ok"}


@app.get("/ready")
async def 就绪():
    """能接流量吗。检查所有依赖。"""
    检查 = {}
    健康 = True

    try:
        await db.execute(text("SELECT 1"))
        检查["数据库"] = "ok"
    except Exception as e:
        检查["数据库"] = f"失败: {e}"
        健康 = False

    try:
        await 模型健康检查()          # 一个极短的调用
        检查["模型api"] = "ok"
    except Exception as e:
        检查["模型api"] = f"失败: {e}"
        健康 = False

    return JSONResponse(
        status_code=200 if 健康 else 503,
        content={"ready": 健康, "检查": 检查},
    )
```

### 为什么要分开

| 端点 | 失败时平台该做什么 |
|---|---|
| `/health` 失败 | **重启容器**（进程有问题） |
| `/ready` 失败 | **停止发流量，但不重启**（依赖有问题，重启没用） |

**混在一起的后果**：数据库挂了，`/health` 返回失败，平台不停地重启你的容器——**但重启解决不了数据库的问题，只会让日志更乱。**

### 可能卡在哪

**`/ready` 检查模型 API 太慢/太贵**

用缓存：每 30 秒真检查一次，中间返回缓存的结果。

**或者干脆不检查模型 API**，只检查数据库。模型 API 挂了应该走降级（U4.5 的 fallback 链），而不是让整个服务不可用。

## 步骤 4 · 告警

### 这一步在做什么

**出事时你要知道，而不是等用户告诉你。**

### 从三条开始

**告警太多等于没有告警。** 先设最重要的三条，跑一个月，再考虑加。

| 告警 | 条件 | 严重度 |
|---|---|---|
| 服务不可用 | `/ready` 连续 3 次失败 | **P0，立刻处理** |
| 错误率飙升 | 5 分钟内错误率 > 20% | **P1，尽快处理** |
| 日成本超限 | 今日成本 > 预算 | P2，当天处理 |

### 发到手机

**飞书机器人是最简单的方式**（你已经在用飞书）：

```python
import httpx

async def 发告警(标题: str, 内容: str, 严重度: str = "P1"):
    图标 = {"P0": "🔴", "P1": "🟠", "P2": "🟡"}[严重度]
    await httpx.AsyncClient().post(
        os.getenv("飞书告警WEBHOOK"),
        json={
            "msg_type": "text",
            "content": {"text": f"{图标} [{严重度}] {标题}\n\n{内容}"},
        },
    )
```

**在飞书里创建一个群，加一个自定义机器人，拿到 webhook 地址。**

**手机上把这个群设成强提醒**，否则 P0 告警你也看不到。

### 告警必须可行动

```
差：「错误率高」
好：「错误率 34%（阈值 20%），持续 8 分钟。
     主要错误：模型 API 429 限流（占 89%）。
     建议：检查是否被限流，考虑切换到 fallback 模型。
     Trace 示例：http://.../trace/abc123」
```

**每条告警要回答：什么坏了、坏了多久、可能的原因、我该做什么、去哪看细节。**

### 告警抑制

同一个问题不要反复告警：

```python
async def 发告警_带抑制(key: str, 标题, 内容, 严重度, 抑制秒: int = 1800):
    上次 = await redis.get(f"alert:{key}")
    if 上次:
        return
    await redis.setex(f"alert:{key}", 抑制秒, "1")
    await 发告警(标题, 内容, 严重度)
```

**没有抑制的话，一个持续的问题会在半小时里发 200 条消息，然后你会静音这个群。**

## 步骤 5 · 部署流程

### 这一步在做什么

把「部署」变成一个可重复、可回滚的流程。

### 完整流程

```
1. 提 PR
2. CI 跑测试 + 评估（U3.7）
3. 通过 → 合并到 main
4. CI 构建镜像，打上 git sha 的 tag
5. 推到镜像仓库
6. 跑数据库迁移（如果有）
7. 部署新镜像
8. 等健康检查通过
9. 灰度分流（U4.6）
10. 观察指标
11. 逐步放量到 100%
```

### 数据库迁移的顺序

**必须在部署新代码之前跑迁移**（U0.8 学的 Alembic）。

**而且迁移必须向后兼容**：新加的字段要允许为空或有默认值，这样旧代码也能跑。

**为什么**：灰度期间新旧代码同时在跑，数据库结构必须两边都能用。

**不兼容的变更要分两步**：

```
第 1 次发布：加新字段（允许为空），新代码同时写新旧字段
第 2 次发布：只用新字段
第 3 次发布：删旧字段
```

### 用 GitHub Actions 自动化

```yaml
name: 部署

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: 构建镜像
        run: |
          docker build -t $镜像仓库/agent:${{ github.sha }} .
          docker tag $镜像仓库/agent:${{ github.sha }} $镜像仓库/agent:latest

      - name: 推送
        run: docker push $镜像仓库/agent:${{ github.sha }}

      - name: 跑迁移
        run: |
          docker run --rm -e DATABASE_URL=$生产库 \
            $镜像仓库/agent:${{ github.sha }} \
            uv run alembic upgrade head

      - name: 部署
        run: |
          # 具体命令看你的平台
          ...

      - name: 等健康检查
        run: |
          for i in $(seq 1 30); do
            if curl -sf $线上地址/ready; then exit 0; fi
            sleep 5
          done
          echo "健康检查超时"; exit 1
```

**每个 commit 一个镜像 tag**，回滚就是部署上一个 tag。

### 可能卡在哪

**部署后服务起不来**

看日志。常见原因：环境变量缺失、数据库连不上、端口配置错。

**先在本地用生产配置跑一次**（`docker run` 加上和生产一样的环境变量），能排除大部分问题。

**迁移失败了怎么办**

**部署前先备份数据库。** 迁移失败就恢复备份，不要在生产上手工改数据。

Alembic 支持 `downgrade`，但复杂迁移的回滚可能有数据丢失。**能不改就不改，要改就先在测试库演练。**

## 步骤 6 · 域名与访问

### 这一步在做什么

让别人能打开。

### 要做的

1. **买个域名**，解析到你的服务
2. **配 HTTPS**（Let's Encrypt 免费，或者用平台自带的）
3. **国内服务器需要 ICP 备案**（如果域名指向国内服务器）
4. **配 CORS**，只允许你的前端域名

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[os.getenv("前端域名")],      # 不要用 ["*"]
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
)
```

### 可能卡在哪

**备案要等很久**

国内备案通常要一到两周。**如果只是练手，可以先用 IP 加端口访问，或者用海外服务器。**

**不想买域名**

很多平台提供免费的二级域名（`your-app.fly.dev` 之类）。够用。
