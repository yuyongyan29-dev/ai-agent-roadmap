# U4.7 · 部署上线（10 小时）

**这个单元解决什么问题**

把跑在你笔记本上的东西，变成一个别人打开链接就能用的服务。

**学完你能做到**：一个真实可访问的地址；你故意搞挂它时，手机在两分钟内收到告警。

**前置**：U4.9 做完。镜像仓库、HTTPS、数据库备份、对象存储都在那里，这个单元只讲应用本身的生产配置和发布流程。

---

## 步骤 1 · 选平台

### 这一步在做什么

根据你的实际情况选一个，不要纠结。

### 选项

| 平台 | 适合 | 注意 |
|---|---|---|
| **阿里云函数计算 / 腾讯云 SCF** | 国内用户、长任务、按量付费 | 冷启动、单次执行时长上限 |
| **一台轻量云服务器** | 最简单、最可控 | 要自己管运维、监控 |
| **Fly.io / Railway / Render** | 海外、体验好 | 国内访问慢 |
| **Vercel / Cloudflare Workers** | 只适合前端和短请求 | 都有执行时长或 CPU 限制，**不适合你的长任务后端**；Cloudflare 国内访问还不稳定 |

**后端如果是 Node 而不是 Python**：选项一样。打成镜像走同一条流水线，或者放到函数平台上。`pm2` 只在不用容器、直接在机器上跑进程时才需要，本计划不用。各层还有什么可选见[选型地图](../../docs/选型地图.md)。

### 建议

**如果你在国内且用户也在国内**：先用一台 2核4G 的轻量服务器，最简单直接。等有真实流量了再考虑弹性方案。

**长任务的特殊考虑**：函数计算类平台通常有单次执行时长上限。有些平台支持很长的异步执行（阿里云的 AgentRun 基于函数计算的异步调用，支持长时任务和 SSE 流式推送、状态持久化），如果你的任务确实很长，值得研究一下。

**但对你现在的规模，一台服务器 + U4.3 的异步架构就够了。**

### 可能卡在哪

**不知道选哪个**

**选一个，跑通，别纠结。** 换平台的成本主要在于「你的应用有没有和平台绑定」——如果你用的是标准 Docker 镜像加环境变量，换平台是一两个小时的事。

**这也是为什么 U0.9 要学 Docker。**

## 步骤 2 · 生产配置

### 这一步在做什么

生产环境和开发环境的差异要处理掉。

### 必须处理的差异

| 项 | 开发 | 生产 |
|---|---|---|
| 密钥 | `.env` 文件 | **平台的密钥服务** |
| 数据库 | 本地 Docker | **云托管的 Postgres** |
| 日志 | 终端 | **结构化 JSON，输出到日志服务** |
| 调试信息 | 详细 | **关掉，不返回堆栈给用户** |
| CORS | 全放开 | **只允许你的前端域名** |
| 并发 | 1 个 worker | 按 CPU 核数 |

### 密钥管理

**不要用 `.env` 文件部署到生产。** 用平台的密钥服务或环境变量注入。

代码不用改（U0.5 学的 `os.getenv` 两种都能读）。

**做一次密钥轮换演练**：

1. 在提供方控制台生成新密钥
2. 在平台更新环境变量
3. 重启服务
4. 确认可用
5. 作废旧密钥

**记录耗时。** 真的出泄露时，这个流程要能在 10 分钟内走完。

### 结构化日志

```python
import logging, json, sys

class JsonFormatter(logging.Formatter):
    """把每条日志渲染成一行 JSON。日志服务能直接按字段检索，
    而不是拿正则去切一行自由文本。"""

    def format(self, record):
        payload = {
            "time": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
        }
        # 关键：带上 trace_id。有它才能把这条日志和 U3.5 的完整链路对上
        if hasattr(record, "trace_id"):
            payload["trace_id"] = record.trace_id
        # 异常单独成字段，不要拼进 message，否则堆栈会把这行日志撑爆且没法过滤
        if record.exc_info:
            payload["exception"] = self.formatException(record.exc_info)
        # ensure_ascii=False：中文日志直接可读，不要变成 \uXXXX
        return json.dumps(payload, ensure_ascii=False)
```

**每条日志带 trace_id**，这样能和 U3.5 的 trace 对上。**排查时这个关联非常关键。**

### 不要把内部错误返回给用户

```python
@app.exception_handler(Exception)
async def handle_unexpected_error(request, exc):
    # 先生成一个随机 id，日志和响应用同一个值——用户报这个 id，你就能定位到那条日志
    error_id = generate_id()
    # logger.exception 会把完整堆栈写进日志（只给你看），响应里不带
    logger.exception("未处理异常 error_id=%s", error_id)
    return JSONResponse(
        status_code=500,
        content={"error": "服务暂时不可用", "error_id": error_id},
    )
```

**返回一个错误 id 让用户报给你**，而不是返回堆栈（堆栈会泄露内部结构，是安全问题）。

## 步骤 3 · 健康检查

### 这一步在做什么

让平台知道你的服务是不是活着、能不能接流量。

### 两个不同的端点

```python
@app.get("/health")
async def liveness():
    """进程还活着吗。不检查依赖——依赖挂了重启进程也没用，见下面的对照表。"""
    return {"status": "ok"}


@app.get("/ready")
async def readiness():
    """能接流量吗。检查所有依赖。"""
    checks = {}
    healthy = True

    # 每个依赖单独 try：一个挂了也要把其余的结果填完，
    # 否则你只能看到第一个失败项，排查时还得再试一次
    try:
        await db.execute(text("SELECT 1"))
        checks["database"] = "ok"
    except Exception as e:
        checks["database"] = f"失败: {e}"
        healthy = False

    try:
        await check_model_api()       # 一个极短的调用，别在探针里烧 token
        checks["model_api"] = "ok"
    except Exception as e:
        checks["model_api"] = f"失败: {e}"
        healthy = False

    # 状态码要真的反映健康与否：平台只看状态码决定发不发流量，不会读 body
    return JSONResponse(
        status_code=200 if healthy else 503,
        content={"ready": healthy, "checks": checks},
    )
```

### 为什么要分开

| 端点 | 失败时平台该做什么 |
|---|---|
| `/health` 失败 | **重启容器**（进程有问题） |
| `/ready` 失败 | **停止发流量，但不重启**（依赖有问题，重启没用） |

**混在一起的后果**：数据库挂了，`/health` 返回失败，平台不停地重启你的容器——**但重启解决不了数据库的问题，只会让日志更乱。**

### 可能卡在哪

**`/ready` 检查模型 API 太慢/太贵**

用缓存：每 30 秒真检查一次，中间返回缓存的结果。

**或者干脆不检查模型 API**，只检查数据库。模型 API 挂了应该走降级（U4.5 的 fallback 链），而不是让整个服务不可用。

## 步骤 4 · 告警

### 这一步在做什么

**出事时你要知道，而不是等用户告诉你。**

### 从三条开始

**告警太多等于没有告警。** 先设最重要的三条，跑一个月，再考虑加。

| 告警 | 条件 | 严重度 |
|---|---|---|
| 服务不可用 | `/ready` 连续 3 次失败 | **P0，立刻处理** |
| 错误率飙升 | 5 分钟内错误率 > 20% | **P1，尽快处理** |
| 日成本超限 | 今日成本 > 预算 | P2，当天处理 |

### 发到手机

**飞书机器人是最简单的方式**（你已经在用飞书）：

```python
import httpx

async def send_alert(title: str, body: str, severity: str = "P1"):
    # 用 emoji 打头，手机通知栏折叠成一行时也能一眼分出严重度
    icon = {"P0": "🔴", "P1": "🟠", "P2": "🟡"}[severity]
    # webhook 地址等于告警通道的密码，只能从环境变量读，不要写进代码
    await httpx.AsyncClient().post(
        os.getenv("FEISHU_ALERT_WEBHOOK"),
        json={
            "msg_type": "text",
            "content": {"text": f"{icon} [{severity}] {title}\n\n{body}"},
        },
    )
```

**在飞书里创建一个群，加一个自定义机器人，拿到 webhook 地址。**

**手机上把这个群设成强提醒**，否则 P0 告警你也看不到。

### 告警必须可行动

```
差：「错误率高」
好：「错误率 34%（阈值 20%），持续 8 分钟。
     主要错误：模型 API 429 限流（占 89%）。
     建议：检查是否被限流，考虑切换到 fallback 模型。
     Trace 示例：http://.../trace/abc123」
```

**每条告警要回答：什么坏了、坏了多久、可能的原因、我该做什么、去哪看细节。**

### 告警抑制

同一个问题不要反复告警：

```python
async def send_alert_throttled(key: str, title, body, severity, cooldown_seconds: int = 1800):
    """key 标识「同一个问题」（比如 db_down），同一个 key 在冷却期内只发一次。"""
    # 冷却标记存在 Redis 而不是进程内存：多个 worker / 重启后仍然算同一次告警
    if await redis.get(f"alert:{key}"):
        return
    # 先打标记再发送：反过来的话两个并发请求会都读到空值，同时发出两条
    await redis.setex(f"alert:{key}", cooldown_seconds, "1")
    await send_alert(title, body, severity)
```

**没有抑制的话，一个持续的问题会在半小时里发 200 条消息，然后你会静音这个群。**

## 步骤 5 · 部署流程

### 这一步在做什么

把「部署」变成一个可重复、可回滚的流程。

### 完整流程

```
1. 提 PR
2. CI 跑测试 + 评估（U3.7）
3. 通过 → 合并到 main
4. CI 构建镜像，打上 git sha 的 tag
5. 推到镜像仓库
6. 跑数据库迁移（如果有）
7. 部署新镜像
8. 等健康检查通过
9. 灰度分流（U4.6）
10. 观察指标
11. 逐步放量到 100%
```

### 数据库迁移的顺序

**必须在部署新代码之前跑迁移**（U0.8 学的 Alembic）。

**而且迁移必须向后兼容**：新加的字段要允许为空或有默认值，这样旧代码也能跑。

**为什么**：灰度期间新旧代码同时在跑，数据库结构必须两边都能用。

**不兼容的变更要分两步**：

```
第 1 次发布：加新字段（允许为空），新代码同时写新旧字段
第 2 次发布：只用新字段
第 3 次发布：删旧字段
```

### 用 GitHub Actions 自动化

```yaml
name: 部署

on:
  push:
    branches: [main]      # 只有合并进 main 才部署，PR 阶段只跑测试

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: 构建镜像
        run: |
          # 用 commit sha 当 tag：每个版本都有唯一且不可变的镜像，回滚就是部署上一个 sha
          docker build -t $REGISTRY/agent:${{ github.sha }} .
          docker tag $REGISTRY/agent:${{ github.sha }} $REGISTRY/agent:latest

      - name: 推送
        run: docker push $REGISTRY/agent:${{ github.sha }}

      - name: 跑迁移
        run: |
          # 迁移必须在部署新代码之前跑，而且用的就是这次要部署的那个镜像，
          # 保证迁移脚本和代码版本一致
          docker run --rm -e DATABASE_URL=$PROD_DATABASE_URL \
            $REGISTRY/agent:${{ github.sha }} \
            uv run alembic upgrade head

      - name: 部署
        run: |
          # 一台服务器 + Docker 的版本见 U4.9 步骤 7：ssh 到服务器，compose pull 再 up -d。
          # Serverless 容器平台就是它们各自的 CLI 一条命令，逻辑相同：换镜像 tag，等健康检查。
          ssh -o StrictHostKeyChecking=accept-new deploy@$DEPLOY_HOST \
            "cd /opt/agent && docker compose pull api && docker compose up -d api"

      - name: 等健康检查
        run: |
          # 轮询最多 30 次（约 2.5 分钟）；curl -sf 在非 2xx 时返回非零，所以能直接当判断条件。
          # 没有这一步的话，即使新版本起不来 CI 也是绿的，你要等用户来告诉你
          for i in $(seq 1 30); do
            if curl -sf $PROD_URL/ready; then exit 0; fi
            sleep 5
          done
          # 超时就让这次部署显式失败，触发告警
          echo "健康检查超时"; exit 1
```

**每个 commit 一个镜像 tag**，回滚就是部署上一个 tag。

### 可能卡在哪

**部署后服务起不来**

看日志。常见原因：环境变量缺失、数据库连不上、端口配置错。

**先在本地用生产配置跑一次**（`docker run` 加上和生产一样的环境变量），能排除大部分问题。

**迁移失败了怎么办**

**部署前先备份数据库。** 迁移失败就恢复备份，不要在生产上手工改数据。

Alembic 支持 `downgrade`，但复杂迁移的回滚可能有数据丢失。**能不改就不改，要改就先在测试库演练。**

## 步骤 6 · 域名与访问

### 这一步在做什么

让别人能打开。

### 要做的

1. **买个域名**，解析到你的服务
2. **配 HTTPS**：一台服务器的做法是 U4.9 步骤 2 的 Caddy，已经自动签好了；托管平台用它自带的
3. **国内服务器需要 ICP 备案**（如果域名指向国内服务器）
4. **配 CORS**，只允许你的前端域名

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    # 白名单只放自己的前端域名。allow_credentials=True 时用 ["*"] 浏览器会直接拒绝，
    # 而且等于允许任何网站带着用户的 cookie 调你的接口
    allow_origins=[os.getenv("FRONTEND_ORIGIN")],
    allow_credentials=True,
    # 只开实际用到的方法，别习惯性写 ["*"]
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
)
```

### 可能卡在哪

**备案要等很久**

国内备案通常要一到两周。**如果只是练手，可以先用 IP 加端口访问，或者用海外服务器。**

**不想买域名**

很多平台提供免费的二级域名（`your-app.fly.dev` 之类）。够用。
