### 背后的逻辑

Python 是**解释型语言**。你写的 `.py` 文件不需要先编译成可执行程序，而是由一个叫「解释器」的程序（就是 `python3` 这个命令）逐行读取并执行。

这带来两个后果，你后面会反复感受到：

- **好处**：改完立刻能跑，不用等编译
- **代价**：错误往往要跑到那一行才暴露。你在第 50 行写错了变量名，前 49 行照样执行，跑到第 50 行才崩

这就是为什么 Python 项目特别依赖测试和类型检查——它们把「跑到才发现」提前到「写的时候就发现」。U0.4 学类型注解、U0.7 学测试，都是在补这个短板。

### 怎么做

新建 `step1.py`，敲这些：

```python
# 变量：不用先声明类型，赋什么值就是什么类型，Python 自己推断
name = "小王"
age = 28
height = 1.75
is_student = False

```

跑 `python3 step1.py`，你应该看到：

```

```

**`type()` 是你的朋友。** 后面调试时「这个变量到底是什么类型」是最高频的疑问，直接打出来看。

**函数：把一段逻辑打包，起个名字。** 继续往 `step1.py` 里加：

```python
# 把「拼一句问候语」的逻辑打包起来，换个人名就能重复用
def greet(name):
    return f"你好，{name}"


print(greet("小王"))
print(greet("小李"))
```

你应该看到：

```

你好，小李
```

拆开看这个函数：

| 部分 | 含义 |
|---|---|
| `def` | 定义函数的关键字（define） |
| `greet` | 函数名 |
| `(name)` | 参数，调用时传进来的数据 |
| `:` | 冒号，表示「下面是函数体」 |
| 缩进的那些行 | 函数体，函数被调用时执行的内容 |
| `return` | 把结果交回去 |

**标识符一律用英文，注释和文档用中文。** 这是真实项目和招聘要求的通行做法，从第一行代码就按这个习惯写。

### f-string：你后面天天用的东西

```python
name = "小王"
count = 3
price = 3.14159

print(f"{name}有{count}条消息")      # 小王有3条消息
print(f"{count * 2}")               # 6，花括号里可以放表达式
print(f"{price:.2f}")               # 3.14，冒号后面是格式说明
print(f"{count:>5}")                # "    3"，右对齐占 5 格
```

跑一遍，四行输出对上再往下。

**为什么强调它**：到 S1 你写 prompt 的时候，几乎每一个 prompt 都是 f-string 拼出来的。现在把它练熟。

### 练习 1

新建 `ex1.py`，写一个函数 `describe_order`，接收三个参数：订单号、分类、金额，返回一句话。

**验收标准**：下面这段调用

```python
print(describe_order(1001, "家电", 1200))
print(describe_order(1002, "家居", 300.5))
```

**必须**输出：

```

订单 1002 属于家居，金额 300.50 元
```

注意金额固定两位小数，`1200` 要变成 `1200.00`。

#### 参考答案（先自己写完再看）

```python
def describe_order(order_id, category, amount):
    """把一条订单拼成人能读的一句话。amount 统一格式化成两位小数。"""
    return f"订单 {order_id} 属于{category}，金额 {amount:.2f} 元"


print(describe_order(1001, "家电", 1200))
print(describe_order(1002, "家居", 300.5))
```

### 可能卡在哪

**`IndentationError: expected an indented block`**

**这是 Python 新手第一大坑。** Python 用缩进表示代码块的从属关系，不像别的语言用花括号。

```python
def f():
print("错")        # 报错：函数体必须缩进
```

```python
def f():
    print("对")    # 缩进 4 个空格
```

**规则**：同一个块里的所有行，缩进必须完全一致。**统一用 4 个空格，不要用 Tab。** VS Code 默认按 Tab 会插入 4 个空格，符合规范。

**`TabError: inconsistent use of tabs and spaces`**

同一个文件里混用了 Tab 和空格。VS Code 里 `Cmd+Shift+P` → 搜 `Convert Indentation to Spaces`。

**`NameError: name 'xxx' is not defined`**

变量名打错了，或者用了一个还没赋值的变量。检查拼写和大小写——**Python 严格区分大小写**，`Name` 和 `name` 是两个变量。

**函数写了但没反应**

定义函数只是「教电脑怎么做」，你还要调用它才会执行：

```python
def f():
    print("hi")

f()        # 少了这行，什么都不会发生
```

### 背后的逻辑

**为什么 Python 用缩进而不用花括号？**

设计者的理由是：不管什么语言，好代码本来就会缩进，那不如让缩进直接成为语法。这样「代码看起来的结构」和「代码实际的结构」永远一致，杜绝了「缩进骗了你」那类 bug。

代价是你必须严格对齐。但这也强迫你写出结构清晰的代码。

**`return` 和 `print` 的区别**

新手最常搞混的一对。建一个 `compare.py` 亲自跑一次：

```python
def a():
    print(1)      # 打印 1，但不交还任何东西

def b():
    return 1      # 交还 1，但不打印


x = a()           # 屏幕显示 1，但 x 是 None
y = b()           # 屏幕什么都不显示，但 y 是 1

print("x =", x)
print("y =", y)
```

输出：

```
1
x = None
y = 1
```

- `print` 是**显示给人看**，程序拿不到这个值
- `return` 是**把值交回给调用者**，程序可以继续用

**函数默认返回 `None`**，也就是「什么都没有」。你以后会遇到「我函数明明算出来了，怎么拿到的是 None」——九成是忘了写 `return`。

## 步骤 2 · 条件判断（0.5 小时）

### 这一步在做什么

让程序能分情况处理，而不是从头到尾一条道跑到黑。

### 怎么做

新建 `step2.py`：

```python
def grade_amount(amount):
    """按金额分档。分支从上往下逐条判断，命中一条就跳过其余的，
    所以条件必须从严到宽排：先判 3000，再判 1000。"""
    if amount >= 3000:
        return "大额"
    elif amount >= 1000:
        return "中额"
    else:
        return "小额"


for amount in [5000, 3000, 1200, 999, 300]:
    print(amount, "→", grade_amount(amount))
```

你应该看到：

```
5000 → 大额
3000 → 大额
1200 → 中额
999 → 小额
300 → 小额
```

**动手改一下**：把 `if amount >= 3000` 和 `elif amount >= 1000` 两行对调，再跑一次。你会看到所有大于 1000 的都变成「中额」——**因为 `elif` 命中一条就不再往下判**。亲手撞一次这个，比读十遍规则管用。

比较运算符：`==`（等于）、`!=`（不等于）、`>`、`<`、`>=`、`<=`
逻辑运算符：`and`、`or`、`not`

### 练习 2

新建 `ex2.py`，写函数 `classify(category, amount)`，规则：

- 分类是「数码」**且**金额 ≥ 3000 → 返回 `"重点订单"`
- 金额 ≥ 3000（但不是数码）→ 返回 `"大额订单"`
- 金额 < 300 → 返回 `"小额订单"`
- 其他 → 返回 `"普通订单"`

**验收标准**：

```python
print(classify("数码", 5000))    # 重点订单
print(classify("家电", 3000))    # 大额订单
print(classify("家居", 250))     # 小额订单
print(classify("家居", 450))     # 普通订单
print(classify("数码", 2000))    # 普通订单
```

五行必须全部对上。**第五行是这道题的考点**——「数码」但金额不够，不能命中第一条。

#### 参考答案（先自己写完再看）

```python
def classify(category, amount):
    """订单分级。两个条件要同时满足才算重点订单，所以用 and 连起来。"""
    if category == "数码" and amount >= 3000:
        return "重点订单"
    elif amount >= 3000:
        return "大额订单"
    elif amount < 300:
        return "小额订单"
    else:
        return "普通订单"
```

### 可能卡在哪

**`=` 和 `==` 搞混**

- `=` 是**赋值**：`x = 5` 意思是「把 5 存进 x」
- `==` 是**比较**：`x == 5` 意思是「x 等于 5 吗」

写 `if x = 5:` 会直接报 `SyntaxError`。

**`is` 和 `==` 搞混**

在交互式里跑一次：

```python
>>> a = [1, 2]
>>> b = [1, 2]
>>> a == b
True
>>> a is b
False
```

- `==` 比较**值相不相等**
- `is` 比较**是不是同一个对象**

**规则**：比较值永远用 `==`。`is` 只用在跟 `None`、`True`、`False` 比较时（`if x is None:`）。

**缩进层级搞乱了**

```python
if a:
    if b:
        print("both")
    print("只有 a")      # 这行属于外层 if
print("总是执行")         # 这行不属于任何 if
```

看不清的时候，VS Code 代码左侧有竖线标出缩进层级。

### 背后的逻辑

**什么东西算「真」？**

`if` 后面不一定要是比较表达式，任何值都可以。规则是：

| 算「假」的 | 其他一切都算「真」 |
|---|---|
| `False`、`None` | 非零数字 |
| `0`、`0.0` | 非空字符串 |
| `""`（空字符串） | 非空容器 |
| `[]`、`{}`、`()`（空容器） |  |

所以你会看到这种写法：

```python
members = []
if members:               # 空列表本身就算「假」，等价于 if len(members) > 0
    print("有人")
else:
    print("空的")
```

**这是 Python 的惯用写法**，比 `if len(members) > 0` 更地道，你读别人代码时会大量遇到。

## 步骤 3 · 循环与列表推导式（1 小时）

### 这一步在做什么

处理「一堆」数据，而不是一个一个手写。

### 怎么做

新建 `step3.py`：

```python
# 遍历一个序列：循环变量每轮自动指向下一个元素
for fruit in ["苹果", "香蕉", "橙子"]:
    print(fruit)

print("---")

# 重复 N 次：不关心元素本身，只借 range 数次数
for i in range(5):        # i 依次是 0,1,2,3,4
    print(i)

print("---")

# 条件为真就一直循环，次数事先不确定时用它
count = 0
while count < 3:
    print(count)
    count += 1            # 必须在循环里改变条件变量，否则死循环
```

输出应该是三个水果、0 到 4、0 到 2。

**同时拿到序号和元素，用 `enumerate`：**

```python
for index, fruit in enumerate(["苹果", "香蕉", "橙子"], start=1):
    print(index, fruit)
```

```
1 苹果
2 香蕉
3 橙子
```

**这个写法后面处理 CSV 行号时会用到**——报错时能说出「第几行坏了」，靠的就是它。

**控制循环：**

```python
for i in range(10):
    if i == 3:
        continue      # 跳过这一轮，进下一轮
    if i == 6:
        break         # 直接跳出整个循环
    print(i)
```

输出 `0 1 2 4 5`。自己想清楚为什么没有 3、也没有 6 到 9。

### 列表推导式

```python
numbers = [1, 2, 3, 4, 5]

# 普通写法：先建空列表，再一个个塞进去
doubled = []
for x in numbers:
    doubled.append(x * 2)
print(doubled)

# 列表推导式，一行搞定，和上面完全等价
doubled = [x * 2 for x in numbers]
print(doubled)

# 带过滤：末尾的 if 决定哪些元素进新列表
even_doubled = [x * 2 for x in numbers if x % 2 == 0]
print(even_doubled)
```

```
[2, 4, 6, 8, 10]
[2, 4, 6, 8, 10]
[4, 8]
```

**这个写法你在任何 Python 代码里都会见到，必须能读能写。** 读法是从中间往两边：先看 `for x in numbers`（对每个 x），再看末尾的 `if`（挑出哪些），最后看开头的 `x * 2`（每个变成什么）。

### 练习 3

新建 `ex3.py`。给定：

```python
amounts = [1200, 300, 3000, 800, 450, 5000, 200, 1500]
```

用**列表推导式**（不许用 for 循环加 append）完成三件事：

1. `big` = 所有 ≥ 1000 的金额
2. `discounted` = 所有金额打九折，保留原顺序
3. `big_labels` = 所有 ≥ 1000 的金额，格式化成 `"1200 元"` 这样的字符串

**验收标准**：

```
[1200, 3000, 5000, 1500]
[1080.0, 270.0, 2700.0, 720.0, 405.0, 4500.0, 180.0, 1350.0]
['1200 元', '3000 元', '5000 元', '1500 元']
```

#### 参考答案（先自己写完再看）

```python
amounts = [1200, 300, 3000, 800, 450, 5000, 200, 1500]

# 只过滤，不变形：开头直接写 x
big = [x for x in amounts if x >= 1000]

# 只变形，不过滤：没有末尾的 if
discounted = [x * 0.9 for x in amounts]

# 既过滤又变形：末尾 if 挑，开头 f-string 变
big_labels = [f"{x} 元" for x in amounts if x >= 1000]

print(big)
print(discounted)
print(big_labels)
```

### 可能卡在哪

**`while` 循环停不下来**

条件永远为真，程序卡死。按 `Ctrl+C` 强制停止。常见原因是忘了在循环里改变条件相关的变量：

```python
i = 0
while i < 3:
    print(i)      # 忘了 i += 1，永远循环
```

**`range(5)` 为什么是 0 到 4，不含 5**

Python 的区间约定是「含头不含尾」。`range(5)` 有 5 个元素，从 0 开始，所以是 0-4。切片也一样：`列表[1:3]` 取第 1、2 个，不含第 3 个。

**好处**：`range(a, b)` 的元素个数正好是 `b - a`，且 `range(0,3)` 和 `range(3,5)` 拼起来正好是 `range(0,5)`，不重叠也不漏。

**在循环里修改正在遍历的列表**

```python
numbers = [2, 4, 6, 8]
for x in numbers:
    if x % 2 == 0:
        numbers.remove(x)   # 边遍历边删，结果会不对
print(numbers)              # [4, 8]，全是偶数却只删掉了两个
```

四个数全是偶数，本该删光，结果剩下两个。**原因是删除会让后面的元素前移，而遍历的下标照样往前走，于是每删一个就跳过一个。**

**正确做法是造一个新列表**：

```python
numbers = [x for x in [2, 4, 6, 8] if x % 2 != 0]
print(numbers)              # []，这才对
```

亲自跑一次上面那段看到 `[4, 8]`，这个坑就记住了。**它的可怕之处在于不报错**——程序照常跑完，结果是错的，你可能几个月后才发现。

### 背后的逻辑

**`for x in 序列` 底层在做什么？**

Python 的 for 循环不是「计数循环」，而是「迭代器循环」。它做的事是：

1. 向对象要一个迭代器
2. 反复调用迭代器的「给我下一个」
3. 直到迭代器说「没了」

这就是为什么 `for` 可以遍历列表、字符串、字典、文件、甚至一个还没算出来的无限序列——**只要对象支持「给我下一个」这个协议就行**。

你在步骤 5 处理大文件时会直接用到这一点：

```python
with open("巨大的文件.txt") as f:
    for line in f:        # 不会把整个文件读进内存，一行一行来
        process(line)
```

## 步骤 4 · 四种容器与「选错的代价」（1.5 小时）

### 这一步在做什么

Python 有四种装东西的容器。**选错容器是新手最常见的性能问题和逻辑 bug 来源**，这一节让你亲手量出选错的代价有多大。

### 四种容器

| 容器 | 写法 | 特点 | 什么时候用 |
|---|---|---|---|
| **list** 列表 | `[1, 2, 3]` | 有序、可改、可重复 | 一串东西，在乎顺序 |
| **dict** 字典 | `{"name": "王", "age": 28}` | 键值对，按键查极快 | 有名字的数据、分组、查表 |
| **set** 集合 | `{1, 2, 3}` | 无序、自动去重、查成员极快 | 去重、判断「在不在里面」 |
| **tuple** 元组 | `(1, 2, 3)` | 有序、**不可改** | 固定不变的一组值、当字典的键 |

新建 `step4.py`，四个都跑一遍：

```python
# list：有序，可以按位置取，可以重复
orders = ["家电", "家居", "家电", "数码"]
print(orders[0], orders[-1], len(orders))     # 家电 数码 4
orders.append("家居")
print(orders)

# dict：按键取值，Agent 开发里最常用的容器
row = {"order_id": 1001, "category": "家电", "amount": 1200}
print(row["category"])                        # 家电
print(row.get("city", "未知"))                # 未知，键不存在时返回默认值而不是崩
row["city"] = "北京"                          # 直接赋值就是新增
print(row)

# set：自动去重
categories = set(orders)
print(categories)                             # {'家电', '家居', '数码'}，顺序不保证
print("数码" in categories)                   # True

# tuple：不可改，改了就报错
point = (1200, "家电")
print(point[1])
# point[0] = 999                              # 取消注释会报 TypeError
```

**`dict.get(键, 默认值)` 这个方法你后面天天用。** 直接写 `row["city"]` 在键不存在时会抛 `KeyError` 让程序崩，`get` 让你给一个兜底值。

### 用 dict 做分组：这是综合项目的核心

**这段代码是本单元最重要的一段。** 综合项目的统计逻辑就是它。

```python
rows = [
    {"category": "家电", "amount": 1200},
    {"category": "家居", "amount": 300},
    {"category": "家电", "amount": 800},
    {"category": "数码", "amount": 3000},
]

# 分组的通用套路：一个 dict，键是组名，值是这一组的所有元素
groups = {}
for row in rows:
    category = row["category"]
    if category not in groups:      # 第一次见到这个分类，先开一个空列表
        groups[category] = []
    groups[category].append(row["amount"])

print(groups)
```

```
{'家电': [1200, 800], '家居': [300], '数码': [3000]}
```

**「不在就先建一个空的，然后往里塞」是分组的固定套路。** 标准库有个简写：

```python
from collections import defaultdict

# defaultdict(list) 的意思是「取一个不存在的键时，自动给它建一个空 list」
groups = defaultdict(list)
for row in rows:
    groups[row["category"]].append(row["amount"])

print(dict(groups))     # 转回普通 dict 再打印，输出更干净
```

两种写法都要能写。**先用第一种把逻辑想清楚，再用第二种偷懒。**

### 选错容器的代价：自己量一次

在终端里跑这两条（不用写文件，`-m timeit` 是 Python 自带的计时工具）：

```bash
python3 -m timeit -s "data = list(range(100000))" "99999 in data"
python3 -m timeit -s "data = set(range(100000))" "99999 in data"
```

我这台机器上的结果：

```
500 loops, best of 5: 480 usec per loop
20000000 loops, best of 5: 10.7 nsec per loop
```

**480 微秒 vs 10.7 纳秒，差了四万多倍。** 你的机器数字会不一样，但量级差距是一样的。

**动手改一次**：把 `100000` 改成 `1000`，两条再跑一次。你会看到 list 那条快了大约 100 倍，set 那条几乎没变。这就是下面要说的 O(n) 和 O(1) 的区别——**不是「set 比 list 快一点」，是「list 会随数据变大而变慢，set 不会」。**

### 复杂度：只需要记住三个词

真实工作里你不需要会算复杂度，但**必须能判断「我这个写法会不会随着数据变多而崩」**。这是面试和 code review 都会问的。

记号写作 `O(...)`，读作「大 O」，描述的是**数据量翻倍时，耗时怎么变**。

| 记号 | 叫法 | 数据翻倍时 | 典型操作 |
|---|---|---|---|
| `O(1)` | 常数时间 | **耗时不变** | dict/set 的查找、list 按下标取 `a[5]`、append |
| `O(n)` | 线性时间 | **耗时翻倍** | list 的 `in`、遍历一遍、`list.remove()` |
| `O(n²)` | 平方时间 | **耗时变四倍** | 双层嵌套循环 |

四种容器的关键操作：

| 操作 | list | dict | set |
|---|---|---|---|
| 判断 `x in 容器` | **O(n)** 挨个比 | O(1) | O(1) |
| 按键/下标取值 | O(1) | O(1) | 不支持 |
| 加一个元素 | O(1) | O(1) | O(1) |
| 删一个元素 | O(n) | O(1) | O(1) |

**你要形成的条件反射**：写 `if x in 某个东西` 时，先看那个东西是不是 list。是的话，问自己「它会不会变得很大」。会的话，改成 set。

**O(n²) 长什么样**——这段是真实代码里最常见的性能事故：

```python
# 找出两个列表都有的元素。这个写法在两边各一万条时会跑好几秒
common = []
for a in list_a:                # 外层 n 次
    if a in list_b:             # 每次内部又是 n 次比较 → n × n
        common.append(a)

# 改一行就够了：把被搜的那个转成 set
set_b = set(list_b)             # 这一步是 O(n)，只做一次
common = [a for a in list_a if a in set_b]     # 每次查找变成 O(1) → 总共 O(n)
```

**注意「隐藏的循环」。** `if a in list_b` 看起来是一行，实际上里面藏着一整个循环。这是新手看不出 O(n²) 的主要原因。

### 练习 4

新建 `ex4.py`。给定：

```python
rows = [
    {"category": "家电", "amount": 1200, "city": "北京"},
    {"category": "家居", "amount": 300, "city": "上海"},
    {"category": "数码", "amount": 3000, "city": "深圳"},
    {"category": "家电", "amount": 800, "city": "广州"},
    {"category": "家居", "amount": 450, "city": "北京"},
    {"category": "数码", "amount": 5000, "city": "上海"},
]
```

写函数 `summarize(rows)`，按 `category` 分组，返回一个 dict，每组给出条数和均值：

**验收标准**：`print(summarize(rows))` 输出

```
{'家电': {'count': 2, 'mean': 1000.0}, '家居': {'count': 2, 'mean': 375.0}, '数码': {'count': 2, 'mean': 4000.0}}
```

**附加题**：再写一句，用 set 求出「出现过的城市」，输出城市个数。答案是 4。

#### 参考答案（先自己写完再看）

```python
from collections import defaultdict


def summarize(rows):
    """按 category 分组，返回 {分类: {"count": 条数, "mean": 均值}}。"""
    # 第一遍：把每组的金额收集起来
    groups = defaultdict(list)
    for row in rows:
        groups[row["category"]].append(row["amount"])

    # 第二遍：把每组的列表折算成 count 和 mean
    result = {}
    for category, amounts in groups.items():
        result[category] = {
            "count": len(amounts),
            "mean": sum(amounts) / len(amounts),
        }
    return result


print(summarize(rows))

# 附加题：set 推导式，自动去重
cities = {row["city"] for row in rows}
print(len(cities))      # 4
```

**为什么分两遍写**：第一遍只管收集、第二遍只管计算，各自逻辑简单。想一次性算完（边遍历边更新 count 和 mean）也行，但均值没法边走边算，代码会更绕。**能拆两遍就别硬凑一遍**，这是可读性优先于「显得聪明」。

### 可能卡在哪

**`KeyError: 'city'`**

字典里没这个键。三种处理方式，按场景选：

```python
row.get("city")                 # 没有就返回 None
row.get("city", "未知")          # 没有就返回你给的默认值
if "city" in row: ...           # 先判断再取
```

**修改列表时意外改了另一个**

```python
a = [1, 2, 3]
b = a                # 这不是复制，b 和 a 指向同一个列表
b.append(4)
print(a)             # [1, 2, 3, 4]，a 也变了
```

`=` 只是给同一个对象贴第二个标签。要真复制：

```python
b = a.copy()         # 或者 b = list(a)
```

**可变默认参数**

```python
def add_item(item, items=[]):    # 陷阱：默认的空列表只会创建一次
    items.append(item)
    return items

print(add_item(1))      # [1]
print(add_item(2))      # [1, 2]  ← 不是期望的 [2]
```

因为默认值 `[]` 只在**函数定义时**创建一次，之后所有调用共用同一个列表。

**正确写法**：

```python
# 默认值用 None 占位，每次调用时再造新列表，调用之间就互不影响
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

**这个坑几乎每个 Python 新手都会踩一次，亲自跑一遍上面那段看到 `[1, 2]`。**

**set 打印出来顺序每次不一样**

正常。set 是无序的，不要依赖它的顺序。需要有序输出就 `sorted(my_set)`。

### 背后的逻辑

**为什么 dict 和 set 查找是 O(1)？**

它们内部是**哈希表**。存一个元素时，先用哈希函数把它算成一个数字，这个数字直接决定它放在内存的哪一格。查的时候再算一次，直接跳到那一格——不管表里有 10 个还是 1000 万个元素，都是「算一次，跳一次」。

这也解释了两件事：

- **为什么 set 和 dict 的键必须是不可变类型**（不能拿 list 当 dict 的键）。因为如果元素能改，它的哈希值就变了，之前存的位置就找不回来了。tuple 可以当键，list 不行，就是这个原因。
- **为什么 set 无序**。元素的位置由哈希值决定，跟你插入的顺序没关系。

**为什么会有「同一个对象」的问题？**

Python 里变量存的不是值本身，而是**指向对象的引用**（可以理解成地址）。`b = a` 复制的是地址，不是内容。

判断一个类型是「可变」还是「不可变」：

- **可变**：list、dict、set —— 改它会影响所有引用它的变量
- **不可变**：int、float、str、tuple —— 「改」实际上是造了个新对象

```python
a = "abc"
b = a
b += "d"        # 造了个新字符串 "abcd" 赋给 b
print(a)        # 还是 "abc"，没被影响
```

理解这个区别，能解释你以后遇到的一大类「值莫名其妙变了」的 bug。

## 步骤 5 · 文件读写与 JSON（1 小时）

### 这一步在做什么

让程序能读进外部数据、把结果存下来。到这一步为止你的程序都是「跑完就没了」。

### 怎么做

新建 `step5.py`：

```python
# 写：with 保证文件一定会被关闭
with open("demo.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")

# 读法一：全部读成一个字符串。文件大就别这么干
with open("demo.txt", "r", encoding="utf-8") as f:
    content = f.read()
print(repr(content))          # '第一行\n第二行\n'

# 读法二：一行一行读，省内存，还能知道行号
with open("demo.txt", "r", encoding="utf-8") as f:
    for line_no, line in enumerate(f, start=1):
        print(line_no, line.strip())      # strip() 去掉行尾换行符

# 追加：模式 "a"，不会覆盖原内容
with open("demo.txt", "a", encoding="utf-8") as f:
    f.write("第三行\n")
```

```
'第一行\n第二行\n'
1 第一行
2 第二行
```

模式：`"r"` 读、`"w"` 写（**会清空原文件**）、`"a"` 追加。

**`repr()` 是调试利器**：它把字符串里的换行符、空格原样显示出来。`print(content)` 你看不出末尾有没有换行，`print(repr(content))` 一目了然。

### JSON：后面天天用

JSON 是程序之间交换数据的通用格式。**你在 S1 调模型 API、S2 让 Agent 返回结构化结果，全是 JSON。**

```python
import json

# 写：字典的键用英文，值可以是中文内容
data = {"name": "小王", "tags": ["家电", "家居"], "count": 3}
with open("demo.json", "w", encoding="utf-8") as f:
    # ensure_ascii=False 让中文原样落盘，indent=2 让文件人能读
    json.dump(data, f, ensure_ascii=False, indent=2)

# 读：json.load 直接把文件内容还原成 Python 字典
with open("demo.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded["tags"][0])      # 家电
```

跑完后 `cat demo.json` 看一眼：

```json
{
  "name": "小王",
  "tags": [
    "家电",
    "家居"
  ],
  "count": 3
}
```

**现在把 `ensure_ascii=False` 删掉再跑一次，再 `cat`：**

```json
{
  "name": "小王",
  ...
}
```

中文变成了转义码。**技术上没错，但人没法读，排查问题时会很难受。永远加 `ensure_ascii=False`。**

**四个函数别记混**：

| 函数 | 做什么 |
|---|---|
| `json.dump(对象, 文件)` | 对象 → **写进文件** |
| `json.dumps(对象)` | 对象 → **返回字符串** |
| `json.load(文件)` | 文件 → 对象 |
| `json.loads(字符串)` | 字符串 → 对象 |

**带 `s` 的是「string」，处理字符串；不带 `s` 的处理文件。** 记住这条就不会混。

### 练习 5

新建 `ex5.py`：读 `sales.csv`（先不用 csv 模块，就当普通文本按逗号切），统计一共多少行数据（**不含表头**），写进 `count.json`。

提示：切分用 `line.strip().split(",")`。跳过表头的一个办法是 `enumerate` 之后判断行号。

**验收标准**：

```bash
cat count.json
```

输出：

```json
{
  "rows": 20
}
```

**如果你得到 21，说明表头被算进去了**——这就是步骤 0 让你记住「21 行」的原因。

#### 参考答案（先自己写完再看）

```python
import json

rows = 0
with open("sales.csv", "r", encoding="utf-8") as f:
    for line_no, line in enumerate(f, start=1):
        if line_no == 1:          # 第一行是表头，跳过
            continue
        if not line.strip():      # 空行也跳过，文件末尾常有一个
            continue
        rows += 1

with open("count.json", "w", encoding="utf-8") as f:
    json.dump({"rows": rows}, f, ensure_ascii=False, indent=2)

print("写完了，共", rows, "行")
```

### 可能卡在哪

**`FileNotFoundError`**

路径不对。**Python 的相对路径是相对于「你运行命令时所在的目录」，不是相对于 `.py` 文件所在的目录。**

这是新手极常见的困惑：在 `py-basics` 目录里跑 `python3 ex5.py` 能找到 `sales.csv`，回到上一级跑 `python3 py-basics/ex5.py` 就找不到了。

稳妥做法：

```python
from pathlib import Path

# __file__ 是当前脚本自己的路径，以它为基准拼路径，
# 无论从哪个目录运行都能找到文件
here = Path(__file__).parent
data_file = here / "sales.csv"

with open(data_file, "r", encoding="utf-8") as f:
    ...
```

**亲手验证一次**：先用相对路径跑通，然后 `cd ..` 再跑 `python3 py-basics/ex5.py`，看它崩掉，再改成 `Path(__file__).parent` 的写法，看它两个位置都能跑。**撞过一次，以后看到 FileNotFoundError 第一反应就对了。**

**中文乱码**

`open` 时永远显式写 `encoding="utf-8"`。不写的话 Python 用系统默认编码，不同机器行为不一致。

**写完文件是空的**

忘了用 `with`，文件没关闭，内容还在缓冲区里：

```python
f = open("a.txt", "w")
f.write("内容")
# 忘了 f.close()，内容可能没落盘
```

**永远用 `with`。**

**`json.dump` 报 `Object of type X is not JSON serializable`**

你想存的东西 JSON 表达不了。JSON 只认这几种：字符串、数字、布尔、null、数组、对象。set 和 datetime 都不行，要先转：`list(my_set)`、`dt.isoformat()`。

### 背后的逻辑

**`with` 是什么？**

它叫「上下文管理器」。语义是：进入这个块时做点准备工作，离开这个块时做点清理工作，**哪怕中间抛异常也保证清理**。

```python
with open("a.txt") as f:
    code_that_raises()    # 即使这里崩了
# f 也一定会被关闭
```

这个模式你后面会大量遇到：数据库连接（U0.8）、HTTP 会话（U0.5）、锁（U0.11）、临时目录。**看到 `with` 就想到「这东西用完需要收尾」。**

## 步骤 6 · CSV：用标准库，别自己切（0.5 小时）

### 这一步在做什么

练习 5 你用 `split(",")` 切 CSV，能跑。这一节告诉你为什么真实项目不那么干。

### 手工切分会在哪翻车

在交互式里跑：

```python
>>> line = '1001,"电视机, 65寸",1200,北京'
>>> line.split(",")
['1001', '"电视机', ' 65寸"', '1200', '北京']
```

**字段值里本身带逗号，切出来就是 5 个而不是 4 个，全错位了。** 真实数据里商品名、地址、备注带逗号是常态。

引号、换行、转义还有一堆规则。**别自己写，用标准库。**

新建 `ex6.py`：用 `csv.DictReader` 读 `sales.csv`，输出三样东西：

1. 总行数
2. 总金额
3. 出现过的分类（去重，排序后输出）

### 可能卡在哪

**`newline=""` 是干什么的，能不能不写**

能跑，但在 Windows 上写 CSV 会多出空行。**这是 csv 模块官方文档明确要求的写法**，养成习惯写上，成本为零。

**表头里有空格或 BOM，取不到键**

某些 Excel 导出的 CSV，第一个字段名前面会带一个看不见的 BOM 字符，导致 `row["order_id"]` 报 `KeyError`。

诊断方法：

```python
print(reader.fieldnames)        # 把表头原样打出来看
```

看到 `['﻿image_id', ...]` 就是 BOM。解法是把 `encoding="utf-8"` 改成 `encoding="utf-8-sig"`，它会自动吃掉 BOM。

**`ValueError: could not convert string to float: ''`**

### 背后的逻辑

**为什么不用 `split(",")`：这是「格式」和「分隔符」的区别。**

新手容易把 CSV 理解成「用逗号分隔的文本」，但 CSV 是一个**有规范的格式**（RFC 4180），规范里包括：字段可以用双引号包起来，包起来之后里面可以有逗号和换行，引号本身用两个引号转义。

这个思路你后面会反复用到：**遇到一个「看起来结构很简单」的格式，先查有没有标准库。** JSON、YAML、URL、HTML、日期时间，全都有你想不到的边界情况。自己手写解析器是 bug 的稳定来源。

## 步骤 7 · 异常处理（1 小时）

### 这一步在做什么

上一节最后那个 `ValueError` 就是入口：**真实数据里一定有脏数据，你的程序不能因为第 7 行坏了就整个崩掉。**

### 先造一份脏数据

```bash
cp sales.csv sales_dirty.csv
cat >> sales_dirty.csv <<'CSV'
1021,家电,,北京
1022,家居,N/A,上海
1023,数码,abc,深圳
CSV
```

现在用练习 6 的代码去读它，会崩：

```
ValueError: could not convert string to float: ''
```

**而且崩在第 21 行，前面 20 行的统计全白算了。**

### 怎么做

新建 `step7.py`：

```python
def parse_amount(text):
    """把 CSV 里的金额文本转成 float。转不了就返回 None，让调用方决定怎么办。"""
    try:
        return float(text)
    except ValueError:          # 只捕获「转不了数字」这一种，别的错误照样往上抛
        return None


for text in ["1200", "300.5", "", "N/A", "abc"]:
    print(repr(text), "→", parse_amount(text))
```

```
'1200' → 1200.0
'300.5' → 300.5
'' → None
'N/A' → None
'abc' → None
```

完整语法：

```python
try:
    # try 里只放可能出错的那一两行，范围越小越好定位
    number = int(input("输入一个数字："))
    result = 100 / number
except ValueError:               # 输入的不是整数，int() 会抛这个
    print("这不是数字")
except ZeroDivisionError:        # 输入了 0
    print("不能除以零")
else:
    print(f"结果是 {result}")     # 没出错才执行
finally:
    print("无论如何都执行")        # 收尾动作放这里，出不出错都会跑
```

**`try` 块里只放会出错的那一两行。** 把一大段代码全裹进 try 里，出错时你不知道是哪一行炸的，等于没定位。

### 什么时候该捕获，什么时候该让它崩

**这个判断比语法重要得多，很多写了几年代码的人也没想清楚。**

**该捕获**：你预料得到、并且知道怎么办的情况。

```python
try:
    response = call_api()
except NetworkTimeout:       # 只捕获这一种你预料得到的错误
    retry_after_a_second()   # 你有应对方案
```

**不该捕获**：程序逻辑本身错了。

```python
try:
    result = heavy_calculation()
except:                      # 把所有错误都吞掉
    pass                     # 什么都不做
```

**这是最糟糕的代码。** 它让 bug 静默发生，你永远不知道哪里错了。程序应该在遇到未预期的错误时**大声崩掉**，而不是假装没事继续跑。

**判断标准一句话**：你能写出「捕获之后要做什么」，才该捕获。写不出来（只能 `pass`）就说明你没预料到它，让它崩。

### 练习 7

新建 `ex7.py`：读 `sales_dirty.csv`，做到三件事：

1. 跳过金额无效的行，**但不崩**
2. 正常统计剩下的行（行数、总额）
3. **把跳过的行报告出来**，包括行号和原始值

**验收标准**：

```
第 22 行金额无效，跳过：''
第 23 行金额无效，跳过：'N/A'
第 24 行金额无效，跳过：'abc'
有效行数: 20
总额: 29200.0
跳过: 3
```

行号从 2 开始数（第 1 行是表头），所以三条坏数据分别是第 22、23、24 行。**行号必须对**——排查线上数据问题时，「哪一行坏了」是最有用的信息。

#### 参考答案（先自己写完再看）

```python
import csv
from pathlib import Path

here = Path(__file__).parent


def parse_amount(text):
    """转 float，转不了返回 None。只兜 ValueError，其他错误照样抛。"""
    try:
        return float(text)
    except ValueError:
        return None


count = 0
total = 0.0
skipped = 0

with open(here / "sales_dirty.csv", "r", encoding="utf-8", newline="") as f:
    # start=2 因为 DictReader 已经吃掉了表头，第一条数据在文件的第 2 行
    for line_no, row in enumerate(csv.DictReader(f), start=2):
        amount = parse_amount(row["amount"])
        if amount is None:
            print(f"第 {line_no} 行金额无效，跳过：{row['amount']!r}")
            skipped += 1
            continue
        count += 1
        total += amount

print("有效行数:", count)
print("总额:", total)
print("跳过:", skipped)
```

**两个细节**：

- `enumerate(..., start=2)`：`DictReader` 会先读掉表头，所以它吐出的第一条数据对应文件的第 2 行。想清楚这个偏移，行号才准。
- `{row['amount']!r}`：f-string 里的 `!r` 等于对它调 `repr()`。**空字符串不加 `!r` 打出来什么都看不见**，加了才显示成 `''`。

### 可能卡在哪

**`except:` 光秃秃不写异常类型**

它会捕获一切，包括 `Ctrl+C`（`KeyboardInterrupt`）——你会发现程序按 Ctrl+C 停不下来。**永远写明要捕获什么**，最宽也要写 `except Exception as e:`。

**捕获了但不知道错在哪**

```python
except Exception as e:
    print(f"出错了：{e}")        # 至少要把错误信息打出来
```

更好的做法是用 logging（U0.4 步骤 6），它会自动记录完整调用栈。

**f-string 里嵌套引号报错**

```python
print(f"{row["amount"]}")       # Python 3.11 及以前会报 SyntaxError
print(f"{row['amount']}")       # 里外用不同引号，永远安全
```

Python 3.12 之后放宽了这个限制，但**里外用不同引号**是无论哪个版本都对的写法。

### 背后的逻辑

Python 的哲学是 **EAFP**：Easier to Ask Forgiveness than Permission（先做，出错再道歉）。

对比另一种风格 **LBYL**：Look Before You Leap（先检查再做）。

```python
# LBYL 风格：先检查键在不在，再取
if "key" in config:
    value = config["key"]
else:
    value = default_value

# EAFP 风格（Python 更推荐）：直接取，取不到再兜底
try:
    value = config["key"]
except KeyError:
    value = default_value
```

为什么 Python 偏好 EAFP？两个理由：

- **「检查」和「使用」之间可能有变化。** 你检查完文件存在，正要打开时它被删了——检查白做。多线程和网络场景下这类竞态很常见。
- **大多数情况下不会出错。** 先检查等于每次都付出额外代价，而 try 在不出错时几乎零开销。

## 步骤 8 · 报错怎么读，bug 怎么找（1.5 小时）

### 这一步在做什么

**这是整个单元最重要的一节。** 到目前为止你学的是「怎么让代码跑对」，这一节学的是「跑错了怎么办」。

真实工作里，你花在「找 bug」上的时间远多于「写代码」。**不会调试的人的典型症状是：报错了就把整段代码丢给 AI 说「帮我修」，AI 改完能跑了但他不知道为什么。** 这条路走不远——到 S2 你的 Agent 出现「有时候对有时候错」的问题时，没人能替你定位。

### 先造一个真 bug

新建 `buggy.py`，**原样敲进去，它是有 bug 的**：

```python
import csv
from pathlib import Path

here = Path(__file__).parent


def load_amounts(path):
    """读出所有金额，返回一个 list。"""
    amounts = []
    with open(path, "r", encoding="utf-8", newline="") as f:
        for row in csv.DictReader(f):
            amounts.append(row["amount"])
    return amounts


def average(numbers):
    """求均值。"""
    return sum(numbers) / len(numbers)


def main():
    amounts = load_amounts(here / "sales.csv")
    print("均值是", average(amounts))


if __name__ == "__main__":
    main()
```

跑它：

```bash
python3 buggy.py
```

```

  File "/.../buggy.py", line 27, in <module>
    main()
    ~~~~^^
  File "/.../buggy.py", line 23, in main
    print("均值是", average(amounts))
                    ~~~~~~~^^^^^^^^^
```

**先不要往下看解法。** 先按下面的方法自己读一遍。

### 第一步：读报错，三个动作

**动作一：先看最后一行。** 它是错误类型和描述，信息密度最高。

```
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

翻译：`+` 不支持「整数 加 字符串」。

常见错误类型对照：

| 错误类型 | 意思 | 典型原因 |
|---|---|---|
| `SyntaxError` | 语法写错了 | 中文标点、少冒号、括号没配对 |
| `IndentationError` | 缩进错了 | 该缩没缩，或缩进不一致 |
| `NameError` | 用了不存在的名字 | 拼写错、大小写错、变量还没赋值 |
| `TypeError` | 类型不对 | 拿字符串当数字算、给函数传错参数个数 |
| `ValueError` | 类型对但值不行 | `int("abc")` |
| `KeyError` | 字典里没这个键 | 键名拼错、数据里本来就没有 |
| `IndexError` | 下标越界 | 列表只有 3 个却取第 5 个 |
| `AttributeError` | 对象没这个方法 | 对 None 调方法（最常见） |
| `FileNotFoundError` | 文件不存在 | 路径不对 |

**动作二：从下往上读调用链。** `most recent call last` 就是提示你「最近的调用在最后」。

```
main()              ← 第 27 行调用了 main
  average(amounts)  ← 第 23 行，main 里调用了 average
    sum(numbers)    ← 第 18 行，average 里炸了
```

**最底下那层是崩的地方，往上是「谁把它调到这儿的」。**

**动作三：分清「报错的位置」和「bug 的位置」。**

**这是新手和熟手最大的差别。** 这个例子里报错在 `average` 第 18 行，但 `average` 一点问题都没有——它拿到了脏数据。**真正的 bug 在 `load_amounts` 第 12 行**：CSV 读出来全是字符串，忘了转 `float`。

**报错位置是「毒发的地方」，bug 位置是「下毒的地方」，中间可能隔着好几层。** 顺着调用链往上找「这个坏数据是谁给的」，才是正确的排查路径。

### 第二步：三种定位手段，从轻到重

**手段一：print 大法**（80% 的情况够用）

在你怀疑的地方打两样东西：**值和类型**。

```python
def average(numbers):
    print("DEBUG numbers[:3] =", numbers[:3])       # 前几个长什么样
    print("DEBUG type =", type(numbers[0]))         # 是什么类型
    return sum(numbers) / len(numbers)
```

```
DEBUG numbers[:3] = ['1200', '300', '3000']
DEBUG type = <class 'str'>
```

**看到引号了吗？** `'1200'` 带引号就是字符串。找到了。

**打 print 的三条经验**：

- **打值，也打类型。** 一半的 bug 是类型不对，光看值看不出 `'1200'` 和 `1200` 的区别。用 `repr()` 或者 f-string 的 `!r` 能让引号显出来。
- **前缀加个 `DEBUG`。** 好搜、好删。收尾时 `grep -n DEBUG *.py` 一次清干净。
- **打在「怀疑的数据刚生出来的地方」和「它出问题的地方」，两头夹。** 中间一分为二地找，比一行行看快得多。

**手段二：`breakpoint()`**（想看更多变量、想边看边试的时候）

在想停下的那一行前面写一行 `breakpoint()`：

```python
def average(numbers):
    """求均值。"""
    breakpoint()
    return sum(numbers) / len(numbers)
```

跑起来会停在那里，给你一个 `(Pdb)` 提示符：

```

(Pdb)
```

**这时候你可以敲任何 Python 表达式看当前状态**：

```
(Pdb) p numbers[:3]
['1200', '300', '3000']
(Pdb) p type(numbers[0])
<class 'str'>
(Pdb) p len(numbers)
20
(Pdb) c
```

常用命令，记这六个就够：

| 命令 | 全称 | 作用 |
|---|---|---|
| `p 表达式` | print | 打印任意表达式的值 |
| `n` | next | 执行下一行（**不进入函数内部**） |
| `s` | step | 执行下一行（**进入函数内部**） |
| `c` | continue | 继续跑，直到下一个断点或结束 |
| `u` | up | 沿调用链往上跳一层（看调用者的变量） |
| `q` | quit | 退出 |

**`u` 是找 bug 的关键命令。** 崩在 `average` 里，敲 `u` 跳到 `main`，就能看到 `amounts` 是谁传的、长什么样。

### 第三步：VS Code 图形化调试

pdb 在服务器上很有用，但你日常在 VS Code 里，**图形化断点更直观**。

**怎么用（照着做一遍）**：

1. 确认装了 Python 扩展（`ms-python.python` 和 `ms-python.debugpy`，都在本仓库的推荐扩展里，U0.1 装过）
2. 打开 `buggy.py`，**在第 18 行左边、行号左侧那一列点一下**，出现一个红点，这就是断点
3. 按 `F5`，第一次会让你选调试配置，选 **Python Debugger** → **Python File**
4. 程序跑到第 18 行停住，那一行被高亮

停住之后，看这几个地方：

| 位置 | 你能看到什么 |
|---|---|
| 左侧 **变量 / VARIABLES** 面板 | 当前所有变量的名字、值、类型。**展开 `numbers` 能直接看到每个元素带不带引号** |
| 左侧 **调用堆栈 / CALL STACK** 面板 | 现在处在哪一层。**点上面一层，变量面板立刻切到那一层的上下文**——等价于 pdb 的 `u`，但更好用 |
| 左侧 **监视 / WATCH** 面板 | 点 `+` 加一个表达式（比如 `type(numbers[0])`），每次暂停都自动求值 |
| 底部 **调试控制台 / DEBUG CONSOLE** | 直接敲表达式当场求值，等价于 pdb 的 `p` |
| 顶部悬浮工具条 | 继续（F5）、单步跳过（F10）、单步进入（F11）、跳出（Shift+F11）、停止 |

**F10 和 F11 的区别，是新手最容易糊涂的一点**：

- **F10 单步跳过**：下一行如果是个函数调用，**整个函数一步执行完**，你不进去
- **F11 单步进入**：**钻进那个函数里面**，一行一行看它怎么执行的

**用法**：先用 F10 快速走，走到某一行发现「结果不对」，就重跑，在那一行用 F11 钻进去看。

**条件断点**：在断点红点上右键 → **编辑断点** → 输入条件，比如 `line_no == 22`。**处理 20 行数据时不用按 20 次继续，直接停在你要的那一行。** 这个功能省下来的时间比你想的多。

### 可能卡在哪

**报错里全是看不懂的库文件路径**

比如一长串 `site-packages/httpx/...`。**在调用链里从下往上找第一个是「你自己写的文件」的那一层**，那才是你的入口。库内部的栈帧通常不是你的问题。

**`AttributeError: 'NoneType' object has no attribute 'xxx'`**

**这个报错单独拎出来说，因为它太常见了。** 它的意思永远是：某个变量是 `None`，你在对 `None` 调方法。

而 `None` 从哪来？**九成是某个函数忘了写 `return`**（回去看步骤 1 的「背后的逻辑」），或者 `dict.get()` 没取到值。

排查方法：顺着调用链往上，找那个变量是谁给的，去看那个函数最后有没有 `return`。

**F5 之后弹出一堆配置选项不知道选哪个**

选 **Python Debugger** → **Python File**（当前文件）。VS Code 会在 `.vscode/launch.json` 里记下来，下次直接 F5。

**断点点了不生效，程序直接跑完**

两个常见原因：断点打在了一段根本不会执行的代码上（比如某个 `if` 分支没进去）；或者你按的是右上角的「运行」三角形而不是 F5——**运行不带调试器，断点当然不生效**。三角形旁边的下拉箭头里有「调试 Python 文件」。

### 背后的逻辑

**为什么 Python 的报错叫「Traceback」而不是「Error Message」？**

因为它给的不是一条消息，是一条**路径**。Python 在每次函数调用时都把「我从哪来」压进一个叫「调用栈」的结构里，出错时把整个栈原样倒出来。

**这个思路贯穿你后面所有课程**：

- U0.7 测试失败时，pytest 给的也是 traceback，读法一模一样
- S3 的可观测性（Langfuse、OpenTelemetry）本质上是「分布式的 traceback」——一次 Agent 调用跨了模型、工具、数据库，trace 让你看到它在哪一环出的问题
- S4 排查线上故障，第一件事永远是「把日志里的 traceback 找出来，从下往上读」

**所以这一节不是「Python 的调试技巧」，是「排查问题」这件事本身的入门。** 现在在 20 行的脚本上练熟，后面在跨五个服务的 Agent 系统上才有得用。

**另一个观念：让 bug 早点崩。**

`load_amounts` 那个 bug 之所以难找，是因为脏数据被「安静地」存进了 list，跑出去两层才炸。如果在读的时候就转 `float`，它会**在第 12 行、拿到坏数据的那一瞬间**就崩，报错位置和 bug 位置重合，一眼就找到。

这就是 U0.4 要教类型注解和 Pydantic 的原因：**在数据进门的地方就校验，让错误在离源头最近的地方暴露。**

### 参考实现（四个检查点都过了再看）

```python
"""按分类统计 CSV，输出 JSON。"""

import csv
import json
import sys
from collections import defaultdict
from pathlib import Path


def parse_amount(text):
    """把金额文本转成 float，转不了返回 None，由调用方决定怎么处理。"""
    try:
        return float(text)
    except (ValueError, TypeError):     # TypeError 兜住 text 是 None 的情况
        return None


def read_rows(path, group_column, value_column):
    """读 CSV，返回 (可用行列表, 跳过说明列表)。

    文件不存在在这里就报出来，不要让 FileNotFoundError 裸奔到 main。
    """
    rows = []
    skipped = []
    try:
        # utf-8-sig 能顺手吃掉 Excel 导出时可能带的 BOM
        with open(path, "r", encoding="utf-8-sig", newline="") as f:
            reader = csv.DictReader(f)
            # DictReader 已吃掉表头，第一条数据对应文件第 2 行
            for line_no, raw in enumerate(reader, start=2):
                amount = parse_amount(raw.get(value_column))
                if amount is None:
                    skipped.append(
                        f"第 {line_no} 行：{value_column} 无效 {raw.get(value_column)!r}"
                    )
                    continue
                group = raw.get(group_column)
                if not group:
                    skipped.append(f"第 {line_no} 行：{group_column} 为空")
                    continue
                rows.append({group_column: group, value_column: amount})
    except FileNotFoundError:
        # 给用户一句人话，而不是一整篇 traceback
        raise SystemExit(f"找不到文件：{path}")
    return rows, skipped


def summarize(rows, group_column, value_column):
    """按 group_column 分组，返回 {分类: {"count": n, "mean": m}}。"""
    groups = defaultdict(list)
    for row in rows:
        groups[row[group_column]].append(row[value_column])

    result = {}
    for group in sorted(groups):        # sorted 保证每次输出顺序一致，方便 diff
        values = groups[group]
        result[group] = {
            "count": len(values),
            "mean": round(sum(values) / len(values), 2),
        }
    return result


def write_result(result, path):
    """写 JSON。ensure_ascii=False 让中文原样落盘。"""
    with open(path, "w", encoding="utf-8") as f:
        json.dump(result, f, ensure_ascii=False, indent=2)


def main():
    # sys.argv[0] 是脚本名，argv[1] 才是第一个参数；没传就用默认文件
    src = Path(sys.argv[1]) if len(sys.argv) > 1 else Path(__file__).parent / "sales.csv"
    out = Path(__file__).parent / "stats.json"

    rows, skipped = read_rows(src, "category", "amount")
    for note in skipped:
        # 报告走 stderr，正常结果走 stdout，这样管道里只会流过有用数据
        print(note, file=sys.stderr)

    result = summarize(rows, "category", "amount")
    write_result(result, out)
    print(f"读入 {len(rows)} 行，跳过 {len(skipped)} 行，结果写入 {out.name}")


if __name__ == "__main__":
    main()
```

```json
  },

    "mean": 3000.0
  }
```

### 这个实现里有四个「不是新手写法」的地方，值得单独看

**1. `read_rows` 返回两样东西，而不是一样。**

新手写法是在 `read_rows` 里直接 `print` 跳过的行。**这就把「读数据」和「怎么告诉用户」绑死了**——以后想改成写日志、或者在 Web 服务里返回给前端，就得改这个函数。

返回 `(rows, skipped)`，让 `main` 决定怎么呈现。**这叫「决定权交给调用方」，是分层设计最基本的一条。** U0.4 讲模块拆分、U0.6 讲 FastAPI 分层，用的都是同一个道理。

**2. 报告走 `stderr`，结果走 `stdout`。**

这样别人可以 `python3 csv_stats.py x.csv > result.txt`，跳过报告只留干净输出。**这是命令行工具的通行约定**，U0.1 学的重定向在这里派上用场。

**3. `summarize` 里用 `sorted(groups)`。**

dict 在 Python 3.7+ 保持插入顺序，所以不排序的话，输出顺序取决于数据里谁先出现。**排了序，输出才是稳定的，`diff` 才有意义。** 上面那条「两份完全一致」的验收就依赖这一点。

**4. `parse_amount` 捕获两种异常。**

`float(None)` 抛的是 `TypeError` 不是 `ValueError`。真实数据里字段缺失（`.get()` 返回 `None`）和字段是空串（`''`）都会发生，两种都得兜。

**这一条是「想到边界情况」的示范**：写完一个函数，问自己「传进来的可能是什么」——空字符串、None、超长字符串、负数、零。

### 可能卡在哪

**统计结果比 20 少几行**

文件末尾有空行，或者某一行的 `category` 是空的。把 `skipped` 打出来看它跳了什么。

**mean 是 `1000` 而不是 `1000.0`**

说明你的数是 int 不是 float。`float(text)` 转过就一定是 float。检查是不是某个分支漏转了。

**`sys.argv` 报 `IndexError: list index out of range`**

你直接写了 `sys.argv[1]` 但运行时没传参数。要先判断 `len(sys.argv) > 1`。

**JSON 里中文是 `家电`**

忘了 `ensure_ascii=False`。

**`diff` 说两份文件不一样**

大概率是 `summarize` 里没 `sorted`，两次跑出来的键顺序不同。
