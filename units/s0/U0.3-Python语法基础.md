## 准备工作：怎么运行 Python

### 这一步在做什么

搞清楚「我写的代码怎么跑起来」。有三种方式，用途不同。

### 怎么做

**方式一：交互式（试语法用）**

```bash
python3
```

进入一个 `>>>` 提示符，敲一行执行一行。适合验证「这样写对不对」。

```python
>>> 1 + 1
2
>>> "hello".upper()
'HELLO'
>>> exit()
```

**方式二：跑脚本文件（正式写代码用）**

用 VS Code 新建一个 `hello.py`，写：

```python
print("你好")
```

保存，在终端里：

```bash
python3 hello.py
```

**方式三：VS Code 里直接点运行**

打开 `.py` 文件，右上角有个三角形播放按钮，点它。VS Code 会自动在下方终端里跑 `python3 你的文件.py`。

### 可能卡在哪

**`command not found: python3`**

macOS 可能没预装。用 brew 装：

```bash
brew install python@3.13
```

**输入 `python` 报错，`python3` 才行**

历史遗留。Python 2 和 Python 3 语法不兼容，为了不搞混，很多系统上 `python` 指向 2.x 或者干脆不存在。**你永远用 `python3`**，或者在 U0.4 学会用 uv 之后，用 `uv run` 就不用管这个了。

**VS Code 右下角提示「选择解释器」**

点它，选带 `3.13` 之类版本号的那个。这是告诉 VS Code「用哪个 Python 来跑我的代码」。

**中文显示成乱码**

现在基本不会了。真遇到的话，确认文件保存为 UTF-8 编码（VS Code 右下角能看到）。

### 背后的逻辑

Python 是**解释型语言**。你写的 `.py` 文件不需要编译成可执行程序，而是由一个叫「解释器」的程序（就是 `python3` 这个命令）逐行读取并执行。

这带来两个后果，你后面会反复感受到：

- **好处**：改完立刻能跑，不用等编译，开发快
- **代价**：错误往往要跑到那一行才暴露。比如你在第 50 行写错了变量名，前 49 行照样会执行，跑到第 50 行才崩

这也是为什么 Python 项目特别依赖测试和类型检查——它们把「跑到才发现」提前到「写的时候就发现」。

## 第 1 周 · 函数与变量

对应 CS50P Week 0。

### 这一步在做什么

学会给数据起名字（变量），学会把一段逻辑打包起来重复用（函数）。

### 核心概念

**变量就是给一块数据贴标签。**

```python
名字 = "小王"
年龄 = 28
身高 = 1.75
是学生 = False
```

Python 不需要声明类型，它自己看出来 `"小王"` 是字符串、`28` 是整数。

**函数就是把一段逻辑打包，起个名字。**

```python
def 打招呼(名字):
    return f"你好，{名字}"

print(打招呼("小王"))    # 你好，小王
```

拆开看：

| 部分 | 含义 |
|---|---|
| `def` | 定义函数的关键字（define） |
| `打招呼` | 函数名 |
| `(名字)` | 参数，调用时传进来的数据 |
| `:` | 冒号，表示「下面是函数体」 |
| 缩进的那些行 | 函数体，函数被调用时执行的内容 |
| `return` | 把结果交回去 |

**实际写代码请用英文命名。** 上面用中文只是为了让你先看清结构。

### 必须掌握的：f-string

```python
名字 = "小王"
数量 = 3
print(f"{名字}有{数量}条消息")        # 小王有3条消息
print(f"{数量 * 2}")                 # 6，花括号里可以放表达式
print(f"{3.14159:.2f}")             # 3.14，冒号后面是格式说明
```

**这是 Python 里最常用的字符串拼接方式**，你后面写 prompt 会天天用。

### 可能卡在哪

**`IndentationError: expected an indented block`**

**这是 Python 新手第一大坑。** Python 用缩进表示代码块的从属关系，不像别的语言用花括号。

```python
def f():
print("错")        # 报错：函数体必须缩进
```

```python
def f():
    print("对")    # 缩进 4 个空格
```

**规则**：同一个块里的所有行，缩进必须完全一致。**统一用 4 个空格，不要用 Tab**（VS Code 默认按 Tab 会插入 4 个空格，符合规范）。

**`TabError: inconsistent use of tabs and spaces`**

同一个文件里混用了 Tab 和空格。VS Code 里 `Cmd+Shift+P` → 搜 `Convert Indentation to Spaces`。

**`NameError: name 'xxx' is not defined`**

变量名打错了，或者用了一个还没赋值的变量。检查拼写和大小写——**Python 严格区分大小写**，`Name` 和 `name` 是两个变量。

**函数写了但没反应**

定义函数只是「教电脑怎么做」，你还要调用它才会执行：

```python
def f():
    print("hi")

f()        # 少了这行什么都不会发生
```

### 背后的逻辑

**为什么 Python 用缩进而不用花括号？**

设计者的理由是：不管什么语言，好的代码本来就会缩进，那不如让缩进直接成为语法。这样「代码看起来的结构」和「代码实际的结构」永远一致，杜绝了那种「缩进骗了你」的 bug。

代价就是你必须严格对齐。**但这也强迫你写出结构清晰的代码**，从长远看是好事。

**`return` 和 `print` 的区别**

新手经常搞混。

- `print` 是**显示给人看**，程序拿不到这个值
- `return` 是**把值交回给调用者**，程序可以继续用

```python
def a():
    print(1)      # 打印 1

def b():
    return 1      # 返回 1

x = a()           # 屏幕显示 1，但 x 是 None
y = b()           # 屏幕什么都不显示，但 y 是 1
```

**函数默认返回 `None`**，也就是「什么都没有」。

## 第 2 周 · 条件判断

对应 CS50P Week 1。

### 核心概念

```python
分数 = 85

if 分数 >= 90:
    print("优秀")
elif 分数 >= 60:
    print("及格")
else:
    print("不及格")
```

比较运算符：`==`（等于）、`!=`（不等于）、`>`、`<`、`>=`、`<=`
逻辑运算符：`and`、`or`、`not`

### 可能卡在哪

**`=` 和 `==` 搞混**

- `=` 是**赋值**：`x = 5` 意思是「把 5 存进 x」
- `==` 是**比较**：`x == 5` 意思是「x 等于 5 吗」

写 `if x = 5:` 会直接报语法错误。

**`is` 和 `==` 搞混**

- `==` 比较**值相不相等**
- `is` 比较**是不是同一个对象**

```python
a = [1, 2]
b = [1, 2]
a == b      # True，内容一样
a is b      # False，是内存里两个不同的列表
```

**规则**：比较值永远用 `==`。`is` 只用在跟 `None`、`True`、`False` 比较时（`if x is None:`）。

**缩进层级搞乱了**

```python
if a:
    if b:
        print("both")
    print("只有 a")      # 这行属于外层 if
print("总是执行")         # 这行不属于任何 if
```

看不清的时候，在 VS Code 里代码左侧会有竖线标出缩进层级。

### 背后的逻辑

**什么东西算「真」？**

`if` 后面不一定要是比较表达式，任何值都可以。Python 的规则是：

| 算「假」的 | 其他一切都算「真」 |
|---|---|
| `False`、`None` | 非零数字 |
| `0`、`0.0` | 非空字符串 |
| `""`（空字符串） | 非空容器 |
| `[]`、`{}`、`()`（空容器） |  |

所以你会看到这种写法：

```python
名单 = []
if 名单:                  # 等价于 if len(名单) > 0
    print("有人")
else:
    print("空的")
```

**这是 Python 的惯用写法**，比 `if len(名单) > 0` 更地道。

## 第 3 周 · 循环

对应 CS50P Week 2。

### 核心概念

```python
# 遍历一个序列
for 水果 in ["苹果", "香蕉", "橙子"]:
    print(水果)

# 重复 N 次
for i in range(5):        # i 依次是 0,1,2,3,4
    print(i)

# 条件为真就一直循环
计数 = 0
while 计数 < 3:
    print(计数)
    计数 += 1
```

控制循环：

```python
for i in range(10):
    if i == 3:
        continue      # 跳过这一轮，进下一轮
    if i == 6:
        break         # 直接跳出整个循环
    print(i)
```

### 列表推导式：Python 最常见的写法

```python
数字 = [1, 2, 3, 4, 5]

# 普通写法
翻倍 = []
for x in 数字:
    翻倍.append(x * 2)

# 列表推导式，一行搞定
翻倍 = [x * 2 for x in 数字]

# 带过滤
偶数翻倍 = [x * 2 for x in 数字 if x % 2 == 0]
```

**这个写法你在任何 Python 代码里都会见到，必须能读能写。**

### 可能卡在哪

**`while` 循环停不下来**

条件永远为真，程序卡死。按 `Ctrl+C` 强制停止。

常见原因是忘了在循环里改变条件相关的变量：

```python
i = 0
while i < 3:
    print(i)      # 忘了 i += 1，永远循环
```

**`range(5)` 为什么是 0 到 4，不含 5**

Python 的区间约定是「含头不含尾」。`range(5)` 有 5 个元素，从 0 开始，所以是 0-4。

这个约定在切片里也一样：`列表[1:3]` 取第 1、2 个，不含第 3 个。

**好处**：`range(a, b)` 的元素个数正好是 `b - a`，且 `range(0,3)` 和 `range(3,5)` 拼起来正好是 `range(0,5)`，不会重叠也不会漏。

**在循环里修改正在遍历的列表**

```python
数字 = [1, 2, 3, 4]
for x in 数字:
    if x % 2 == 0:
        数字.remove(x)      # 结果会不对！
```

因为删除会让后面的元素前移，遍历就跳过了。**正确做法是造一个新列表**：

```python
数字 = [x for x in 数字 if x % 2 != 0]
```

### 背后的逻辑

**`for x in 序列` 底层在做什么？**

Python 的 for 循环不是「计数循环」，而是「迭代器循环」。它做的事是：

1. 向对象要一个迭代器
2. 反复调用迭代器的「给我下一个」
3. 直到迭代器说「没了」

这就是为什么 `for` 可以遍历列表、字符串、字典、文件、甚至一个还没算出来的无限序列——**只要对象支持「给我下一个」这个协议就行**。

你以后处理大文件时会用到这一点：

```python
with open("巨大的文件.txt") as f:
    for 行 in f:          # 不会把整个文件读进内存，一行一行来
        处理(行)
```

## 第 4 周 · 异常处理

对应 CS50P Week 3。

### 这一步在做什么

学会「预料到会出错，并且优雅地处理」。

### 核心概念

```python
try:
    数字 = int(input("输入一个数字："))
    结果 = 100 / 数字
except ValueError:
    print("这不是数字")
except ZeroDivisionError:
    print("不能除以零")
else:
    print(f"结果是 {结果}")       # 没出错才执行
finally:
    print("无论如何都执行")
```

### 什么时候该捕获，什么时候该让它崩

**这是比语法更重要的判断，很多写了几年代码的人也没想清楚。**

**该捕获**：你知道会发生、并且知道怎么办的情况。

```python
try:
    响应 = 调用API()
except 网络超时:
    等一秒再试一次()          # 你有应对方案
```

**不该捕获**：程序逻辑本身错了。

```python
try:
    结果 = 复杂计算()
except:                      # 把所有错误都吞掉
    pass                     # 什么都不做
```

**这是最糟糕的代码。** 它让 bug 静默发生，你永远不知道哪里错了。程序应该在遇到未预期的错误时**大声崩掉**，而不是假装没事继续跑。

### 可能卡在哪

**`except:` 光秃秃的不写异常类型**

它会捕获一切，包括 `Ctrl+C`（KeyboardInterrupt）。**永远写明要捕获什么**，至少写 `except Exception as e:`。

**捕获了但不知道错在哪**

```python
except Exception as e:
    print(f"出错了：{e}")        # 至少要把错误信息打出来
```

更好的做法是用 logging（U0.4 会学），它会自动记录完整的调用栈。

**看不懂报错信息**

Python 的报错格式是这样的：

```
Traceback (most recent call last):
  File "a.py", line 10, in <module>
    结果 = 除法(1, 0)
  File "a.py", line 5, in 除法
    return a / b
ZeroDivisionError: division by zero
```

**读法是从下往上**：

- **最后一行**是错误类型和描述——先看这个
- **上面的是调用链**，最下面那层是真正出错的地方
- `most recent call last` 就是提示你「最近的调用在最后」

### 背后的逻辑

Python 的哲学是 **EAFP**：Easier to Ask Forgiveness than Permission（先做，出错再道歉）。

对比另一种风格 **LBYL**：Look Before You Leap（先检查再做）。

```python
# LBYL 风格
if "key" in 字典:
    值 = 字典["key"]
else:
    值 = 默认值

# EAFP 风格（Python 更推荐）
try:
    值 = 字典["key"]
except KeyError:
    值 = 默认值
```

为什么 Python 偏好 EAFP？因为「检查」和「使用」之间可能有变化（多线程环境下尤其明显），而且大多数情况下不会出错，先检查等于每次都付出额外代价。

## 第 5 周 · 库

对应 CS50P Week 4。

### 核心概念

```python
import json                          # 导入整个模块
import datetime as dt                # 导入并改名
from pathlib import Path             # 从模块里导入某个东西
from collections import Counter, defaultdict
```

标准库里你会常用的：

| 模块 | 用途 |
|---|---|
| `json` | JSON 的读写，**Agent 开发中天天用** |
| `pathlib` | 路径操作，比老的 `os.path` 好用 |
| `datetime` | 时间处理 |
| `re` | 正则表达式 |
| `collections` | 增强的数据结构 |
| `random` | 随机数 |
| `csv` | CSV 读写 |

### 可能卡在哪

**`ModuleNotFoundError: No module named 'xxx'`**

两种情况：

1. **是第三方库**，你还没装。U0.4 会学怎么用 uv 装。现阶段可以先 `pip3 install 包名`。
2. **是你自己的文件**，但路径不对。Python 找模块的顺序是：当前目录 → 已安装的包目录。

**自己的文件名和标准库重名**

比如你建了个 `json.py`，然后 `import json` 会导入你自己的文件，导致各种诡异错误。**不要用标准库的名字给自己的文件命名**：`json.py`、`random.py`、`time.py`、`test.py` 都要避开。

### 背后的逻辑

**`import` 到底做了什么？**

1. 在 `sys.path` 列出的目录里找这个模块
2. 找到后**执行整个模块文件**（所以模块顶层的代码会跑一遍）
3. 把模块对象绑定到你的命名空间

第 2 点很重要——这就是为什么你会在很多 Python 文件末尾看到：

```python
if __name__ == "__main__":
    main()
```

它的意思是「只有当这个文件被直接运行时才执行 main()，被 import 时不执行」。因为 `__name__` 这个变量，在直接运行时是 `"__main__"`，被导入时是模块名。

## 第 6 周 · 单元测试

对应 CS50P Week 5。这周先了解概念，U0.7 会深入。

### 核心概念

测试就是「写代码来验证代码」。

```python
def 加(a, b):
    return a + b

def test_加():
    assert 加(1, 2) == 3
    assert 加(-1, 1) == 0
    assert 加(0, 0) == 0
```

`assert 条件` 的意思是「如果条件为假就报错」。

### 背后的逻辑

为什么要写测试？三个理由，重要性递增：

1. 验证代码是对的
2. **改代码时不怕改坏**——改完跑一遍测试，全绿就说明没破坏原有功能
3. **测试是可执行的文档**——想知道一个函数怎么用，看它的测试比看注释准

第 2 点是你后面最需要的。到 S3 你会发现，AI Agent 的「测试」是一个更大的话题（叫评估），但底层思维是一样的：**没有自动化的验证，你就不敢改东西。**

## 第 7 周 · 文件读写

对应 CS50P Week 6。

### 核心概念

```python
# 读
with open("data.txt", "r", encoding="utf-8") as f:
    内容 = f.read()              # 全部读成一个字符串

with open("data.txt", "r", encoding="utf-8") as f:
    for 行 in f:                 # 一行一行读，省内存
        print(行.strip())        # strip() 去掉行尾换行符

# 写
with open("out.txt", "w", encoding="utf-8") as f:
    f.write("内容\n")

# 追加
with open("out.txt", "a", encoding="utf-8") as f:
    f.write("再加一行\n")
```

模式：`"r"` 读、`"w"` 写（**覆盖**）、`"a"` 追加。

### JSON 读写（后面天天用）

```python
import json

# 写
数据 = {"名字": "小王", "标签": ["家电", "家居"]}
with open("d.json", "w", encoding="utf-8") as f:
    json.dump(数据, f, ensure_ascii=False, indent=2)

# 读
with open("d.json", "r", encoding="utf-8") as f:
    数据 = json.load(f)
```

**`ensure_ascii=False` 一定要加**，否则中文会被存成 `中文` 这种转义形式。

### 可能卡在哪

**`FileNotFoundError`**

路径不对。**记住 Python 的相对路径是相对于「你运行命令时所在的目录」，不是相对于 `.py` 文件所在的目录。**

这是新手极常见的困惑。稳妥做法是用绝对路径，或者：

```python
from pathlib import Path
这个文件所在目录 = Path(__file__).parent
数据文件 = 这个文件所在目录 / "data.txt"
```

**中文乱码**

`open` 时永远显式写 `encoding="utf-8"`。不写的话 Python 会用系统默认编码，在不同机器上行为不一致。

**写完文件是空的**

忘了用 `with`，文件没关闭，内容还在缓冲区里。

```python
f = open("a.txt", "w")
f.write("内容")
# 忘了 f.close()，内容可能没落盘
```

**永远用 `with`**，它保证无论如何都会关闭文件。

### 背后的逻辑

**`with` 是什么？**

它叫「上下文管理器」。语义是：进入这个块时做点准备工作，离开这个块时做点清理工作，**哪怕中间抛异常也保证清理**。

```python
with open("a.txt") as f:
    出错的代码()          # 即使这里崩了
# f 也一定会被关闭
```

这个模式在你后面会大量遇到：数据库连接、网络会话、锁、临时目录，都用 `with`。看到 `with` 就想到「这东西用完需要收尾」。

## 数据结构：四种容器

CS50P 分散在各周讲，这里集中说，因为**选错容器是新手最常见的性能和逻辑问题来源**。

| 容器 | 写法 | 特点 | 什么时候用 |
|---|---|---|---|
| **list** 列表 | `[1, 2, 3]` | 有序、可改、可重复 | 一串东西，在乎顺序 |
| **dict** 字典 | `{"名": "王", "岁": 28}` | 键值对，按键查极快 | 有名字的数据、查表 |
| **set** 集合 | `{1, 2, 3}` | 无序、自动去重、查成员极快 | 去重、判断「在不在里面」 |
| **tuple** 元组 | `(1, 2, 3)` | 有序、**不可改** | 固定不变的一组值、当字典的键 |

### 关键差异：查找速度

```python
名单 = ["a", "b", ..., "z"]         # list
if "z" in 名单:                     # 从头找到尾，慢

名单 = {"a", "b", ..., "z"}         # set
if "z" in 名单:                     # 直接算出位置，快
```

列表里判断「在不在」要挨个比对，元素越多越慢。集合和字典用哈希表，不管多少元素都是一步到位。

**实践建议**：如果你要反复判断「某个东西在不在这堆里」，用 set 而不是 list。

### 可能卡在哪

**修改列表时意外改了另一个**

```python
a = [1, 2, 3]
b = a                # 这不是复制！b 和 a 指向同一个列表
b.append(4)
print(a)             # [1, 2, 3, 4]，a 也变了
```

`=` 只是给同一个对象贴第二个标签。要真复制：

```python
b = a.copy()         # 或者 b = list(a)
```

**可变默认参数**

```python
def 添加(项, 列表=[]):        # 陷阱！
    列表.append(项)
    return 列表

添加(1)      # [1]
添加(2)      # [1, 2]  ← 不是期望的 [2]
```

因为默认值 `[]` 只在函数定义时创建一次，之后一直复用同一个列表。

**正确写法**：

```python
def 添加(项, 列表=None):
    if 列表 is None:
        列表 = []
    列表.append(项)
    return 列表
```

**这个坑几乎每个 Python 新手都会踩一次**，记住它。

### 背后的逻辑

**为什么会有「同一个对象」的问题？**

Python 里变量存的不是值本身，而是**指向对象的引用**（可以理解为地址）。`b = a` 复制的是地址，不是内容。

判断一个类型是「可变」还是「不可变」：

- **可变**：list、dict、set —— 改它会影响所有引用它的变量
- **不可变**：int、float、str、tuple —— 「改」实际上是造了个新对象

```python
a = "abc"
b = a
b += "d"        # 造了个新字符串 "abcd" 赋给 b
print(a)        # 还是 "abc"，没被影响
```

理解这个区别，能解释你以后遇到的一大类「值莫名其妙变了」的 bug。
