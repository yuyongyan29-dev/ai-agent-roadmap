# U0.3 · Python：能读、能判、能调（6 小时）

**这个单元解决什么问题**

这份计划里的 Python 代码几乎都由 agent 写。**但 agent 写出来的东西你得看得懂、判得出对错、出了问题调得动**，否则到 S2 你的 Agent「有时对有时错」时，你和它都不知道该改哪里。

这个单元不教你「写」Python，教你三件事：

- **能读**：看一段 30 行的代码，说出它在做什么、输出是什么
- **能判**：agent 写完，你能看出它有没有偷懒、有没有埋雷
- **能调**：报错了，你能从 traceback 找到真正出错的那一行——**这一节是全单元的重心**

**学完你能做到**：让 agent 写一个读 CSV、分组统计、输出 JSON 的脚本，逐段验收，然后在它埋的 bug 里找出问题。

### 可能卡在哪

**`command not found: python3`**

macOS 可能没预装。用 U0.1 装好的 brew：

```bash
brew install python@3.13
```

**输入 `python` 报错，`python3` 才行**

历史遗留。Python 2 和 3 语法不兼容，为了不搞混，很多系统上 `python` 指向 2.x 或者干脆不存在。**你永远用 `python3`**。到 U0.4 学会 uv 之后，用 `uv run` 就不用管这个了。

**VS Code 右下角提示「选择解释器」**

点它，选带 `3.13` 之类版本号的那个。这是在告诉 VS Code「用哪个 Python 跑我的代码」。

**`print("你好")` 报 `SyntaxError: invalid character '（'`**

你用了中文标点。**Python 只认英文半角的 `(` `)` `,` `"` `:`。** 中文输入法下打出来的 `（` `，` `：` 全部不行。这是零基础第一周最高频的报错，看到 `invalid character` 就去检查标点。

VS Code 里中文标点和英文标点长得很像，一个快速判别法：把光标停在那个符号上，看它占一格还是两格宽——中文标点占两格。

### 背后的逻辑

Python 是**解释型语言**。你写的 `.py` 文件不需要先编译成可执行程序，而是由一个叫「解释器」的程序（就是 `python3` 这个命令）逐行读取并执行。

这带来两个后果，你后面会反复感受到：

- **好处**：改完立刻能跑，不用等编译
- **代价**：错误往往要跑到那一行才暴露。你在第 50 行写错了变量名，前 49 行照样执行，跑到第 50 行才崩

这就是为什么 Python 项目特别依赖测试和类型检查——它们把「跑到才发现」提前到「写的时候就发现」。U0.4 学类型注解、U0.7 学测试，都是在补这个短板。

## 步骤 1 · 读懂一段代码：变量、函数、条件、循环（1 小时）

### 这一步在做什么

一次性认识 Python 最常见的四样东西。**不是背语法，是练「看到代码能说出它在干什么」。**

### 先读，再跑

新建 `step1.py`，把下面这段**看一遍，在纸上写下你预测的输出**，然后再跑：

```python
# 变量：给数据起名字，不用声明类型
orders = [1200, 300, 3000, 800, 450, 5000]


def grade(amount):
    """按金额分档。分支从上往下判断，命中一条就不再往下，所以要从严到宽排。"""
    if amount >= 3000:
        return "大额"
    elif amount >= 1000:
        return "中额"
    else:
        return "小额"


# for 循环：对列表里每个元素做一遍
for amount in orders:
    print(amount, grade(amount))

# 列表推导式：从一个列表造另一个列表，一行搞定
big = [x for x in orders if x >= 1000]
print(len(big), "笔大于等于 1000")

# f-string：把变量拼进字符串，冒号后面是格式
total = sum(orders)
print(f"合计 {total}，均值 {total / len(orders):.2f}")
```

```bash
python3 step1.py
```

你应该看到：

```
1200 中额
300 小额
3000 大额
800 小额
450 小额
5000 大额
4 笔大于等于 1000
合计 10750，均值 1791.67
```

**对照你的预测。** 哪一行猜错了，就把那一行连同代码贴给 agent：「解释为什么这行输出是 X，假设我没学过编程」。

### 动手改一次

把 `if amount >= 3000` 和 `elif amount >= 1000` 两行对调，再跑。所有大于 1000 的都变成「中额」了——**因为 `elif` 命中一条就不再往下判**。改回来。

这种「改一行看会怎样」是最快的学法。**你改的是 agent 以后会写的代码，你得知道它哪里一动就错。**

### 五个必须认识的东西

| 看到 | 它是 | 一句话 |
|---|---|---|
| `def 名字(参数):` | 定义函数 | 把一段逻辑打包起个名字，之后用名字调用 |
| `return` | 交还结果 | 和 `print` 不同：`print` 是显示给人看，`return` 是交给程序继续用。**函数忘了 `return` 会得到 `None`，这是最常见的 bug 之一** |
| `if / elif / else` | 分支 | 从上往下，命中即止 |
| `for x in 列表:` | 循环 | 对每个元素做一遍 |
| `[表达式 for x in 列表 if 条件]` | 列表推导式 | 读法从中间往两边：先 `for`（对每个），再 `if`（挑哪些），最后开头（变成什么） |

### 可能卡在哪

**`IndentationError` / `TabError`**

Python 用缩进表示从属关系。agent 写的代码通常不会错，**但你手改的时候容易错**：统一 4 个空格，不要 Tab。VS Code 里 `Cmd+Shift+P` → `Convert Indentation to Spaces`。

**`SyntaxError: invalid character '（'`**

你手改时用了中文标点。Python 只认英文的 `( ) , " :`。

**`NameError: name 'xxx' is not defined`**

拼写、大小写错了，或者用了还没赋值的变量。Python 严格区分大小写。

**`=` 和 `==`**

`=` 是赋值（把 5 存进 x），`==` 是比较（x 等于 5 吗）。写 `if x = 5:` 直接报语法错。

### 背后的逻辑

**Python 用缩进而不是花括号**，设计者的理由是：好代码本来就会缩进，那不如让缩进直接成为语法，杜绝「看起来在 if 里面其实不在」这类 bug。代价是你必须严格对齐。

**`for x in 列表` 不是计数循环，是「向对象要下一个，直到没有」。** 所以它能遍历列表、字符串、字典、文件——只要对象支持「给我下一个」。步骤 3 读大文件时你会直接用到这一点：`for line in f` 一行一行读，不会把整个文件读进内存。

## 步骤 2 · 容器与分组：agent 最容易选错的地方（1 小时）

### 这一步在做什么

Python 有四种装东西的容器。**agent 写代码时选错容器不会报错，只会在数据变多时慢一百倍**——这种问题只有你能在验收时看出来。

### 四种容器

| 容器 | 写法 | 特点 | 什么时候用 |
|---|---|---|---|
| **list** | `[1, 2, 3]` | 有序、可改、可重复 | 一串东西，在乎顺序 |
| **dict** | `{"name": "王", "age": 28}` | 键值对，按键查极快 | 有名字的数据、**分组**、查表 |
| **set** | `{1, 2, 3}` | 无序、自动去重、查成员极快 | 去重、判断「在不在」 |
| **tuple** | `(1, 2, 3)` | 有序、**不可改** | 固定的一组值 |

新建 `step2.py`，先预测再跑：

```python
row = {"order_id": 1001, "category": "家电", "amount": 1200}
print(row["category"])                 # 按键取值
print(row.get("city", "未知"))         # 键不存在时给默认值，而不是崩

# 用 dict 分组：这是综合项目的核心，也是 agent 写统计代码的固定套路
rows = [
    {"category": "家电", "amount": 1200},
    {"category": "家居", "amount": 300},
    {"category": "家电", "amount": 800},
]
groups = {}
for r in rows:
    c = r["category"]
    if c not in groups:        # 第一次见到这个分类，先开一个空列表
        groups[c] = []
    groups[c].append(r["amount"])
print(groups)

# set 去重
print(set(["家电", "家居", "家电"]))
```

```
家电
未知
{'家电': [1200, 800], '家居': [300]}
{'家电', '家居'}
```

最后一行两个元素的顺序可能和你的不一样。**set 是无序的，这是正常的。**

**`row.get(键, 默认值)` 你后面天天见。** `row["city"]` 在键不存在时会抛 `KeyError` 让程序崩，`get` 给一个兜底。

### 选错容器的代价：自己量一次

在终端里跑这两条：

```bash
python3 -m timeit -s "data = list(range(100000))" "99999 in data"
python3 -m timeit -s "data = set(range(100000))" "99999 in data"
```

我这台机器上：

```
500 loops, best of 5: 480 usec per loop
20000000 loops, best of 5: 10.7 nsec per loop
```

**差了四万多倍。** 把 `100000` 改成 `1000` 再跑，list 那条快了约 100 倍，set 那条几乎没变。这就是 O(n) 和 O(1) 的区别：**list 会随数据变大而变慢，set 不会。**

### 复杂度：三个词够用

| 记号 | 数据翻倍时 | 典型操作 |
|---|---|---|
| `O(1)` | 耗时不变 | dict / set 的查找、list 按下标取 |
| `O(n)` | 耗时翻倍 | list 的 `in`、遍历一遍 |
| `O(n²)` | 耗时四倍 | 双层循环，**或者「循环里套一个 list 的 `in`」** |

**验收 agent 代码时的条件反射**：看到 `if x in 某个东西`，先看那个东西是不是 list。是的话问自己「它会不会变大」。会的话让 agent 改成 set。

```python
# agent 常写的 O(n²)：外层 n 次，每次 `in list_b` 又是 n 次
common = [a for a in list_a if a in list_b]

# 改一行：被搜的那个转成 set
set_b = set(list_b)
common = [a for a in list_a if a in set_b]
```

### 可能卡在哪

**修改列表时意外改了另一个**

```python
a = [1, 2, 3]
b = a            # 这不是复制，是给同一个列表贴第二个标签
b.append(4)
print(a)         # [1, 2, 3, 4]
```

要真复制：`b = a.copy()`。**这个坑 agent 也会踩**，看到 `b = a` 后面跟着 `b.append` 要警惕。

**可变默认参数**

```python
def add_item(item, items=[]):    # 默认的空列表只创建一次，所有调用共用
    items.append(item)
    return items

print(add_item(1))    # [1]
print(add_item(2))    # [1, 2]  ← 不是 [2]
```

正确写法是默认值用 `None`，函数里再造新列表。**这是 agent 写出来能跑、但埋雷的典型代码**，亲自跑一遍上面那段记住它。

**边遍历边删**

```python
numbers = [2, 4, 6, 8]
for x in numbers:
    if x % 2 == 0:
        numbers.remove(x)
print(numbers)        # [4, 8]，四个偶数只删掉两个
```

删除让后面的元素前移，遍历下标照走，于是每删一个跳过一个。**不报错，结果是错的。** 正确做法是造新列表：`[x for x in numbers if x % 2 != 0]`。

### 背后的逻辑

**dict 和 set 查找是 O(1)，因为它们是哈希表**：存的时候用哈希函数把元素算成一个数字，直接决定放哪一格；查的时候再算一次直接跳过去。不管 10 个还是 1000 万个元素都是「算一次，跳一次」。这也解释了为什么 set 无序、为什么 list 不能当 dict 的键（能改的东西哈希值会变）。

**「同一个对象」的问题**来自 Python 变量存的是引用不是值。`b = a` 复制的是地址。list / dict / set 可变，改它影响所有引用；int / str / tuple 不可变，「改」其实是造新对象。

## 步骤 3 · 文件、JSON、CSV、异常：脏数据怎么处理（1 小时）

### 这一步在做什么

真实数据一定有脏行。**agent 写的读文件代码，默认是「一行坏了整个程序崩」**——这是你验收时最该盯的地方。

### 先读，再跑

新建 `step3.py`：

```python
import csv
import json

# with 保证文件用完一定关闭，哪怕中间出错
with open("sales.csv", "r", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)       # 每行读成一个 dict，键是表头
    first = next(reader)
print(first)

# 注意：CSV 里所有值都是字符串，'1200' 不是 1200
print(type(first["amount"]))

# 要算数必须转类型
with open("sales.csv", "r", encoding="utf-8", newline="") as f:
    total = sum(float(row["amount"]) for row in csv.DictReader(f))
print(total)

# JSON 写：ensure_ascii=False 让中文原样落盘，indent=2 让人能读
with open("demo.json", "w", encoding="utf-8") as f:
    json.dump({"total": total, "note": "全部 20 单"}, f, ensure_ascii=False, indent=2)
```

```
{'order_id': '1001', 'category': '家电', 'amount': '1200', 'city': '北京'}
<class 'str'>
29200.0
```

`cat demo.json` 看一眼，中文应该是原样的。**把 `ensure_ascii=False` 删掉再跑一次**，中文变成 `\u5168` 这种转义——技术上没错，排查问题时你会很难受。agent 经常忘加这个参数。



### 异常处理：只兜你预料得到的

```python
def parse_amount(text):
    """转 float，转不了返回 None，让调用方决定怎么办。"""
    try:
        return float(text)
    except ValueError:        # 只捕获「转不了数字」，别的错误照样往上抛
        return None
```

**判断标准一句话**：你能写出「捕获之后要做什么」，才该捕获。写不出来（只能 `pass`）就让它崩。

**最糟糕的代码是这样的，agent 偶尔会写：**

```python
try:
    do_everything()
except:          # 吞掉一切，包括 Ctrl+C
    pass         # 什么都不做
```

它让 bug 静默发生。**验收时看到光秃秃的 `except:` 或者 `except Exception: pass`，直接让它改。**

### 可能卡在哪

**`FileNotFoundError`**

Python 的相对路径是相对于「你运行命令时所在的目录」，不是脚本所在目录。在 `py-basics` 里跑能找到，`cd ..` 再跑就找不到。稳妥写法是 `Path(__file__).parent / "sales.csv"`。**亲手撞一次**：`cd ..` 后跑 `python3 py-basics/ex3.py` 看它崩，再让 agent 改成 `Path(__file__)` 的写法。

**为什么不用 `line.split(",")` 切 CSV**

字段里带逗号就全错位了（`"电视机, 65寸"`）。CSV 是有规范的格式（引号、转义、换行），**用标准库，别自己切。** 这个原则以后反复用：看起来简单的格式，先查有没有标准库。

**`json.dump` 报 `not JSON serializable`**

### 背后的逻辑

**`with` 是上下文管理器**：进入时准备，离开时清理，哪怕中间抛异常也保证清理。数据库连接、HTTP 会话、锁，后面全是 `with`。看到 `with` 就想到「这东西用完要收尾」。

**Python 偏好 EAFP**（先做，出错再处理）而不是 LBYL（先检查再做），因为「检查」和「使用」之间可能有变化，而且大多数时候不会出错，`try` 在不出错时几乎零开销。

```python

def load_amounts(path):
    """读出所有金额，返回一个 list。"""
    amounts = []

    return sum(numbers) / len(numbers)
```

### 第一步：读报错，三个动作

**动作一：先看最后一行。** 它是错误类型和描述，信息密度最高。

```
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

翻译：`+` 不支持「整数 加 字符串」。

常见错误类型对照：

| 错误类型 | 意思 | 典型原因 |
|---|---|---|
| `SyntaxError` | 语法写错了 | 中文标点、少冒号、括号没配对 |
| `IndentationError` | 缩进错了 | 该缩没缩，或缩进不一致 |
| `NameError` | 用了不存在的名字 | 拼写错、大小写错、变量还没赋值 |
| `TypeError` | 类型不对 | 拿字符串当数字算、给函数传错参数个数 |
| `ValueError` | 类型对但值不行 | `int("abc")` |
| `KeyError` | 字典里没这个键 | 键名拼错、数据里本来就没有 |
| `IndexError` | 下标越界 | 列表只有 3 个却取第 5 个 |
| `AttributeError` | 对象没这个方法 | 对 None 调方法（最常见） |
| `FileNotFoundError` | 文件不存在 | 路径不对 |

**动作二：从下往上读调用链。** `most recent call last` 就是提示你「最近的调用在最后」。

```
main()              ← 第 27 行调用了 main
  average(amounts)  ← 第 23 行，main 里调用了 average
    sum(numbers)    ← 第 18 行，average 里炸了
```

**最底下那层是崩的地方，往上是「谁把它调到这儿的」。**

**动作三：分清「报错的位置」和「bug 的位置」。**

**这是新手和熟手最大的差别。** 这个例子里报错在 `average` 第 18 行，但 `average` 一点问题都没有——它拿到了脏数据。**真正的 bug 在 `load_amounts` 第 12 行**：CSV 读出来全是字符串，忘了转 `float`。

**报错位置是「毒发的地方」，bug 位置是「下毒的地方」，中间可能隔着好几层。** 顺着调用链往上找「这个坏数据是谁给的」，才是正确的排查路径。

### 第二步：三种定位手段，从轻到重

**手段一：print 大法**（80% 的情况够用）

在你怀疑的地方打两样东西：**值和类型**。

```python
def average(numbers):
    print("DEBUG numbers[:3] =", numbers[:3])       # 前几个长什么样
    print("DEBUG type =", type(numbers[0]))         # 是什么类型

```

```
DEBUG type = <class 'str'>
```

**看到引号了吗？** `'1200'` 带引号就是字符串。找到了。

**打 print 的三条经验**：

- **打值，也打类型。** 一半的 bug 是类型不对，光看值看不出 `'1200'` 和 `1200` 的区别。用 `repr()` 或者 f-string 的 `!r` 能让引号显出来。
- **前缀加个 `DEBUG`。** 好搜、好删。收尾时 `grep -n DEBUG *.py` 一次清干净。
- **打在「怀疑的数据刚生出来的地方」和「它出问题的地方」，两头夹。** 中间一分为二地找，比一行行看快得多。

**手段二：`breakpoint()`**（想看更多变量、想边看边试的时候）

### 第三步：VS Code 图形化调试

pdb 在服务器上很有用，但你日常在 VS Code 里，**图形化断点更直观**。

3. 按 `F5`，第一次会让你选调试配置，选 **Python Debugger** → **Python File**
4. 程序跑到第 18 行停住，那一行被高亮

停住之后，看这几个地方：

| 位置 | 你能看到什么 |
|---|---|
| 左侧 **变量 / VARIABLES** 面板 | 当前所有变量的名字、值、类型。**展开 `numbers` 能直接看到每个元素带不带引号** |
| 左侧 **调用堆栈 / CALL STACK** 面板 | 现在处在哪一层。**点上面一层，变量面板立刻切到那一层的上下文**——等价于 pdb 的 `u`，但更好用 |

#### 参考答案（先自己修完再看）

```python
def load_amounts(path):
    """读出所有金额，返回一个 list。

    CSV 里所有值都是字符串，这里必须转成 float，
    否则 sum() 会在下游炸，而且报错位置在 average 里，很误导。
    """
    amounts = []
    with open(path, "r", encoding="utf-8", newline="") as f:
        for row in csv.DictReader(f):
            amounts.append(float(row["amount"]))     # 加了 float
    return amounts
```

### 可能卡在哪

**报错里全是看不懂的库文件路径**

比如一长串 `site-packages/httpx/...`。**在调用链里从下往上找第一个是「你自己写的文件」的那一层**，那才是你的入口。库内部的栈帧通常不是你的问题。

**`AttributeError: 'NoneType' object has no attribute 'xxx'`**

**这个报错单独拎出来说，因为它太常见了。** 它的意思永远是：某个变量是 `None`，你在对 `None` 调方法。

而 `None` 从哪来？**九成是某个函数忘了写 `return`**（回去看步骤 1 的「背后的逻辑」），或者 `dict.get()` 没取到值。

排查方法：顺着调用链往上，找那个变量是谁给的，去看那个函数最后有没有 `return`。

**F5 之后弹出一堆配置选项不知道选哪个**

选 **Python Debugger** → **Python File**（当前文件）。VS Code 会在 `.vscode/launch.json` 里记下来，下次直接 F5。

**断点点了不生效，程序直接跑完**

两个常见原因：断点打在了一段根本不会执行的代码上（比如某个 `if` 分支没进去）；或者你按的是右上角的「运行」三角形而不是 F5——**运行不带调试器，断点当然不生效**。三角形旁边的下拉箭头里有「调试 Python 文件」。

### 背后的逻辑

**为什么 Python 的报错叫「Traceback」而不是「Error Message」？**

因为它给的不是一条消息，是一条**路径**。Python 在每次函数调用时都把「我从哪来」压进一个叫「调用栈」的结构里，出错时把整个栈原样倒出来。

**这个思路贯穿你后面所有课程**：

- U0.7 测试失败时，pytest 给的也是 traceback，读法一模一样
- S3 的可观测性（Langfuse、OpenTelemetry）本质上是「分布式的 traceback」——一次 Agent 调用跨了模型、工具、数据库，trace 让你看到它在哪一环出的问题
- S4 排查线上故障，第一件事永远是「把日志里的 traceback 找出来，从下往上读」

**所以这一节不是「Python 的调试技巧」，是「排查问题」这件事本身的入门。** 现在在 20 行的脚本上练熟，后面在跨五个服务的 Agent 系统上才有得用。

**另一个观念：让 bug 早点崩。**

`load_amounts` 那个 bug 之所以难找，是因为脏数据被「安静地」存进了 list，跑出去两层才炸。如果在读的时候就转 `float`，它会**在第 12 行、拿到坏数据的那一瞬间**就崩，报错位置和 bug 位置重合，一眼就找到。

这就是 U0.4 要教类型注解和 Pydantic 的原因：**在数据进门的地方就校验，让错误在离源头最近的地方暴露。**

### 你读懂：四个「不是新手写法」的地方

1. **`read_rows` 返回两样东西**（有效行、跳过说明），而不是在里面直接 `print`。「读数据」和「怎么告诉用户」分开，以后改成写日志或返回给前端时不用动这个函数。这叫「决定权交给调用方」。
2. **报告走 `stderr`，结果走 `stdout`。** 这样 `python3 csv_stats.py x.csv > result.txt` 只留干净输出。
3. **`summarize` 里有 `sorted`。** 输出顺序稳定，`diff` 才有意义。
4. **`parse_amount` 捕获 `(ValueError, TypeError)` 两种。** `float(None)` 抛的是 `TypeError`，字段缺失和字段为空都会发生。
