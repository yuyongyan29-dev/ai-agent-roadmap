# U0.0 · 你的工作方式：agent 写、你审、你验（4 小时）

**这个单元解决什么问题**

这份计划里的代码，绝大部分不是你敲的，是编码 agent 敲的。**这一点从第一天就定下来**，而不是先苦学六周语法再告诉你「其实可以让 AI 写」。

但「让 AI 写」有两种做法。一种是把需求丢过去，跑得通就往下走，出了问题再丢回去让它修。另一种是每次交给它三样东西——目标、约束、验收命令——它写完你审 diff、你跑验收、你把不懂的地方问到懂。**前一种做法在 S2 会撞墙**：你的 Agent 开始「有时对有时错」，你分不清是 prompt、工具还是代码的问题，而 agent 也分不清。后一种做法就是这个单元要建立的。

**学完你能做到**：装好 Claude Code，用「agent 写、你审、你验」的三段式完成一个小任务，知道三个保命操作，知道什么不能交给它。

**这个单元只装 Claude Code。** Codex、worktree、多 agent 并行、双会话 review 这些深的东西在 U0.10，那时你手上已经有一个真实项目可以练。

---

## 步骤 1 · 装 Claude Code（0.5 小时）

### 这一步在做什么

把你接下来 39 周的主力工具装上。它是一个命令行程序，在终端里跑。

### 怎么做

打开终端（macOS：`Command + 空格`，输入「终端」回车。Windows：按 [U0.1 开头的说明](U0.1-命令行与开发环境.md)装好 WSL2，用 Ubuntu 终端）。

去 [code.claude.com](https://code.claude.com/docs/en/setup) 的安装页，复制**当前显示**的那条安装命令。写这份文档时 macOS / Linux / WSL 上是：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

装完关掉终端重开一个，输入：

```bash
claude --version
```

看到版本号就装好了。然后：

```bash
claude
```

第一次会让你登录，按提示在浏览器里完成。回到终端看到一个输入框，就进来了。输入 `/exit` 退出。

### 可能卡在哪

**`command not found: claude`**

重开一个终端窗口再试。安装脚本改了配置文件，只对新开的终端生效。还不行就看安装脚本最后打印的提示，它会告诉你要把哪个目录加进 PATH。PATH 是什么，U0.1 步骤 7 会讲，现在先照做。

**登录后浏览器显示成功，终端没反应**

回到终端按一下回车。

**公司网络下装不上**

安装脚本要访问 GitHub 和 claude.ai。换手机热点试一次，能装上就说明是网络策略问题。

### 背后的逻辑

Claude Code 和你后面要学的所有 Agent 框架，底层是同一个循环：**读文件、跑命令、看结果、决定下一步。** U2.1 你会亲手把这个循环写出来，200 行以内。**从今天起你是这个循环的使用者，S2 之后你是它的设计者。**

## 步骤 2 · 第一次对话：只读，不写（0.5 小时）

### 这一步在做什么

让 agent 先给你讲这个仓库，你来判断它讲得对不对。**第一次接触就建立「它说的话要核对」的习惯。**

### 怎么做

```bash
cd ~/ai-agent-roadmap
claude --permission-mode plan
```

`--permission-mode plan` 是**只读模式**：它可以读文件、搜索，但不能改任何东西。状态栏会显示 `plan mode on`。

输入：

```
读一下这个仓库的 README.md 和 docs/开始.md，用五句话告诉我：
这是什么、给谁、分几个阶段、第一个阶段做什么、我下一步该打开哪个文件。
```

### 你验收

它回答的五句话，**对照 README 逐句核对**。阶段数对不对？第一阶段的名字对不对？它让你下一步打开的文件存在吗？

如果它说错了，告诉它「第 X 句和 README 不符，重新读」。**这就是你和 agent 关系的基本形态：它做，你核。**

### 可能卡在哪

**它开始改文件了**

确认状态栏有 `plan mode on`。没有的话按 `Shift+Tab` 切换，直到看到为止。

**它的回答很长，不是五句**

它没有严格遵守约束。这很常见。回一句「只要五句」。**约束要写在 prompt 里，不遵守就指出来**，不要将就。

### 背后的逻辑

只读模式存在的理由是：**「理解需求」和「动手改」要分开。** 直接让它写，它会基于自己的猜测动手，你看到结果时它已经改了十个文件。U0.10 会把这展开成完整的「探索 → 计划 → 实现 → 提交」流程，现在先记住：**不确定的时候，先让它只读。**

## 步骤 3 · 三段式：agent 写、你审、你验（1.5 小时）

### 这一步在做什么

**这是本单元的核心，也是之后每个单元「怎么做」那一段的固定形态。**

每次交给 agent 一个任务，你给它三样东西：

| 你给的 | 是什么 | 例子 |
|---|---|---|
| **目标** | 要做出什么 | 「写一个脚本，读 sales.csv，按 category 分组算均值」 |
| **约束** | 不许做什么、必须怎么做 | 「只用标准库，中文注释，不要改别的文件」 |
| **验收命令** | 跑什么、应该看到什么 | 「跑 `python3 stats.py` 应该输出 `家电 1000.0`」 |

**第三样最重要。** 没有验收命令，agent 在「看起来做完了」的时候就会停，而你成了唯一的验证者。有了它，agent 会自己跑、自己修到通过。

### 怎么做

先退出 plan mode（`Shift+Tab` 直到状态栏提示消失），或者重新 `claude` 进入。

**让 agent 做：**

```
在 s0-foundation/hello/ 目录下建一个 greet.py。
要求：
- 定义一个函数 greet(name)，返回 "你好，{name}"
- 文件末尾调用它三次，名字分别是 小王、小李、小张，每次 print 结果
- 英文标识符，中文注释，只用标准库
- 不要创建或修改这个目录之外的任何文件
验收：python3 s0-foundation/hello/greet.py 应该输出三行，第一行是「你好，小王」。
写完自己跑一遍验收，通过了再告诉我。
```

它会创建文件、跑命令、报告结果。**在它报告之前不要打断。**

**你审：**

它做完后，看它改了什么。两种方式：

```
/diff
```

或者在另一个终端窗口：

```bash
cd ~/ai-agent-roadmap && git status && git diff
```

（`git` 命令 U0.2 才学，现在先照敲，看输出里有没有它不该碰的文件。）

审的时候只问三个问题：

1. **它碰的文件是不是只有我允许的那些？** 多碰了一个就问它为什么。
2. **代码里有没有我看不懂的行？** 有就进入下一步「你读懂」。
3. **它有没有偷偷放宽我的约束？** 比如我说只用标准库，它 import 了别的。

**你验：**

自己跑一遍验收命令，不要只信它的报告：

```bash
python3 s0-foundation/hello/greet.py
```

三行输出，第一行「你好，小王」。**它说通过和你看到通过，是两件事。**

**你读懂：**

对着 `greet.py`，你必须能回答：

1. `def greet(name):` 这一行在做什么？
2. `return` 和 `print` 有什么区别？为什么函数里用 `return`、末尾用 `print`？
3. 如果把三次调用删掉，运行时会输出什么？

答不上来就问它：

```
逐行解释 greet.py，每行一句话，假设我完全没学过编程。
```

**读懂了再往下走。** 这三个问题 U0.3 会系统讲，现在你只需要能复述它的解释。

### 可能卡在哪

**它问我「要不要继续」之类的问题**

它在请求权限。看清楚它要做什么，是你允许范围内的就同意。**不要养成不看就按确认的习惯**——U0.10 会教你怎么把常用命令加进白名单，让它不再问，但那是划清边界之后的事。

**它一次写了好几个文件**

约束没写清，或者它没遵守。回一句「我只要 greet.py 一个文件，把多余的删掉」。然后把这条经验记下来：**下次约束里写「只建这一个文件」。**

**验收通过了，但我看代码觉得别扭**

比如它写了 20 行做一件 5 行的事。告诉它「这段能不能更简单」。**验收通过是底线，不是终点。** 但也不要在风格上无限纠缠，能跑、能读懂、没多余文件，就过。

**我看不懂它的解释**

换一种问法：「用一个生活中的比喻解释」或者「把这段代码改成最简单的写法，然后解释」。还不懂就先放着，U0.3 学完回来看。**不要假装懂了。**

### 背后的逻辑

这三段对应软件工程里三个不同的活：**实现、审查、测试。** 在传统团队里这是三个人。在 vibe coding 里实现交给了 agent，**审查和测试没有交出去，也交不出去**——因为「什么算对」只有你知道。

2026 年的招聘 JD 里，AI 编码工具已经是硬要求，同时 debug、code review、系统设计一项没少。**行业淘汰的是「只会敲代码」，不是「会看代码」。** 这个单元建立的三段式，练的正是没被淘汰的那两项。

## 步骤 4 · 写一份最小的项目说明（0.5 小时）

### 这一步在做什么

在仓库根目录放一个 `CLAUDE.md`。agent 每次启动都会读它，**你不用每次重复说规矩。**

### 怎么做

**让 agent 做：**

```
在仓库根目录创建 CLAUDE.md，内容只有下面这些，不要多加：

# CLAUDE.md
## 这是什么
AI Agent 学习路线的代码仓库，学习者按 units/ 下的单元逐个完成。
## 规矩
- 代码放在 s0-foundation/、s1-llm/ 这类阶段目录下，不要动 units/ 和 docs/ 里的教程文档
- 英文标识符，中文注释
- 每次只做我要求的事，不要顺手重构或改别的文件
- 写完先自己跑验收命令，通过了再报告
- 我要求解释时，假设我是零基础，逐行解释，不要跳
```

**你审、你验：**

```
/context
```

输出里应该能看到 `CLAUDE.md` 被加载了。然后 `/clear` 清空会话，随便问一句「这个仓库的规矩是什么」，它应该能复述出来。

### 可能卡在哪

**它在 CLAUDE.md 里加了一堆别的**

agent 喜欢「顺手完善」。删掉，只留上面那些。**检验每一行的标准是：删掉这行会让 agent 犯错吗？不会就删。** U0.10 会教你什么值得写进去。

### 背后的逻辑

CLAUDE.md 是你和 agent 之间的**长期契约**，对话是短期指令。规矩放契约里，任务放对话里。分开之后 `/clear` 就不心疼了——清掉的只是任务上下文，规矩还在。

## 步骤 5 · 三个保命操作（0.5 小时）

### 这一步在做什么

学三个动作，任何时候搞砸了都能退回来。**知道能退回去，你才敢让它大改。**

### 怎么做

**一、`/clear`：换任务就清空。**

现在就试：`/clear`，然后问它「刚才那个 greet.py 里的函数叫什么」。它不知道了。**这是对的**——上下文清空了，它不该知道。需要的话 `@s0-foundation/hello/greet.py` 重新引用。

**规矩**：换一个不相干的任务就 `/clear`。**同一个问题纠正它两次还不对，也 `/clear`**，然后写一个更好的 prompt 重来。一个干净的会话加一个好 prompt，几乎总是胜过一个长会话加一堆纠正。

**二、`Esc Esc`：回到上一个检查点。**

试一下：让它「把 greet.py 里的三个名字全改成英文」。做完后按两下 `Esc`，选择回退代码。文件恢复了。

每条 prompt 都会自动建一个检查点，可以回退对话、回退代码、或者两者都退。**注意它只跟踪 agent 用编辑工具做的改动，agent 跑的 shell 命令造成的改动不在内。** 所以它不能替代 git。

**三、git：真正的兜底。**

```bash
git restore .
```

这一条把工作区所有未提交的改动全部丢弃，回到上次提交的状态。**U0.2 之前你只需要知道有这一条**，U0.2 学完你会知道它为什么有效，U0.12 会教你连提交了的都能救回来。

### 可能卡在哪

**`Esc Esc` 没反应**

要在 agent 空闲、等你输入的时候按。它正在干活时按 `Esc` 一次是打断它。

**`git restore .` 提示 not a git repository**

你不在仓库目录里。`cd ~/ai-agent-roadmap` 再试。

### 背后的逻辑

三个操作对应三个层次：**对话层（`/clear`）、agent 编辑层（`Esc Esc`）、文件系统层（git）。** 越往下越可靠，越往下也越粗暴。日常用上面两个，出大事用最下面那个。

## 步骤 6 · 什么不能交给它（0.5 小时）

### 这一步在做什么

划清界线。**这条线随你的能力变化，但现在必须严格。**

### S0 和 S1 阶段的规矩

**agent 可以写，但每一段它写的代码，你必须能口头解释它在做什么、为什么这样写。** 看不懂就让它解释到你懂；解释了还看不懂，就让它改成更简单的写法。

一个自检，每次 agent 写完一段代码问自己：

> 如果现在断网，这段代码报错了，我能不能自己修？

**答不上来就是没看懂**，回去问，直到能答上来。

### 永远是你的三件事

**架构决策。** 用不用多 Agent、选哪个框架、工具怎么切分。这些是面试要问的，也是 agent 给不了正确答案的——它不知道你的约束。

**取舍的理由。** 它可以实现，但「为什么这样而不是那样」必须是你的判断。

**验收标准。** 什么算做对了，只能你定。**你定不出验收标准的任务，不要交给它。**

### 背后的逻辑

这三件事的共同点是：**它们决定了「做什么」，而 agent 只负责「怎么做」。** 把「做什么」也交出去的人，最后手里什么都不剩。

## 完成判据

- [ ] `claude --version` 有输出，登录成功
- [ ] 用 plan mode 让它讲过一遍仓库，并且**核对出至少一处它说得不准的地方**（如果一处都没有，换个更细的问题再问一次，比如「S0 有几个单元、各多少小时」）
- [ ] `greet.py` 三段式走完：审过 diff、自己跑过验收、三个理解问题能口头回答
- [ ] `CLAUDE.md` 存在，`/context` 能看到它被加载
- [ ] `/clear`、`Esc Esc`、`git restore .` 各亲手用过一次
- [ ] 在单元笔记里写下：这个单元里 agent 有没有做过你没让它做的事？是什么？你下次的约束怎么写？

**理解检查**（不看资料）

1. 交给 agent 一个任务要给它哪三样东西？哪一样最重要，为什么？
2. 「它说通过」和「你看到通过」为什么是两件事？
3. 什么时候该 `/clear`？纠正两次还不对为什么不该继续纠正？
4. `Esc Esc` 和 `git restore .` 各能退回什么、不能退回什么？
5. S0 和 S1 阶段的规矩是什么？怎么自检？

## 这个单元之后

从 U0.1 开始，每个单元的「怎么做」都按这个三段式写：**让 agent 做 / 你验收 / 你读懂**。手敲不再是要求。

但有一个例外你现在就该知道：**U2.1「手写 Agent 循环」那 200 行，要求你亲手写。** 不这样做，你永远不知道 Claude Code 在替你做什么，也过不了禁用 AI 的编码面试。整份计划只有那一个单元这样要求。

U0.10 会把今天这四小时展开成完整的工作流：Codex 做交叉 review、权限白名单和沙箱、worktree 并行跑多个 agent、一个需求从提出到合并 PR 的 12 步。那时你手上有一个真实项目，练起来才有意义。
