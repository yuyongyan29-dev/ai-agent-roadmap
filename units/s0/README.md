## 每个单元怎么读

每个单元都按同一个结构写：

**每一步分四段** —— 这一步在做什么 / 怎么做 / 可能卡在哪 / 背后的逻辑。

「怎么做」你照着敲就行。「可能卡在哪」不要跳过，**里面写的都是你大概率会撞上的具体报错和解法**。「背后的逻辑」第一遍看不懂没关系，做完这一步再回头看，会突然通了。

**U0.11 修一处断裂**：U2.4、U4.2、U4.3、U4.7 四个单元都用了 Redis，U4.7 代码里直接写着 `redis.setex()`，但在此之前没有任何单元教过它。

**U0.10 和 U0.12 是一对**：前者讲怎么和编码 agent 协作，后者讲多个 agent 并行时 Git 怎么撑住。**U0.12 先学 reflog 再学别的**——你敢让 agent 大改代码的前提，是知道无论它干了什么都能退回去。

**U0.10 放在最后，但它定义的是你后面每一天的工作方式。** 它需要你先有一个真实的项目（U0.1–U0.9 做出来的 csvstats）才能练。

**顺序不能打乱。** 每个单元都依赖前面的：U0.4 的虚拟环境用到 U0.1 的 PATH 概念，U0.6 的自动文档来自 U0.4 的类型注解，U0.7 的依赖替换用 U0.6 的依赖注入，U0.9 的 compose 要连 U0.8 的数据库。

## 三个贯穿全阶段的纪律

**每一行代码你都要能口头解释。** 可以让 AI 解释给你听，但不能让它替你写完你不看。这条纪律只在 S0 和 S1 有效，S2 之后你有判断力了就可以放开用 AI 加速。

**判据没达到就不勾选。** 宁可一个单元拖一周，也不要虚勾往前赶。后面的单元建立在前面之上，欠的债会连本带利还。

**每天写代码比周末写一整天有效。** 编程是肌肉记忆，间隔重复胜过集中突击。哪怕每天只写 20 行。

## M0 里程碑验收清单

三周结束时，你的 `s0-foundation/csvstats/` 应该满足：

- [ ] README 写清楚这是什么、怎么装、怎么跑、有哪些端点
- [ ] `docker compose up` 一条命令起得来
- [ ] `uv run pytest` 全绿，覆盖率 70%+，**断网也能跑**
- [ ] `uv run ruff check src/` 零报错
- [ ] 全量类型注解，类型检查通过
- [ ] 数据持久化到 Postgres，重启不丢
- [ ] 没有任何密钥进了 git 历史
- [ ] 至少 15 个 commit，信息可读

**这个项目不是练习题。** 它是你后面所有 Agent 项目的骨架：S2 的 Agent 跑在这套结构上，S4 的部署用这套 Docker 配置。写完不要扔。
