## 每个单元怎么读

每个单元都按同一个结构写：

**每一步分四段** —— 这一步在做什么 / 怎么做 / 可能卡在哪 / 背后的逻辑。

**「怎么做」从 U0.1 起都是三段式：让 agent 做 / 你验收 / 你读懂。** 手敲不是要求。给 agent 的指令可以直接粘贴，验收命令你必须自己跑，「你读懂」的问题必须能口头回答。「可能卡在哪」不要跳过，**里面写的都是你大概率会撞上的具体报错和解法**，现在还多了一类：agent 写出来能跑但方向不对的信号。「背后的逻辑」第一遍看不懂没关系，做完这一步再回头看，会突然通了。

**U0.0 放最前面，因为它定义的是你之后每一天的工作方式。** 只装 Claude Code，不需要任何前置知识。U0.10 是它的完整版，放在最后，因为那时你手上有一个真实项目可以练 worktree 和多 agent 并行。

**U0.3 步骤 4「报错怎么读，bug 怎么找」是整个 S0 最重要的一节。** 它教读 traceback、print 调试、`breakpoint()`、`python3 -m pdb` 事后验尸、VS Code 断点与调用堆栈。**分清「报错的位置」和「bug 的位置」是新手和熟手最大的差别**，也是 vibe coding 时代人最不能交出去的能力。这一节用一个真 bug 让你亲手走一遍，然后让 agent 埋 bug 你来找。

**U0.11 修一处断裂**：U2.4、U4.2、U4.3、U4.7 四个单元都用了 Redis，U4.7 代码里直接写着 `redis.setex()`，但在此之前没有任何单元教过它。

**U0.10 和 U0.12 是一对**：前者讲怎么和编码 agent 协作，后者讲多个 agent 并行时 Git 怎么撑住。**U0.12 先学 reflog 再学别的**——你敢让 agent 大改代码的前提，是知道无论它干了什么都能退回去。

**顺序不能打乱。** 每个单元都依赖前面的：U0.4 的虚拟环境用到 U0.1 的 PATH 概念，U0.6 的自动文档来自 U0.4 的类型注解，U0.7 的依赖替换用 U0.6 的依赖注入，U0.9 的 compose 要连 U0.8 的数据库。

## 三个贯穿全阶段的纪律

**agent 写的每一段代码，你都要能口头解释。** 看不懂就让它解释到你懂，还不懂就让它改简单。自检只有一句：断网时这段代码报错了，你能不能自己修。这条纪律在 S0 和 S1 最严，S2 之后你有判断力了可以放松对细节的追问，但架构决策、取舍理由、验收标准永远是你的。

**判据没达到就不勾选。** 宁可一个单元拖一周，也不要虚勾往前赶。后面的单元建立在前面之上，欠的债会连本带利还。

**每天碰代码比周末碰一整天有效。** 读代码、审 diff、找 bug 都是肌肉记忆，间隔重复胜过集中突击。
