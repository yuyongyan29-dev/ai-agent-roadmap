# U0.1 · 命令行与开发环境（4 小时）

**这个单元解决什么问题**

你现在用电脑的方式是「看到图标，点它」。程序员用电脑的方式是「打字告诉电脑做什么」。这两种方式不是谁高级谁低级，而是后者能被记录、被重复、被组合——你今天敲的一串命令，明天可以让电脑自动跑一百遍。整个 AI Agent 领域的所有工具，几乎都只有命令行界面，没有图标可点。

**学完你能做到**：不碰访达（Finder），用纯打字的方式管理文件；装好后面 26 周要用的全部基础工具。

---

## Windows 用户先看这里

本教程的命令行部分按 macOS 写。**Windows 用户不要用 PowerShell 或 CMD 跟着做**，两者的命令和路径规则都不一样，你会在第一天就被一堆和教程无关的差异卡住。

正确做法是装 **WSL2**（Windows 内置的 Linux 子系统），之后本教程的所有命令、路径、工具都和 macOS 一致，后面 37 周不再有任何平台差异：

1. 以管理员身份打开 PowerShell，运行 `wsl --install`，重启。默认装的是 Ubuntu。
2. 开始菜单打开「Ubuntu」，设置一个 Linux 用户名和密码。**这个终端就是你接下来要用的「终端」。**
3. VS Code 装 `WSL` 扩展（Microsoft 官方，id `ms-vscode-remote.remote-wsl`），之后在 Ubuntu 终端里 `code .` 会自动以 WSL 模式打开 VS Code。
4. **仓库要 clone 在 Linux 这一侧**（比如 `~/ai-agent-roadmap`），不要放在 `/mnt/c/...` 下，否则文件读写会慢十倍以上，Docker 也会出问题。

装 Homebrew 那一步在 WSL 里同样可用（brew 官网首页的那条命令就是给 macOS 和 Linux 共用的）。也可以用 Ubuntu 自带的 `sudo apt install`，但为了和教程一致，建议还是 brew。

对应关系速查：

| 教程里写的 | 你在 WSL 里 |
|---|---|
| 「打开终端」 | 打开 Ubuntu |
| `/Users/you` | `/home/you` |
| `~/.zprofile`、`~/.zshrc` | `~/.bashrc`（Ubuntu 默认 shell 是 bash，不是 zsh；想一致可以 `sudo apt install zsh` 后 `chsh -s $(which zsh)`） |
| `Cmd+` 开头的快捷键 | `Ctrl+` |
| Docker Desktop | 同样装 Docker Desktop for Windows，设置里勾选 WSL2 集成 |

Linux 用户直接往下走，不需要任何调整。

## 步骤 1 · 打开终端，认识提示符

### 这一步在做什么

打开那个「打字告诉电脑做什么」的窗口。它叫「终端」。

### 怎么做

按 `Command + 空格`，输入 `终端`，回车。

会弹出一个白色或黑色的窗口，里面有一行字，大概长这样：

```
you@MacBook-Pro ~ %
```

光标在 `%` 后面闪。

### 这行字是什么意思

| 部分 | 含义 |
|---|---|
| `you` | 你的用户名。**本教程所有出现 `you` 的地方，都替换成你自己的** |
| `MacBook-Pro` | 你的电脑名 |
| `~` | **你现在站在哪个文件夹里**。`~` 代表你的主目录，也就是 `/Users/you` |
| `%` | 提示符，它后面就是你要打字的地方 |

这一整行叫「提示符」（prompt）。**每次敲完一条命令，它都会重新出现，代表电脑做完了，在等你的下一条指令。**

### 可能卡在哪

**看到的是 `$` 不是 `%`**。没问题，这只是不同 shell 的默认提示符。macOS 现在默认用 zsh，提示符是 `%`；老一点的 bash 是 `$`。不影响任何操作。

**窗口里有一堆看不懂的字**。可能是上次的残留。输入 `clear` 回车，清屏。

### 背后的逻辑

终端本身只是一个「显示文字的窗口」。真正干活的是它里面跑着的一个程序，叫 **shell**（外壳）。你打的每一行字，都是交给 shell 去解释和执行的。

为什么叫「外壳」？因为它是包在操作系统内核外面的一层。你不直接跟内核说话，你跟外壳说，外壳翻译给内核。

macOS 默认的 shell 是 **zsh**。你以后会看到有人说 bash，那是另一种 shell，语法基本相通。

## 步骤 2 · 装 Homebrew

### 这一步在做什么

装一个「软件商店」，但是是命令行版本的。以后你要装任何开发工具，都是一句 `brew install 工具名`，不用去官网找下载链接、下 dmg、拖进应用程序文件夹。

### 怎么做

打开浏览器访问 [brew.sh](https://brew.sh)，首页最显眼的位置有一行命令，长这样（**以官网当前显示的为准，不要照抄这里的**）：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

复制它，粘贴进终端，回车。

会发生这些事：

1. 提示你输入密码。**输入你的电脑开机密码**。注意：**打字的时候屏幕上什么都不会显示，连星号都没有**。这是正常的，不是键盘坏了。打完直接回车。
2. 显示一堆将要安装的目录，让你按回车确认。按回车。
3. 开始下载安装，大概 3 到 10 分钟，取决于网速。

**装完之后还有一步，很多人漏掉。** 安装脚本最后会打印几行以 `==> Next steps` 开头的提示，里面有两三行命令，长得像这样：

```bash
# 前两行把 brew 的环境设置追加进 .zprofile，这样以后每开一个新终端都会自动配好
echo >> /Users/you/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> /Users/you/.zprofile
# 第三行只作用于当前这个终端窗口，让设置马上生效，不用先关掉再开
eval "$(/opt/homebrew/bin/brew shellenv)"
```

**把这几行逐条复制粘贴执行。** 然后关掉终端窗口，重新打开一个。

### 验证成功

```bash
brew --version
```

看到 `Homebrew 4.x.x` 之类的输出就是成功了。

### 可能卡在哪

**`zsh: command not found: brew`**

这是最常见的问题，说明上面那个「Next steps」你没做，或者做了但没重开终端。

解法：先确认 brew 真的装上了：

```bash
ls /opt/homebrew/bin/brew
```

如果这条命令显示了路径，说明装上了，只是电脑「找不到」它。执行：

```bash
# 手动补上安装脚本 Next steps 里漏做的那步：把 brew 的目录加进 PATH
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
source ~/.zprofile     # 重新读一遍配置文件，省掉「关终端再开」这一步
brew --version         # 能打印版本号，就说明 PATH 里已经能找到 brew 了
```

如果 `ls` 那条报 `No such file or directory`，说明真的没装上，重新跑一遍安装命令。

**下载卡住不动，或者报 `Failed to connect to raw.githubusercontent.com`**

网络问题。Homebrew 的安装脚本和软件源都在国外。两个办法：挂代理，或者用国内镜像源（搜索「Homebrew 国内镜像」，中科大和清华都有，跟着它们的说明改一下源地址）。

**报错里有 `Permission denied`**

密码输错了，或者你的账号不是管理员。重来一遍，确认密码。

### 背后的逻辑

这里有两个概念值得搞懂，因为你后面会反复遇到。

**第一个：PATH。**

当你输入 `brew` 的时候，电脑怎么知道去哪里找这个程序？答案是它有一份「搜索路径清单」，叫 PATH。它会挨个去清单里的文件夹找有没有叫 `brew` 的东西。

你可以看看这份清单：

```bash
echo $PATH
```

输出是一串用冒号分隔的路径。Homebrew 装在 `/opt/homebrew/bin`，如果这个路径不在 PATH 里，电脑就找不到 brew，于是报 `command not found`。

上面那行 `eval "$(/opt/homebrew/bin/brew shellenv)"` 做的事，就是把 `/opt/homebrew/bin` 加进 PATH。

**以后你遇到任何 `command not found`，第一反应都应该是查 PATH。** 这个套路会救你很多次。

**第二个：为什么要写进 `.zprofile`。**

PATH 是内存里的东西，关掉终端就没了。`.zprofile` 是一个脚本文件，**每次你打开新终端，zsh 都会自动执行它一遍**。把设置 PATH 的命令写进去，就等于「每次开终端都自动配好」。

同类的文件还有 `.zshrc`。区别很细（一个是登录时执行，一个是每次开交互式 shell 时执行），现阶段你可以当成一回事。

## 步骤 3 · 用 brew 装三个工具

### 这一步在做什么

装齐后面 26 周的地基工具：版本管理、GitHub 命令行、Python 包管理。

### 怎么做

```bash
brew install git gh uv
```

一条命令装三个。等几分钟。

验证：

```bash
# 逐个确认装上没有：只要有版本号就算成功
# 哪一条报 command not found，就是那个工具没装上或者 PATH 没配好
git --version
gh --version
uv --version
```

三条都有版本号输出就成功了。

### 这三个各是什么

| 工具 | 是什么 | 你什么时候会用 |
|---|---|---|
| `git` | 版本管理。记录你的代码每一次改动，可以随时回到任何一个历史版本 | 每天。下一个单元 U0.2 专门讲它 |
| `gh` | GitHub 的官方命令行工具。建仓库、提 PR、看 issue 都不用开浏览器 | S3 做 CI 的时候会大量用 |
| `uv` | Python 的包管理器和环境管理器 | S0 之后每个 Python 项目 |

### 可能卡在哪

**`git --version` 显示的版本很老（比如 2.39）**

macOS 自带一个古董版 git。你刚装的新版在 `/opt/homebrew/bin/git`，系统自带的在 `/usr/bin/git`。PATH 里谁在前面就用谁。

查一下电脑实际在用哪个：

```bash
which git
```

如果显示 `/usr/bin/git`，说明系统自带的排在前面。这在现阶段完全不影响你学习，可以先不管。想改的话，确保 `/opt/homebrew/bin` 在 PATH 里排在 `/usr/bin` 前面。

**下载慢**。同上，换镜像源。

### 背后的逻辑

`brew install` 做的事是：去它的软件源查这个包的信息 → 下载预编译好的二进制文件 → 解压到 `/opt/homebrew/Cellar/` → 在 `/opt/homebrew/bin/` 里建一个软链接指过去。

**软链接**就是快捷方式。这样设计的好处是：`/opt/homebrew/bin` 一个目录进 PATH，所有 brew 装的东西就都能被找到了。

`which 命令名` 这条命令你要记住，它告诉你「电脑实际执行的是哪个文件」。排查工具版本问题全靠它。

## 步骤 4 · 理解「你现在在哪」

### 这一步在做什么

命令行和图形界面最大的区别是：**图形界面里你能看到自己在哪个文件夹，命令行里你必须自己记住。** 这一步就是建立这个感觉。

### 怎么做

三条命令，反复用：

```bash
pwd              # 我现在在哪？（print working directory）
ls               # 这里有什么？（list）
cd <directory>   # 换个地方（change directory），<directory> 换成真实的目录名
```

跟着做一遍：

```bash
cd ~              # 回到主目录
pwd               # 应该显示 /Users/you
ls                # 看到 Desktop Documents Downloads 等
cd Desktop        # 进入桌面
pwd               # 现在显示 /Users/you/Desktop
ls                # 看到你桌面上的东西
cd ..             # 退回上一层
pwd               # 又回到 /Users/you
```

### 四个特殊符号，必须记住

| 符号 | 含义 |
|---|---|
| `~` | 你的主目录，`/Users/you` |
| `.` | 当前目录 |
| `..` | 上一层目录 |
| `/` | 整个硬盘的最顶层（根目录） |

### 绝对路径 vs 相对路径

这是新手最容易懵的地方，但其实很简单。

**绝对路径**：从根目录开始写全，以 `/` 开头。比如 `/Users/you/Desktop/a.txt`。**不管你现在站在哪，它都指向同一个文件。**

**相对路径**：从「你现在站的地方」开始算。比如你在 `/Users/you`，那 `Desktop/a.txt` 和 `./Desktop/a.txt` 指的都是同一个文件。**你换个地方站，它就指向别的东西了。**

打个比方：绝对路径是「北京市朝阳区xx路1号」，相对路径是「往前走两百米左转」。

### 可能卡在哪

**`cd: no such file or directory: xxx`**

三种原因，按顺序排查：

1. **拼错了**。用 Tab 键自动补全：输入 `cd Desk` 然后按 `Tab`，会自动补成 `cd Desktop/`。**从今天起养成按 Tab 的习惯，能消灭 90% 的拼写错误。**
2. **大小写错了**。macOS 的文件系统默认不区分大小写，但 Linux 服务器区分。养成大小写严格的习惯。
3. **路径里有空格**。比如 `cd AI Agent 学习计划` 会失败，因为 shell 认为你要 cd 到 `AI`，后面的 `Agent` 和 `学习计划` 是另外的参数。解法是加引号：`cd "AI Agent 学习计划"`，或者直接用 Tab 补全（它会自动加转义）。

**`ls` 什么都不显示**

要么目录是空的，要么里面只有隐藏文件。用 `ls -a` 看全部（`-a` 是 all）。

### 背后的逻辑

**为什么以 `.` 开头的文件是隐藏的？**

这其实是个历史意外。早期 Unix 的 `ls` 想过滤掉 `.`（当前目录）和 `..`（上级目录）这两个特殊项，实现的时候偷懒写成「跳过所有以 `.` 开头的」，结果这个 bug 变成了特性，从此约定俗成：配置文件都以 `.` 开头，默认不显示。

你后面会天天见到它们：`.git`、`.env`、`.gitignore`、`.zshrc`。

**`ls -a` 里的 `-a` 是什么？**

叫「选项」或「flag」。命令行工具的标准形态是：`命令 -选项 参数`。

- 单字母选项用一个横线：`ls -a`
- 完整单词选项用两个横线：`ls --all`
- 多个单字母可以合并：`ls -la` 等于 `ls -l -a`

`ls -la` 是你以后最常用的组合，`-l` 是详细列表（显示权限、大小、修改时间）。

## 步骤 5 · 增删改查文件

### 这一步在做什么

把「新建文件夹、复制、改名、删除」这些你在访达里点鼠标做的事，改成打字做。

### 怎么做

在桌面建一个 `practice` 目录，全程跟着敲：

```bash
# 全程在一个专门的 practice 目录里操作，删错了也不会伤到别的文件
cd ~/Desktop
mkdir practice          # 新建文件夹（make directory）
cd practice
touch a.txt             # 新建一个空文件
ls                      # 看到 a.txt

echo "第一行" > a.txt    # 把文字写进文件（覆盖，原有内容全没）
cat a.txt               # 看文件内容（concatenate）

echo "第二行" >> a.txt   # 追加一行，上面那行还在
cat a.txt               # 现在有两行了

cp a.txt b.txt          # 复制（copy），原文件还在
mv b.txt c.txt          # 改名（move）；文件系统里改名和移动是同一个动作
mkdir subdir
mv c.txt subdir/        # 目标以 / 结尾，表示「移动进这个目录」而不是「改成这个名字」
ls subdir               # 确认它在里面

rm subdir/c.txt         # 删除文件（remove）。不进废纸篓，删了就没了
rm -r subdir            # 删除整个目录（-r 是递归 recursive，把里面的东西一层层删掉）
```

### `>` 和 `>>` 的区别

这两个符号叫「重定向」，是命令行里最有用的东西之一。

- `>` **覆盖**写入。文件原有内容全没了。
- `>>` **追加**写入。加在末尾。

**记混这两个会丢数据。** 一个记忆方法：`>>` 两个箭头，像在往后接。

### 可能卡在哪

**`rm` 删掉的东西找不回来**

**这是本单元最重要的一条警告。** 命令行的 `rm` 不进废纸篓，删了就是真没了，没有撤销。

三条保命规则：

1. 删之前先 `ls` 一下确认你要删的是什么
2. **永远不要敲 `rm -rf /`** 或者任何以 `/` 开头的路径。这会删掉整个系统
3. 不确定的时候用 `rm -i`，它会每个文件都问你一次

**`rm: 目录名: is a directory`**

`rm` 默认只删文件。删目录要加 `-r`（递归，把里面的东西一层层删掉）。

**`mv a.txt b.txt` 之后 a.txt 不见了**

这是对的。`mv` 是 move，移动。「改名」在文件系统看来就是「移动到同一个目录下的另一个名字」，所以是同一个命令。

### 背后的逻辑

**为什么 `echo "文字" > 文件` 能写文件？**

因为在 Unix 的世界观里，**一切皆文件**，而每个程序默认有三个通道：

| 通道 | 名字 | 默认连到哪 |
|---|---|---|
| 标准输入 | stdin | 你的键盘 |
| 标准输出 | stdout | 你的屏幕 |
| 标准错误 | stderr | 你的屏幕 |

`echo "文字"` 本来是把文字送到 stdout（屏幕）。`>` 的作用是**把 stdout 这根管子从屏幕拔下来，插到文件上**。

理解了这个，你就理解了整个命令行的设计哲学。下一步的管道也是同一个道理。

## 步骤 6 · 管道：把命令串起来

### 这一步在做什么

学会命令行最强大的一个能力：**把一个命令的输出，直接喂给下一个命令。**

### 怎么做

先造点数据：

```bash
cd ~/Desktop/practice
ls /usr/bin > commands.txt      # 把系统里所有命令的名字存进文件
wc -l commands.txt              # 数一下有多少行（word count -lines）
```

现在用管道：

```bash
ls /usr/bin | wc -l                    # 直接数，不用先存成文件
ls /usr/bin | grep python              # 只看名字里带 python 的
ls /usr/bin | grep python | wc -l      # 管道可以接着串：过滤完的结果再交给 wc 数
cat commands.txt | head -20            # 只看前 20 行
cat commands.txt | tail -5             # 只看最后 5 行
```

竖线 `|` 就是管道符（在回车键上方，`\` 那个键按 Shift）。

### 常用的几个「过滤器」

| 命令 | 作用 |
|---|---|
| `grep 关键词` | 只留下含关键词的行。**你以后用得最多的命令** |
| `wc -l` | 数行数 |
| `head -N` | 只看前 N 行 |
| `tail -N` | 只看后 N 行 |
| `sort` | 排序 |
| `uniq` | 去掉相邻的重复行（通常配合 sort 用） |

### 可能卡在哪

**`grep` 搜中文搜不到**

编码问题。先确认文件是 UTF-8。大多数情况下直接搜是可以的，搜不到先检查关键词有没有打错。

**管道后面的命令没反应**

检查前一个命令有没有输出。`命令1 | 命令2` 里，如果命令1 什么都没输出，命令2 自然没东西可处理。单独跑一下命令1 看看。

**想搜的内容里有特殊字符**

比如搜 `a.txt` 里的点，`grep a.txt` 会把点当成「任意字符」（正则表达式）。加引号并转义：`grep "a\.txt"`，或者用 `grep -F "a.txt"`（`-F` 表示按字面量搜）。

### 背后的逻辑

管道体现的是 Unix 哲学最核心的一条：**每个程序只做一件事，把它做好；程序之间用文本流沟通。**

所以没有一个叫「列出目录并过滤并计数」的大程序，而是 `ls`、`grep`、`wc` 三个小程序，用管道拼起来。

这个思路你在整个 AI Agent 学习里会不断遇到：**工具应该小而专，靠组合产生能力。** S2 设计 Agent 工具的时候，你会发现遵循这条原则的工具，模型用起来准确率高得多。

## 步骤 7 · 认识配置文件

### 这一步在做什么

打开那个「每次开终端都会自动执行」的文件，理解你的终端为什么长这样。

### 怎么做

```bash
cat ~/.zshrc
```

可能显示内容，也可能报 `No such file or directory`（说明你还没有这个文件，正常）。

再看看 Homebrew 写的那个：

```bash
cat ~/.zprofile
```

应该能看到 `eval "$(/opt/homebrew/bin/brew shellenv)"` 这行——就是步骤 2 里你加进去的。

**加一个自己的快捷命令试试**：

```bash
# 把别名写进 .zshrc，而不是直接在终端里敲 alias：后者关掉窗口就没了
echo 'alias ll="ls -la"' >> ~/.zshrc
source ~/.zshrc      # 让改动立刻生效，不用重开终端
ll                   # 现在 ll 等于 ls -la
```

### 可能卡在哪

**改完没生效**

配置文件只在「开新终端」时被读取。改完之后要么 `source ~/.zshrc`，要么关掉重开一个终端窗口。

**`source` 之后报了一堆错**

说明你写进去的东西有语法错误。用文本编辑器打开检查：

```bash
open -e ~/.zshrc
```

把有问题的那行删掉，重新 source。

**改坏了，终端一开就报错**

不用慌，`.zshrc` 只是个文本文件。用上面的 `open -e` 打开它，把最近加的内容删掉。实在不行 `mv ~/.zshrc ~/.zshrc.bak` 把它改个名，等于禁用了。

### 背后的逻辑

`alias` 是「别名」。你定义 `ll` 等于 `ls -la`，以后敲 `ll` shell 就会替换成 `ls -la` 再执行。

这体现了命令行环境的一个特点：**它是可编程的、可定制的**。你用得越久，`.zshrc` 里积累的自定义就越多，效率就越高。图形界面给你的是固定的按钮，命令行给你的是可以自己造工具的原料。
