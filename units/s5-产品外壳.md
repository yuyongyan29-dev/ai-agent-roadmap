# Stage 5 · 产品外壳：网站 / App / 小程序（W19–W22，80h）

**目标**：给你的 Agent 做一个别人愿意用的界面，并覆盖你想要的「独立做网站、App、小程序」这条线。

**版本基线（2026 年 9 月核实，来自 npm registry）**：Next.js 16.x、React 19.2、TypeScript 7.x、Tailwind CSS 4.3、Vercel AI SDK 7.x。**动手前再核一次，前端版本变化很快。**

**心理准备**：有了 Python 基础后学 TypeScript 会比想象中快，但 CSS 和布局是另一套思维，不要低估。**这四周的目标是「能做出可用的界面」，不是「成为前端工程师」。**

---

## U5.1 TypeScript 基础（10h）

**目标**：能读懂也能写 TypeScript，理解它和 Python 类型注解的区别。

**具体做什么**

1. 装 Node.js（用 [fnm](https://github.com/Schniz/fnm) 或 nvm 管版本）和 [pnpm](https://pnpm.io/)。
2. 先补 JavaScript 的必要部分，不用全学：`const/let`、箭头函数、解构、展开运算符、模板字符串、`async/await`、Promise、数组方法（`map filter reduce find`）、模块导入导出。
3. TypeScript 核心：
   - 基础类型、数组、对象类型
   - `interface` 和 `type` 的区别与选择
   - 联合类型 `A | B`、字面量类型、可选属性
   - 泛型（先会用再会写）
   - **类型收窄**（narrowing），这是 TS 最常用也最容易懵的概念
   - `unknown` 和 `any` 的区别，为什么永远不该用 `any`
4. 配 `tsconfig.json`，开 `strict: true`。**从一开始就开严格模式**，后期再开会痛苦十倍。
5. **实战**：把 S1 的 `llm_kit` 用 TypeScript 重写一个精简版（只要多模型切换和结构化输出两个能力）。

**产出**：`s5-frontend/llm-kit-ts/`

**完成判据**：`tsc --noEmit` 在严格模式下零报错，且你能解释代码里每个泛型在做什么。

## U5.2 前端基础与 React（14h）

**目标**：能把想法变成页面。

**具体做什么**

1. **HTML/CSS 够用就行**，别陷进去。需要掌握的只有：语义化标签、盒模型、Flexbox、Grid、响应式断点。**Flexbox 和 Grid 是重点**，现代布局基本靠这两个。
2. Tailwind CSS 4：理解原子类的思路，掌握间距、颜色、字号、flex、grid、响应式前缀（`md:` `lg:`）、状态前缀（`hover:` `dark:`）。
3. React 核心概念，按这个顺序学：
   - 组件与 JSX
   - props 传递
   - `useState` 管状态
   - 列表渲染与 `key` 的作用（**`key` 用错是新手最常见的 bug**）
   - 条件渲染
   - `useEffect` 与它的依赖数组（**这是最容易出错的 hook，慢慢来**）
   - 受控组件与表单
   - `useRef`、`useMemo`、`useCallback`（知道什么时候需要，不要滥用）
4. 理解 React 的心智模型：**UI 是状态的函数**。你改的永远是状态，不是 DOM。
5. **实战**：做一个纯前端的多轮对话界面，消息列表、输入框、发送、加载状态、错误提示。数据先用假的。

**产出**：`s5-frontend/chat-ui/`

**完成判据**：界面能正常增删消息，状态管理清晰，没有直接操作 DOM 的代码。

## U5.3 Next.js App Router（12h）

**目标**：把界面变成一个真正的应用，且密钥不泄露到浏览器。

**具体做什么**

1. `pnpm create next-app`，选 App Router、TypeScript、Tailwind。
2. 理解文件路由：`app/page.tsx`、`app/layout.tsx`、`app/xxx/page.tsx`、动态路由 `[id]`。
3. **理解 Server Components 和 Client Components 的区别**，这是 App Router 最核心也最容易搞混的概念：
   - 默认是 Server Component，在服务器上渲染，**可以直接读数据库、可以用密钥**，代码不会发到浏览器
   - 加 `'use client'` 才是 Client Component，能用 `useState` 和事件处理
   - 判断标准：需要交互的才 client，其余都 server
4. **Server Actions**：直接在组件里定义一个 `'use server'` 函数，前端当普通函数调，框架自动帮你处理网络请求。**这是 AI 应用特别受益的一点**，模型调用逻辑天然留在服务端。
5. 数据获取、loading.tsx、error.tsx、streaming 与 Suspense。
6. **把 U5.2 的界面迁过来**，接上你 S4 部署的 Agent API。
7. **验证密钥安全**：打开浏览器开发者工具的 Network 和 Sources，确认找不到任何 API key。

**产出**：`s5-frontend/app/`

**完成判据**：界面能真实调用你的 Agent；浏览器里搜不到任何密钥。

## U5.4 Vercel AI SDK 与流式界面（12h）

**目标**：让用户看到 Agent 在「思考」，而不是盯着一个转圈等 30 秒。**这是 Agent 产品体验的分水岭。**

**具体做什么**

1. `pnpm add ai`，读 [AI SDK 文档](https://ai-sdk.dev)。注意 v5 之后 API 有较大变化，**照最新文档写，不要照老教程**。
2. 用 `useChat` 或 `streamText` 实现基础流式对话，文字逐字出现。
3. **渲染工具调用过程**，这是 Agent 界面和普通聊天界面的关键差别。用户应该看到：
   ```
   正在搜索「小红书 家电 选题」…
   找到 23 条笔记
   正在分析互动数据…
   ```
   而不是一个空白的加载动画。数据来源就是 U4.3 做的 SSE 事件流。
4. 实现中断：用户能随时点「停止」，前端断开的同时后端也要真的停下来（调 U4.3 的 cancel 接口）。
5. 处理错误状态：模型报错、工具失败、超时，各自给用户看得懂的提示。
6. **实现人工确认的界面**：Agent 请求执行高危操作时，界面弹出确认卡片，用户点批准或拒绝。这是 U4.4 那套流程的前端部分。
7. 加一些体验细节：自动滚动到底部、Markdown 渲染、代码块高亮、消息复制、重新生成。

**产出**：`s5-frontend/app/chat/`

**完成判据**：完整跑一次多步任务，全程能看到每一步在做什么；中途点停止能真的停下来；触发高危操作时弹出确认。

## U5.5 认证与数据（10h）

**目标**：多用户各自独立，数据不串。

**具体做什么**

1. 接认证。国内项目考虑微信登录或手机号验证码；练手可以先用 [Auth.js](https://authjs.dev/)（开源）或 [Clerk](https://clerk.com/)（省事但海外）。
2. **数据隔离**：所有查询都必须带用户过滤。**最好在数据库层用行级安全（RLS）兜底**，不要只依赖应用层记得加 `where user_id = ?`，人总会忘。
3. 会话历史：列表、搜索、重命名、删除、继续之前的对话。
4. 用量限制：按用户限制每日调用次数和 token 预算，接上 U4.5 的限流。
5. **做一次越权测试**：用 A 用户的身份，把请求里的会话 id 换成 B 用户的，确认拿不到数据。

**产出**：`s5-frontend/app/(auth)/`

**完成判据**：两个账号各自登录，会话历史互不可见，越权测试失败。

## U5.6 小程序（14h）

**目标**：把 Agent 装进微信。

**技术选型**：[Taro](https://taro-docs.jd.com/)，用 React 语法写小程序，U5.2 学的 React 能直接复用，同一套代码还能编译到多端。如果只做微信一端且要求极致性能，用微信原生开发也可以，但你要多学一套语法。

**具体做什么**

1. 装微信开发者工具，注册小程序账号（个人主体就能注册，但**个人主体不能做某些类目，涉及内容发布的要提前查清楚**）。
2. `npx @tarojs/cli init`，选 React + TypeScript 模板，跑通 Hello World。
3. **理解小程序的能力边界**，这些限制会直接影响你的设计：
   - 只能请求配置在后台白名单里的域名，**必须是 HTTPS，且不能用 IP**
   - 包体积有上限，主包通常 2MB
   - 没有 DOM，不能用浏览器 API
   - 部分能力需要用户授权
4. 实现核心页面：对话列表、对话详情、设置。
5. **流式输出在小程序里是个坑**：小程序的 `request` 不支持标准 SSE。三种解法——用 WebSocket、用分块传输的 `onChunkReceived`（需基础库版本支持）、或者退化成轮询。**先用轮询跑通，再优化。**
6. 微信登录：`wx.login` 拿 code，后端换 openid，和 U5.5 的账号体系打通。
7. 真机预览，在自己手机上跑一遍。

**产出**：`s5-frontend/miniapp/`

**完成判据**：微信开发者工具里能跑，真机预览能用，能调通你线上的 Agent。

**关于上架**：小程序审核有门槛，AI 类目通常需要额外资质。**本单元的完成判据不包含上架**，能真机跑通即可。想上架的话提前研究备案和类目要求。

## U5.7 上线与打磨（8h）

**具体做什么**

1. Web 端部署到 [Vercel](https://vercel.com)（Next.js 官方平台，免费额度够用），接自定义域名。
2. **移动端适配**：手机浏览器上过一遍所有页面，重点检查输入框被键盘遮挡、横向滚动、点击区域太小三个问题。
3. 性能：图片优化、字体加载、首屏时间。用 Lighthouse 跑一次，把明显的问题修掉。
4. 基础可用性：加载状态、空状态、错误状态、暗色模式。
5. 写一个像样的落地页，说明这个 Agent 能做什么、怎么用。**这一页是你作品集的门面。**

**完成判据**：手机浏览器打开流畅可用；把链接发给三个朋友，他们不需要你解释就知道怎么用。
