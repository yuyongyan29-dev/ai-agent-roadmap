# U2.7 · MCP 实战（10 小时）

**这个单元解决什么问题**

到现在你的工具都是硬编码在项目里的。**MCP（Model Context Protocol）让工具变成可复用的、跨项目的、跨客户端的独立服务。**

它已经是 2026 年 Agent 接工具的事实标准：Claude、ChatGPT、VS Code、Cursor 等都支持，[官方 servers 仓库](https://github.com/modelcontextprotocol/servers) 有 9 万 star 的现成实现。

**学完你能做到**：写一个 MCP server，**同一份代码同时被 Claude Code 和你自己的 Agent 使用**。

## 步骤 2 · 理解三种原语

### 先看清 MCP 的架构

```
  ┌─────────────────────────────────┐
  │  MCP Host（Claude Code / 你的 Agent）│
  │  ┌───────────────────────────┐  │
  │  │      MCP Client           │  │
  │  └────┬─────────────┬────────┘  │
  └───────│─────────────│───────────┘
          │ stdio       │ HTTP 流式
          │（本地子进程）│（远程服务）
  ┌───────▼──────┐  ┌───▼──────────┐
  │ MCP Server A │  │ MCP Server B │
  │  Tools       │  │  Tools       │
  │  Resources   │  │  Resources   │
  │  Prompts     │  │  Prompts     │
  └──────┬───────┘  └──────┬───────┘
         │                 │
    ┌────▼────┐       ┌────▼────┐
    │ 你的数据库│       │ 外部 API │
    └─────────┘       └─────────┘

三种原语的区别在于「谁决定用它」：
  Tools     → 模型自己决定调用
  Resources → 客户端/用户决定加载什么进上下文
  Prompts   → 用户主动触发

这是一个安全设计：不是所有东西都该让模型自己决定。
```



### 这一步在做什么

MCP 不只有工具，还有另外两种东西。搞清楚区别，才知道该用哪个。

### 三种原语

| 原语 | 谁发起 | 是什么 | 例子 |
|---|---|---|---|
| **Tools** | **模型** | 模型可以主动调用的函数 | 搜索、写文件、发消息 |
| **Resources** | **客户端/用户** | 可被读取的数据 | 一个文件、一条数据库记录、一个 API 端点的内容 |
| **Prompts** | **用户** | 预置的提示模板 | 「代码审查」「翻译成中文」这类可复用的指令 |

### 关键区别：谁决定用它

**Tools 是模型自己决定调用的。** 它看到工具列表，判断需要就调。

**Resources 是由客户端或用户决定加载的。** 模型不能主动去「读所有资源」，而是客户端把某个资源的内容放进上下文。

**Prompts 是用户主动触发的。** 比如在客户端里选一个「代码审查」模板。

### 什么时候用哪个

| 场景 | 用什么 |
|---|---|
| 「查一下这个关键词」 | Tool |
| 「把这个文件的内容作为背景」 | Resource |
| 「按我们团队的规范审查代码」 | Prompt |

**实践中 Tools 用得最多。** Resources 和 Prompts 在特定客户端里价值更大。**你的第一个 server 可以只做 Tools。**

### 背后的逻辑

这个三分法背后的思想是**区分「模型的能动性」**：

- Tools 给模型能动性（它决定做什么）
- Resources 保留客户端的控制权（避免模型乱读数据）
- Prompts 保留用户的控制权

**这是一个安全设计**：不是所有东西都该让模型自己决定。S4 学安全时你会更理解这个区分的价值。

## 步骤 3 · 写你自己的 server

### 这一步在做什么

**把 U2.2 写的 3 个工具改造成一个 MCP server。**

### 怎么做

```bash
cd s2-agent && uv add mcp
```

```python
# mcp_server/server.py
from mcp.server.fastmcp import FastMCP
from pydantic import Field
from typing import Annotated

# server 的名字会成为客户端里的命名空间，工具重名时靠它区分，
# 所以要和客户端配置文件里的 key 保持一致
mcp = FastMCP("notes-tools")


@mcp.tool()
async def search_notes(
    # Annotated 里的 Field(description=...) 会写进 JSON Schema，
    # 模型只能靠这段文字判断参数怎么填，所以要写清格式而不是只写类型
    keyword: Annotated[str, Field(description="搜索关键词，空格分隔多个词")],
    # ge/le 是硬约束，超范围的值在进函数前就被拦下，省掉一次无效调用
    limit: Annotated[int, Field(ge=1, le=50, description="返回条数")] = 10,
) -> str:
    """在笔记库里按关键词搜索。

    当你需要了解某个话题下已有哪些内容、竞品在做什么、
    或验证一个选题是否已被做过时使用。
    返回笔记标题、点赞数、发布时间和 id。
    注意：只覆盖过去 90 天的数据。
    """
    results = await do_search(keyword, limit)
    # 返回字符串而不是对象：工具结果是要拼进对话上下文给模型读的，
    # 不是给程序解析的，所以格式化这一步必须在这里做完
    return format_results(results)


@mcp.tool()
async def read_note_detail(
    note_id: Annotated[str, Field(description="笔记 id，从搜索结果里获取")],
) -> str:
    """读取某一篇笔记的完整内容。需要先用 search_notes 拿到 id。"""
    ...


if __name__ == "__main__":
    # 默认 stdio 传输：客户端会把这个文件当子进程拉起来，用管道通信
    mcp.run()
```

**注意两点**：

1. **函数的 docstring 就是工具描述**，模型看到的是它。用 U2.2 学的原则写。
2. **参数用 `Annotated` 加 `Field` 描述**，会进入 schema。

### 本地测试

```bash
uv run python mcp_server/server.py
```

它会等在那里（stdio 模式下等待客户端连接）。用 MCP 官方的 inspector 工具测试更方便：

```bash
npx @modelcontextprotocol/inspector uv run python mcp_server/server.py
```

会打开一个网页，能看到工具列表并手工调用。

### 接进 Claude Code

```json
{
  "mcpServers": {
    "notes-tools": {
      "command": "uv",
      "args": ["--directory", "/绝对路径/s2-agent", "run", "python", "mcp_server/server.py"]
    }
  }
}
```

重启客户端，在对话里试着让它搜索笔记。

### 可能卡在哪

**客户端连不上**

按顺序排查：

1. 在终端手工跑那条命令，能起来吗
2. 路径是不是绝对路径（客户端的工作目录和你的不一样）
3. 看客户端的 MCP 日志

**stdio 模式下不能 print**

**这是个很坑的点。** stdio 传输用标准输入输出传协议消息，你 `print` 的任何东西都会污染协议流，导致连接失败。

**调试信息必须输出到 stderr**：

```python
import sys
print("调试信息", file=sys.stderr)
```

或者用 logging 配置成输出到 stderr（这是 logging 的默认行为）。

**环境变量读不到**

客户端启动 server 时的环境和你的终端不同。在配置里显式传：

```json
{
  "command": "uv",
  "args": [...],
  "env": {"DEEPSEEK_API_KEY": "..."}
}
```

**但不要把密钥明文写进配置文件。** 更好的做法是让 server 自己从 `.env` 读（用绝对路径）。

### 背后的逻辑

**为什么 stdio 是默认传输？**

因为它最简单：客户端启动一个子进程，通过管道通信。不需要端口、不需要认证、不需要网络配置。

**代价是**：server 只能在客户端本机跑，一个客户端一个进程。

**HTTP 传输**用于远程 server：一个服务多个客户端共用，但需要处理认证、并发、部署。

**建议**：本地工具用 stdio，需要共享的服务用 HTTP。

## 步骤 4 · 写 MCP client 接进你的 Agent

### 这一步在做什么

**让你 U2.1 的 Agent 循环通过 MCP 拿工具，而不是硬编码。**

### 怎么做

```python
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


class MCPToolSource:
    """把一个 MCP server 包成 Agent 能用的工具源：负责连接、列工具、转发调用。"""

    def __init__(self, command: str, args: list[str]):
        # 构造时只记参数不连接，真正的连接放在 __aenter__ 里，
        # 让 async with 来管生命周期，避免忘记关子进程
        self.server_params = StdioServerParameters(command=command, args=args)
        self.session: ClientSession | None = None

    async def __aenter__(self):
        # stdio_client 负责拉起 server 子进程，返回读写两端的管道
        self._ctx = stdio_client(self.server_params)
        reader, writer = await self._ctx.__aenter__()
        self.session = ClientSession(reader, writer)
        await self.session.__aenter__()
        # initialize 是 MCP 的握手，不调用就拿不到工具列表
        await self.session.initialize()
        return self

    async def get_tool_schemas(self) -> list[dict]:
        # MCP 的 inputSchema 本身就是标准 JSON Schema，
        # 直接放进 function.parameters 即可，不用自己再翻译一遍字段
        r = await self.session.list_tools()
        return [{
            "type": "function",
            "function": {
                "name": t.name,
                "description": t.description,
                "parameters": t.inputSchema,
            },
        } for t in r.tools]

    async def call(self, name: str, arguments: dict) -> str:
        r = await self.session.call_tool(name, arguments)
        # 返回内容是分块的，可能混着图片等非文本块，只挑出有 text 的拼起来
        return "\n".join(c.text for c in r.content if hasattr(c, "text"))
```

在 Agent 里用：

```python
# 用 async with 把连接的生命周期包住：整个任务共用一条连接，
# 退出时自动关掉子进程；不要每次调用工具都重连，握手开销很大
async with MCPToolSource("uv", ["run", "python", "mcp_server/server.py"]) as source:
    tool_registry.register_mcp_source(source)
    result = await agent.run("帮我找家电相关的选题")
```

### 混合本地工具和 MCP 工具

你的工具表应该能同时管理两种：

```python
class ToolRegistry:
    """本地工具和 MCP 工具共用一张表，Agent 循环不需要知道工具来自哪里。"""

    def __init__(self):
        self._local: dict[str, Tool] = {}
        self._mcp_sources: list[MCPToolSource] = []

    async def schemas(self) -> list[dict]:
        # 两类工具的 schema 拼成一份交给模型，模型看到的是一个统一的工具列表
        s = [t.build_schema() for t in self._local.values()]
        for source in self._mcp_sources:
            s.extend(await source.get_tool_schemas())
        return s

    async def execute(self, name: str, arguments: str) -> str:
        # 本地工具优先：命中就不用走进程间通信
        if name in self._local:
            return await self._local[name].execute(arguments)
        for source in self._mcp_sources:
            if await source.has_tool(name):
                # 模型给的是 JSON 字符串，MCP 要的是 dict，在边界上做一次解析
                return await source.call(name, json.loads(arguments))
        # 名字不存在时返回错误字符串而不是抛异常，让模型看到并自己改名重试
        return f"错误：不存在名为 {name} 的工具"
```

### 可能卡在哪

**MCP 返回的 schema 模型不认**

MCP 的 `inputSchema` 是标准 JSON Schema，大多数模型能直接用。**如果模型报错，检查有没有 `$ref` 引用需要展开。**

**工具名冲突**

两个 server 提供了同名工具。**加前缀**：`notes-tools__search_notes`。

**连接管理**

MCP 连接是有状态的，要正确管理生命周期。用 `async with` 或者在应用启动时建立、关闭时释放。**不要每次调用都重新连接**，开销很大。

### 背后的逻辑

**这一步的价值是「解耦」。**

之前：工具的实现和 Agent 的代码在一个项目里，改工具要改 Agent。

之后：工具是独立的服务，Agent 只知道「有哪些工具、怎么调」。**工具可以独立开发、独立测试、独立部署、被多个 Agent 复用。**

**这就是为什么 MCP 赢下了「Agent 连工具」这一层**——它把工具从「代码里的函数」变成了「可组合的基础设施」。

## 步骤 5 · 了解代码执行模式

### 这一步在做什么

理解一个更高级的模式，为 S6 打基础。

### 问题回顾

U2.2 步骤 5 说过：工具超过 15 到 20 个，上下文占用和选择准确率都会成问题。

### 代码执行的思路

不给模型几十个工具的 schema，而是：

1. 给它一个「执行代码」的工具
2. 给它一份 API 文档（可以放在 Resource 里，或者让它自己去读）
3. 它写代码来调用你的能力

```python
# 模型生成的代码：搜索、过滤、并发读详情、汇总，全在一次执行里完成
results = await note_store.search("家电 选购", limit=50)
# 过滤放在代码里做，50 条原始结果不进上下文，只有最后的汇总进
top_liked = [n for n in results if n.likes > 1000]
# gather 并发读 5 篇详情；换成工具调用要来回 5 轮，延迟差一个量级
details = await asyncio.gather(*[note_store.read_detail(n.id) for n in top_liked[:5]])
return summarize(details)
```

**一次调用完成了原本需要 7 次工具调用的事。**

参考 Anthropic《[Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp)》（2025-11-04）。

### 优缺点

| 优点 | 缺点 |
|---|---|
| 上下文占用极小 | **必须有安全沙箱** |
| 模型能组合、循环、条件判断 | 调试更难 |
| 大幅减少轮次和延迟 | 模型写的代码可能有 bug |
| | 需要给模型足够好的 API 文档 |

**「必须有安全沙箱」这一条是硬门槛。** 让模型执行任意代码而不隔离，等于把机器交给它。

**这就是为什么这个模式放在 S6**——那时你会先学沙箱（U6.3），再来实现它。

### 现在做什么

**这一步只要求你理解，不要求实现。**

但可以做一个小实验：给模型一个受限的「执行代码」工具（只允许调用你预定义的几个函数，用 `exec` 加受限的 globals），跑一个任务，感受一下。

**注意：这个实验只能在你自己的机器上、用你自己的输入做。绝不能接受外部输入。**
