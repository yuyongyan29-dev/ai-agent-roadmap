# U2.9 · Skill 与 Plugin（5 小时）

**这个单元解决什么问题**

你的笔记 Agent 已经会检索、读详情，但每次都要重说“结论带来源”“改完跑那几个 case”。现在把这两段反复使用的工作方法做成 Skill，再装进一个可搬到干净目录的 Plugin。

**学完你能做到**：给主线项目做两个有明确输入、步骤、附件和验收的 Skill，完成本地插件安装，并留下裸 prompt 与 Skill 的真实对照记录。

**前置**：U2.2 的工具、U2.5 的检索结果，以及 U2.7 对 MCP 的认识。需要 Python 3 和可用的 Claude Code 客户端；离线部分不需要模型账号。学习用时是建议预算：30 + 60 + 45 + 60 + 75 + 30 分钟。

**版本与证据**：2026-09-10 核对了 [Agent Skills 规范](https://agentskills.io/specification)、[Claude Code Skills](https://code.claude.com/docs/en/skills)、[Plugin 结构](https://code.claude.com/docs/en/plugins-reference)和[本地 Marketplace](https://code.claude.com/docs/en/plugin-marketplaces)。本页使用 Claude Code 的插件格式；把目录复制到别的客户端，不能直接算该客户端已支持或已安装。

---

## 步骤 1 · 给现有需求分工（30 分钟）

### 这一步在做什么

先决定哪一层负责什么，避免为一段提示词启动一个服务，或期待 Skill 自动给你数据库权限。

### 怎么做

在学习项目的 `s2-agent/skill-lab/design.md` 记录下面三件事，换成你已有的工具名：

| 需求 | 放在哪 | 你的产出 |
|---|---|---|
| 按关键词查询笔记，返回真实数据 | U2.7 的 MCP server 或现有函数 | `search_notes`、`read_note_detail` |
| 按证据写简报，比较检索前后是否回退 | Skill | `evidence-brief`、`retrieval-regression` |
| 把这两套方法连同模板和脚本交给别人 | Plugin | `agent-workbench` |

本单元不要求给 Plugin 再加一个 MCP server：先复用 U2.7 的服务。Plugin 可以打包多个组件，但打包与鉴权是两件事；接入服务的凭证仍由运行环境提供。相关结构见 [Plugins reference](https://code.claude.com/docs/en/plugins-reference)。

### 可能卡在哪

**“Skill 是不是写得越长越可靠？”** 长度不是验收。先写输入、输出和失败时怎么处理；机械规则放脚本，长模板放附件。

**“两个 Skill 必须由我的手写 Agent 直接加载吗？”** 本单元由 coding agent 执行 Skill，服务于你的主线项目；让手写 Agent 实现 Skill 发现和加载机制是另一项工程，不在这 5 小时里。

### 背后的逻辑

MCP 定义能力如何被调用；Skill 描述一次任务怎样做；Plugin 负责把组件按客户端要求打包分发。三者可以协作，但不会互相替代。

## 步骤 2 · 跑通两个最小 Skill，再换成自己的输入（60 分钟）

### 这一步在做什么

先用仓库自带的完整例子得到一个能执行的起点，再接上你的主线数据。

### 怎么做

示例位于 [`examples/skill-plugin-lab`](../../examples/skill-plugin-lab/verify.py)，结构如下：

```text
examples/skill-plugin-lab/
├── .claude-plugin/marketplace.json
├── fixtures/                       # 人工构造的数据，不是模型实测成绩
├── verify.py
└── plugins/agent-workbench/
    ├── .claude-plugin/plugin.json
    └── skills/
        ├── evidence-brief/
        │   ├── SKILL.md
        │   └── references/output-template.md
        └── retrieval-regression/
            ├── SKILL.md
            └── scripts/compare.py
```

在仓库根目录执行：

```bash
cd ~/ai-agent-roadmap
python3 examples/skill-plugin-lab/verify.py
python3 examples/skill-plugin-lab/plugins/agent-workbench/skills/retrieval-regression/scripts/compare.py examples/skill-plugin-lab/fixtures/baseline.json examples/skill-plugin-lab/fixtures/candidate.json
```

本仓库实际运行输出：

```text
PASS plugin files and 2 skill entrypoints
PASS improved candidate accepted
PASS regression rejected despite equal total hits
PASS invalid inputs rejected
baseline_hits=1/2
candidate_hits=2/2
regressions=none
```

这证明附件和确定性脚本可用；**不证明模型已读取或自动触发 Skill**。`hit` 是你已经判定的“有没有命中目标材料”，不是脚本替你判断答案好不好。

复制到学习项目：

```bash
mkdir -p s2-agent/skill-lab
cp -R examples/skill-plugin-lab s2-agent/skill-lab/marketplace
```

这个复制步骤只在目标目录尚不存在时做；重跑时直接编辑已复制目录，避免套出多层目录。没有终端输出，检查 `s2-agent/skill-lab/marketplace/verify.py` 存在。

把下面任务交给 coding agent：

```text
修改 s2-agent/skill-lab/marketplace 中的两个 Skill，使其用于本项目已有的笔记 Agent。
先读取 search_notes/read_note_detail 的返回格式和现有检索 case，不虚构工具名。
1. evidence-brief：输入来自现有检索结果；结论带 note_id 和可定位来源；未知写未知。
2. retrieval-regression：从现有 case 导出 baseline/candidate 的 case_id 和布尔 hit。
   若当前没有评测器，先手工标记 5 个固定问题及其应命中的 note_id，并解释判定方式。
保留 compare.py 的输入校验和按 case 检测回归；不得用总命中数掩盖个别 case 回退。
跑 verify.py，用真实项目输入再跑 compare.py，把命令、退出码和原始输出写入 skill-lab/evidence.md。
不修改生产数据，不把 fixtures 的演示数字写成项目效果。
```

“5 个问题”只是这次练习的样本预算，不是统计充分性的保证。

### 可能卡在哪

**输入已经变成 CSV。** 在主线项目加一个短转换器，保留 case_id，再交给脚本；不要让模型凭肉眼猜两份数据如何对应。

**脚本报 `case sets differ`。** 两轮问题集变了，先对齐共同的固定 case。新增问题单独报告，不能伪装成原基线提高了。

### 背后的逻辑

Skill 的自然语言负责选择步骤；脚本把明确的规则变成可复现结果。每条 case 是否回退与总分是否提高是不同问题。

## 步骤 3 · 写触发描述，按需读取附件（45 分钟）

### 这一步在做什么

让客户端知道什么时候加载 Skill，并让入口只承载完成任务必需的流程。

### 怎么做

打开两个 `SKILL.md`。检查 YAML 区域里的 `name` 和 `description`，再检查正文是否引用了模板或脚本。例子采用标准字段；客户端扩展字段的可移植性要单独验证。[规范对入口、元数据和附件的说明](https://agentskills.io/specification)。

把 `evidence-brief` 的描述从“帮助处理笔记”改成三个可判断的条件：要做的事、匹配的用户表达、不匹配的场景。附件按需求读取：模板在生成简报时打开，回归脚本在比较两份 case 时执行。客户端先看到描述，使用时再读取正文和需要的附件，这就是本单元要练的“渐进披露”。[Claude Code Skills](https://code.claude.com/docs/en/skills)。

为每个 Skill 写下这三个触发题：

| Skill | 应触发 | 也应触发 | 不应触发 |
|---|---|---|---|
| evidence-brief | 根据这两篇笔记写有来源的简报 | 这些资料有哪些结论和缺口 | 随便给我起三个项目名 |
| retrieval-regression | 比较这两轮检索 case 是否回退 | baseline 和 candidate 哪些题变差了 | 解释什么是向量数据库 |

先保存题目，步骤 5 再实测。显式输入 `/agent-workbench:evidence-brief` 成功，仅代表显式调用可用；自动触发要用普通用户表达单独试。

### 可能卡在哪

**每个请求都被触发。** 删除“所有任务都必须使用”一类描述，用真实任务收窄范围。

**附件在原项目能读，安装后丢了。** 检查附件是否位于 Plugin 内部，并以 Skill 所在目录为基准引用。不要依赖 `../../你的另一个项目`；插件安装时会复制到缓存目录。[Plugin 文件解析规则](https://code.claude.com/docs/en/plugins-reference)。

### 背后的逻辑

触发描述是任务路由信息，正文是流程，附件是按需材料。只有实际发生读取的证据，才能说明附件进入了这次执行；“回复长得像模板”不够。

## 步骤 4 · 在干净目录安装 Plugin（60 分钟）

### 这一步在做什么

验证可分发性：接收目录没有你原来的项目配置，两个 Skill 仍能被发现，附件仍能运行。

### 怎么做

先在仓库根目录验证两个清单：

```bash
claude plugin validate s2-agent/skill-lab/marketplace
claude plugin validate s2-agent/skill-lab/marketplace/plugins/agent-workbench
```

仓库原始示例已经通过本机 `claude plugin validate`；实际输出中的成功行是 `✔ Validation passed`。你改过的副本也要自己跑一遍。格式校验不会登录模型，更不会替代安装验证。

把整份 Marketplace 搬到接收目录，用临时配置隔离已有插件：

```bash
lab_install=$(mktemp -d)
mkdir -p "$lab_install/project"
cp -R s2-agent/skill-lab/marketplace "$lab_install/marketplace"
cd "$lab_install/project"
CLAUDE_CONFIG_DIR="$lab_install/config" claude plugin marketplace add "$lab_install/marketplace"
CLAUDE_CONFIG_DIR="$lab_install/config" claude plugin install agent-workbench@roadmap-local --scope local
CLAUDE_CONFIG_DIR="$lab_install/config" claude plugin list
CLAUDE_CONFIG_DIR="$lab_install/config" claude
```

命令语法来自 [Marketplace CLI](https://code.claude.com/docs/en/plugin-marketplaces)和[Plugin install](https://code.claude.com/docs/en/plugins-reference)。临时配置目录隔离设置、会话记录和插件；模型调用仍需可用凭证，是否需要重新登录以客户端实际状态为准，不要复制凭证文件进 Plugin。配置目录参数见 [Claude Code 设置](https://code.claude.com/docs/en/settings)。

仓库示例已在临时目录实际完成添加、安装和列出插件，安装与列表输出节选如下；验证后已删除该临时环境：

```text
✔ Successfully installed plugin: agent-workbench@roadmap-local (scope: local)
Version: 0.1.0
Scope: local
Status: ✔ enabled
```

这次没有调用模型，下面两条仍需要你在可用客户端里执行。

在客户端执行以下两条任务，把 `接收目录` 换成刚才命令中的实际路径：

```text
/agent-workbench:evidence-brief 请读取“接收目录/marketplace/fixtures/notes.json”并生成简报。
```

```text
/agent-workbench:retrieval-regression 比较“接收目录/marketplace/fixtures/baseline.json”和“接收目录/marketplace/fixtures/candidate.json”。
```

记录插件列表、两个调用是否出现、实际读到的模板位置、实际执行的脚本位置。**只启动 `claude --plugin-dir ...` 是开发加载，不等于完成 Marketplace 安装**；本练习走完整安装路径。[本地加载与安装的区别](https://code.claude.com/docs/en/plugins)。

### 可能卡在哪

**安装成功，但提示订阅或登录错误。** 保留离线验证和安装证据；将两次模型调用记为“未验证”。恢复可用账号后补测，不能用校验通过代替触发通过。

**插件列表里没有两个 Skill。** 检查 `skills/` 是 Plugin 根目录的子目录，不是 `.claude-plugin/` 的子目录；目录层级放错不会被发现。

### 背后的逻辑

一个可搬走的 Plugin 应包含工作方法本身的依赖。业务输入是接收项目提供的，Skill 内部模板和脚本是 Plugin 自己携带的。

## 步骤 5 · 做裸 prompt 与 Skill 对照（75 分钟）

### 这一步在做什么

实测 Skill 是否减少遗漏，并识别它在哪些请求里反而打扰任务。

### 怎么做

使用步骤 3 保存的 6 个任务，每个任务开独立新会话。固定输入文件、模型、模型设置和工具权限。A 组不给 Plugin，只给相同的简短用户请求；B 组启用 Plugin，仍给相同请求。不要把前一组结果带进后一组上下文。

这比较的是“把流程封装进 Skill 后是否更方便、稳定”，不是宣称相同 token 预算下模型更聪明。Skill 组多了一份流程，记录这项差异。若要比较封装本身，把相同流程全文放进 A 组 prompt，再多做一轮。

在 `s2-agent/skill-lab/comparison.md` 建下面表格；初始全部写“待实测”，不要预填胜负：

| 任务/组别 | 实际加载的 Skill | 来源正确/输入校验 | 是否按要求输出 | 回归 case 识别 | 原始记录 |
|---|---|---|---|---|---|
| 简报/A | 待实测 | 待实测 | 待实测 | 不适用 | 待实测 |
| 简报/B | 待实测 | 待实测 | 待实测 | 不适用 | 待实测 |
| 检索回归/A | 待实测 | 待实测 | 待实测 | 待实测 | 待实测 |
| 检索回归/B | 待实测 | 待实测 | 待实测 | 待实测 | 待实测 |

给 6 个任务都补对应的两行。回归任务分别用 `candidate.json` 和 `regressed.json`；后者总命中数没变，但 `q1` 回退，不能判通过。简报任务检查有没有把“咨询”写成“成交”，有没有凭两篇材料推断“演示类整体表现更好”。

如果任意一组漏了要求，改动一个因素后只重测受影响的任务：触发失败先改描述，步骤遗漏再改正文，数值判断错误修脚本。最终写一段实际结论，包含没有改善的地方。

### 可能卡在哪

**只测一次就想写成功率。** 这是一组小样本练习；报告每题现象即可。要判断稳定性，在自己环境重复测量，保留原始次数，不编一个行业基准。

**A 组被全局 Skill 污染。** 使用与步骤 4 相同的隔离思路，为 A 组建立另一个不装插件的配置目录；记录仍存在的客户端内置能力。

### 背后的逻辑

Skill 是否有价值，取决于真实任务中遗漏是否减少、输入能否检查、输出能否追溯。只看生成文字流畅程度，测不到这些东西。

## 步骤 6 · 交付并解释（30 分钟）

### 这一步在做什么

把可运行包、主线项目输入和实测证据连在一起，让下一位使用者可以复现。

### 怎么做

交付 `marketplace/`、`design.md`、`evidence.md`、`comparison.md`。在说明中写清 Python、Claude Code 的实际版本与安装步骤。保留接收环境验证记录后，退出临时客户端，确认变量仍指向此次 `mktemp` 目录，再删除该临时目录；不要删原项目的 Skill 副本。

### 可能卡在哪

**只交了两个 Markdown。** 检查脚本、模板、Plugin 清单和 Marketplace 清单是否一起交付；接收方不应猜你忘了哪个附件。

### 背后的逻辑

“在我会话里好用”要变成“别人拿到相同输入能复现”，需要明确入口和运行证据。

---

## 验收标准

- [ ] 两个 Skill 都服务主线项目，有输入格式、步骤、失败处理和可观察输出。
- [ ] 触发描述包含适用场景；正例、改写正例、负例都有真实执行记录。
- [ ] 模板、脚本随包分发，干净目录中成功安装并执行两次显式调用。
- [ ] 回归脚本拒绝无效输入，能够发现“总分一样但个别 case 回退”。
- [ ] 裸 prompt 与 Skill 对照保留原始结果和模型设置；无法登录的部分明确标为未验证。

## 你必须懂的 5 个问题

1. `search_notes` 报无权限时，增加 Skill 文字为什么不能解决？
2. 自动触发与显式 `/plugin:skill` 调用分别验证了什么？
3. 哪段内容属于描述、正文、附件？本次运行何时实际加载了它？
4. 为什么两个版本命中总数相同，依然可能出现回归？
5. 哪些证据说明 Plugin 可以搬到新目录，哪些证据才能说明模型按 Skill 工作？
