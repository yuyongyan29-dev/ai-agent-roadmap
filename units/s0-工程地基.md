# Stage 0 · 工程地基（W1–W3，60h）

**这一阶段的目的不是学会编程，是让你后面 23 周不被环境问题卡住。** 零基础的人跳过这里，会在 S1 第一次装依赖时就崩掉。

**贯穿整个阶段的一条纪律**：每一行代码你都要能口头解释。可以让 AI 解释给你听，但不能让 AI 替你写完你不看。

## U0.1 命令行与开发环境（4h）

**目标**：终端从此不再是黑盒，并装好后面 26 周要用的全部基础工具。

**具体做什么**

1. 打开「终端」（Terminal.app），或装 [iTerm2](https://iterm2.com/) 用它。
2. 装 Homebrew：照 [brew.sh](https://brew.sh) 首页那条命令跑。装完按提示把 `brew` 加进 PATH。
3. 用 brew 装：`brew install git gh uv` 三个。`uv` 是 Python 包管理器，2026 年新项目的默认选择，比 pip 快一到两个数量级。
4. 练这些命令，每个至少用 10 次：`pwd cd ls -la mkdir touch cp mv rm cat less head tail grep find wc`。
5. 理解三件事：绝对路径 `/Users/yanyan/x` 与相对路径 `./x`、`~` 代表你的主目录、`.` 开头的文件是隐藏文件。
6. 学管道和重定向：`ls | grep md`、`echo hi > a.txt`、`cat a.txt >> b.txt`。
7. 打开 `~/.zshrc` 看看里面是什么，理解它是每次开终端都会执行的脚本。

**完成判据**：不碰 Finder，纯命令行完成这一串——新建目录、用 `curl -O` 下载一个文件、用 `grep` 搜出含某关键词的行、把结果写进新文件、确认文件内容。

**常见卡点**：`command not found` 几乎总是 PATH 问题。先 `which 命令名` 看在不在，再 `echo $PATH` 看路径里有没有它所在的目录。

## U0.2 Git 与 GitHub（6h）

**目标**：代码有版本、有备份、有历史，出问题能回退。

**具体做什么**

1. 配置身份：`git config --global user.name` 和 `user.email`。
2. 在你的学习仓库里练完整流程：改文件 → `git status` → `git add` → `git commit -m` → `git push`。
3. 理解三个区域：工作区、暂存区（staging）、仓库。**`git status` 每一步都跑一次**，看每个命令让文件在三个区域之间怎么移动。
4. 分支：`git switch -c feature/x`，改点东西，`git switch main`，`git merge feature/x`。
5. **故意制造一次冲突**：在两个分支上改同一行，合并，手动解决冲突标记 `<<<<<<<` `=======` `>>>>>>>`。
6. 学会撤销：`git restore 文件`（丢弃工作区改动）、`git restore --staged 文件`（撤出暂存区）、`git revert 提交号`（反做一次提交）。
7. 写 `.gitignore`，理解为什么 `.env` 和 `node_modules/` 永远不能提交。

**产出**：你的学习仓库有 5 个以上语义清晰的 commit，有一个已合并的分支，有一次冲突解决记录。

**完成判据**：能口头解释 add 和 commit 的区别、merge 冲突为什么会发生、以及「我改错了还没提交」和「我提交错了已经推了」两种情况分别用什么命令救。

**资源**：[Learn Git Branching](https://learngitbranching.js.org/?locale=zh_CN) 交互式练习，中文，一小时能过完主线。

## U0.3 Python 语法基础（10h）

**目标**：能独立写出 100 行以内、有函数有异常处理的脚本。

**具体做什么**

跟 [CS50P](https://cs50.harvard.edu/python/)（哈佛 CS50 的 Python 入门，免费自学，十周内容）走前 7 周，但**不要看完就走，每周的 problem set 必须自己做完**。

这七周的主题依次是：函数与变量、条件、循环、异常、库、单元测试、文件读写。

补充练这些 Python 特有的东西：

1. 四种容器的区别与选择：`list`（有序可变）、`dict`（键值）、`set`（去重）、`tuple`（不可变）。
2. 列表推导式 `[x*2 for x in items if x > 0]`，这是 Python 代码里最高频的写法。
3. f-string：`f"{name} 有 {count} 条"`。
4. 字符串方法：`split strip join replace startswith`。
5. `with open(...) as f:` 读写文件，理解为什么要用 `with`。
6. `try/except/finally`，理解什么时候该捕获异常、什么时候该让它抛出去。

**产出**：`s0-foundation/csv_stats.py`

**完成判据**：不看任何资料，20 分钟内写出「读一个 CSV、按某一列分组、统计每组的数量和均值、输出成 JSON 文件」，且能处理文件不存在和某行数据格式错误两种异常。

**常见卡点**：缩进错误、可变默认参数、`is` 和 `==` 混用。遇到报错先读最后一行，Python 的错误信息比大多数语言都友好。

## U0.4 Python 工程化（8h）

**目标**：从「写脚本」升级到「写项目」。这一步决定你的代码别人能不能用。

**具体做什么**

1. **uv 管项目**：`uv init my-project` → `uv add httpx pydantic` → `uv run python x.py`。理解 `pyproject.toml` 和 `uv.lock` 分别记录什么，为什么要有虚拟环境。
2. **包结构**：把 U0.3 的单文件拆成 `src/csvstats/{__init__.py,reader.py,stats.py,cli.py}`，理解 `import` 的查找规则。
3. **类与对象**：`class`、`__init__`、实例方法、`@dataclass`。不用学继承的复杂用法，够用就行。
4. **类型注解**：给所有函数加上参数和返回值类型。装 `ty`（Astral 出的类型检查器）或 `mypy` 跑一遍，把报错改干净。
5. **Pydantic**：用 `BaseModel` 定义数据结构，体会「数据进来先校验」的价值。这是后面整个 Agent 项目结构化输出的基础，非常重要。
6. **logging**：把所有 `print` 换成 `logging`，理解 DEBUG/INFO/WARNING/ERROR 四个级别该怎么用。
7. **代码格式**：`uv add --dev ruff`，`ruff check --fix` 和 `ruff format`。以后每次提交前跑一遍。

**产出**：`s0-foundation/csvstats/` 完整项目，有 `pyproject.toml`、包结构、全量类型注解、Pydantic 模型。

**完成判据**：删掉 `.venv` 目录，在一台干净环境上 `uv sync && uv run csvstats data.csv` 能直接跑通。

## U0.5 HTTP 与 API（6h）

**目标**：能只看官方文档就调通一个陌生的 API。这是后面调所有模型 API 的前提。

**具体做什么**

1. 理解 HTTP：方法（GET/POST/PUT/DELETE）、状态码（2xx/4xx/5xx 各代表什么）、请求头、请求体、查询参数。
2. 认证方式三种：`Authorization: Bearer xxx`、`X-API-Key: xxx`、OAuth。知道各自长什么样。
3. 用 `curl` 手动发一次请求，再用 Python 的 `httpx` 发一次同样的请求。理解两者是一回事。
4. 学会读 OpenAPI/Swagger 文档：找到端点、必填参数、响应结构、错误码。
5. **密钥管理**：装 `python-dotenv`，密钥写进 `.env`，代码里用 `os.getenv` 读。`.env` 进 `.gitignore`。**从今天起，任何密钥都不许出现在代码里。**
6. 处理真实世界的问题：超时设置、失败重试（用 `tenacity` 库）、限流退避。

**产出**：`s0-foundation/api_client.py`

**完成判据**：挑一个你没用过的公开 API（比如 [GitHub REST API](https://docs.github.com/rest)），**只读官方文档不看教程**，写出带认证、超时、重试的调用代码。

## U0.6 FastAPI 写服务（8h）

**目标**：你的代码从「自己跑」变成「别人能调」。

**具体做什么**

1. `uv add fastapi uvicorn`，跑通官方 [FastAPI 教程](https://fastapi.tiangolo.com/zh/tutorial/)（有中文版）的前八节。
2. 把 U0.4 的 csvstats 包成 API，至少四个端点：上传文件、查询统计、列出历史、删除记录。
3. 用 Pydantic 定义请求体和响应模型，体会自动校验的价值。
4. 打开 `http://localhost:8000/docs`，理解这个交互式文档是自动从你的类型注解生成的。
5. 学依赖注入 `Depends`：把「读配置」「验身份」这类横切逻辑抽出来。
6. 学异常处理：自定义异常 + `@app.exception_handler`，让错误返回统一的 JSON 结构。
7. **理解 async**：`async def` 和 `def` 的区别、什么时候该用 async（IO 密集）、`await` 在等什么。后面所有 Agent 代码都是异步的，这里必须搞懂。

**产出**：`s0-foundation/api/`

**完成判据**：在 `/docs` 页面上点着把四个端点全跑通，包括故意传错参数看到 422 校验错误。

## U0.7 测试（6h）

**目标**：改代码不再靠祈祷。这也是 S3 评估体系的思维基础。

**具体做什么**

1. `uv add --dev pytest pytest-cov`，写第一个 `test_xxx.py`。
2. 理解 AAA 结构：Arrange 准备、Act 执行、Assert 断言。
3. `@pytest.fixture` 准备可复用的测试数据。
4. `@pytest.mark.parametrize` 一次跑多组输入。
5. **Mock 外部依赖**：用 `pytest-httpx` 或 `unittest.mock` 把 U0.5 的 HTTP 调用假掉，让测试不依赖网络。这个技能在 S3 测 Agent 时会天天用。
6. 用 `pytest --cov` 看覆盖率，找出没被测到的分支。
7. 用 `httpx.AsyncClient` 测 FastAPI 端点。

**产出**：`s0-foundation/tests/`

**完成判据**：覆盖率 70% 以上；断网状态下 `pytest` 全绿。

## U0.8 数据库（6h）

**目标**：数据能存下来、查得快、不会写坏。

**具体做什么**

1. `brew install postgresql@17 && brew services start postgresql@17`，或者直接用下一单元的 Docker 起。
2. 用 `psql` 手写 SQL：`CREATE TABLE`、`INSERT`、`SELECT ... WHERE`、`UPDATE`、`DELETE`、`JOIN`、`GROUP BY`、`ORDER BY`、`LIMIT`。
3. 理解索引：给一个十万行的表加索引前后各跑一次 `EXPLAIN ANALYZE`，看耗时差多少。
4. 理解事务：`BEGIN / COMMIT / ROLLBACK`，以及什么操作必须放在一个事务里。
5. 用 [SQLModel](https://sqlmodel.tiangolo.com/)（FastAPI 作者写的，Pydantic + SQLAlchemy 的结合）接进 U0.6 的服务。
6. 学数据库迁移：`uv add alembic`，改一次表结构并生成迁移文件。

**产出**：U0.6 的 API 数据持久化到 Postgres。

**完成判据**：重启服务后数据还在；能写出一个带 JOIN 和 GROUP BY 的查询。

**为什么是 Postgres 而不是别的**：S2 做 RAG 时直接装 `pgvector` 扩展就能当向量库用，不用再学一套新东西。

## U0.9 Docker（6h）

**目标**：「在我机器上能跑」这句话从此作废。

**具体做什么**

1. 装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 或 [OrbStack](https://orbstack.dev/)（Mac 上更轻更快）。
2. 理解三个概念：镜像（模板）、容器（运行实例）、卷（持久化数据）。
3. 手敲一遍常用命令：`docker run / ps / logs / exec -it / stop / rm / images`。
4. 给 U0.6 的服务写 `Dockerfile`：选基础镜像、装依赖、拷代码、暴露端口、定义启动命令。用多阶段构建减小镜像体积。
5. 写 `compose.yaml`，把 API 和 Postgres 编排在一起，配好网络、卷、环境变量、依赖顺序。
6. 理解 `.dockerignore` 和为什么要有它。

**产出**：`s0-foundation/Dockerfile`、`s0-foundation/compose.yaml`

**完成判据**：`docker compose up` 一条命令起全套，`docker compose down -v` 清干净，再 up 一次数据从头开始。
