# Stage 3 · 评估与可观测性（W17–W21，80 小时）

**这是整个计划里最值钱的四周。**

会做 Agent demo 的人很多，能证明自己的 Agent 好在哪、坏在哪、这次改动是变好还是变坏的人很少。面试里这也是最能拉开差距的部分。

---

## 开始前必读

Anthropic《[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)》（2026-01-09）。**整个 S3 的方法论建立在它之上。**

它最关键的几条：

- **从 20 到 50 个来自真实失败的任务开始就够了**，早期改动的效果差异大，小样本足以给出信号
- **好任务的标准是「两个领域专家独立判断会得出相同的通过/失败结论」**
- 三类评分器互补：**代码型**（确定、快、便宜）、**模型型**（灵活、处理细微差别）、**人工**（校准的黄金标准）
- **评结果，不评具体的工具调用序列**，否则会惩罚模型找到的更好解法
- 构建**隔离的环境**，防止试次之间共享状态
- **定期读原始记录**，验证评分器真的在评你以为它在评的东西
- 分数接近 100% 时评估集就**饱和**了，不再有信号
- 原文的态度值得抄下来贴在墙上：**「在有人真正深入细节之前，我们不会把评估分数当真。」**

## 这一阶段的三条纪律

**能用规则判的绝不用模型判。** 代码型评分器确定、快、免费。LLM judge 只用在规则判不了的地方，而且必须校准。

**修任何 bug 之前，先给它写一条评估题。** 顺序不能反。先修再补题，你补出来的往往是「刚好能被你的修复通过」的题。

**定期读原始记录。** 每次跑完评估抽 5 条通过的题人工读一遍。**这十分钟能防止你在一个假象上优化几周。**

---

## 三样最有说服力的产出

做完 S3，你手上会有三样东西，面试时直接拿出来：

1. **CI 拦截劣化 PR 的截图**——证明你的门禁真的有用
2. **一次完整闭环的记录**——真实失败 → trace → 评估题 → 修复 → 回归验证
3. **Judge 校准报告**——一致率、混淆矩阵、三种偏见的测试数据

**这三样展示的是工程能力，不是使用工具的能力。**
