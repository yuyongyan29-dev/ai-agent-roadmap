# 项目结构：七个阶段怎么串成一个东西

**这份文件解决一个我在计划里漏掉的问题**：`s0-foundation/`、`s1-llm/`、`s2-agent/` 这些目录，**它们之间怎么互相 import？**

不搞清楚这个，你会在 S2 遇到「我 S1 写的 `llm_kit` 怎么在 S2 里用」这个卡点。

---

## 一、整体形态：一个 uv workspace

**七个阶段是同一个 workspace 里的七个包**，不是七个独立项目。

```
ai-agent-roadmap/
├── pyproject.toml          # workspace 根配置
├── uv.lock                 # 唯一的锁文件，所有成员共享
├── .venv/                  # 唯一的虚拟环境
│
├── s0-foundation/
│   └── csvstats/
│       ├── pyproject.toml
│       └── src/csvstats/
├── s1-llm/
│   ├── pyproject.toml
│   └── src/llm_kit/
├── s2-agent/
│   ├── pyproject.toml
│   └── src/agent_core/
├── s3-eval/
├── s4-production/
├── s5-frontend/            # 前端不进 workspace，是独立的 pnpm 项目
└── s6-platform/
```

**关键好处**：`s2-agent` 可以直接 `from llm_kit import LLM`，改 `llm_kit` 的代码 S2 立刻生效，不用重新安装。

---

## 二、什么时候建立 workspace

**U0.4 之后，你有了第一个 uv 项目时。**

在仓库根目录建 `pyproject.toml`：

```toml
[project]
name = "ai-agent-roadmap"
version = "0"
requires-python = ">=3.13"

[tool.uv.workspace]
members = [
    "s0-foundation/*",
    "s1-llm",
    "s2-agent",
    "s3-eval",
    "s4-production",
    "s6-platform/*",
]
```

**然后**：

```bash
uv sync
```

**验证**：根目录出现一个 `.venv/`，各阶段目录下**没有**各自的 `.venv/`。

## 三、阶段之间怎么依赖

### 声明依赖

在需要引用别的阶段的那个 `pyproject.toml` 里：

```toml
# s2-agent/pyproject.toml
[project]
name = "agent-core"
dependencies = ["llm-kit"]           # 依赖 S1 的包

[tool.uv.sources]
llm-kit = { workspace = true }       # 告诉 uv 从 workspace 里找，不是从 PyPI
```

**`[tool.uv.sources]` 里的 `workspace = true` 是关键。** 不写的话 uv 会去 PyPI 上找一个叫 `llm-kit` 的包，然后报找不到。

### 实际的依赖链

```
s0-foundation/csvstats   （独立，不被别人依赖）
        │
        │ 提供的是「工程骨架」，不是代码
        ↓
s1-llm (llm_kit)
        ↑
        ├──────────────── s2-agent (agent_core)
        │                        ↑
        │                        ├─── s3-eval
        │                        ├─── s4-production
        │                        └─── s6-platform/runtime
        │
        └──────────────── s3-eval 也直接用（judge 要调模型）
```

**用一条命令确认**：

```bash
uv tree
```

## 四、S0 的 csvstats 到底怎么承接

**这是我原来没说清楚的地方。** 我说过「M0 是你后面所有 Agent 项目的骨架」，但没说怎么承接。

**答案：承接的是结构和配置，不是代码。**

| 从 csvstats 拿走的 | 怎么用 |
|---|---|
| **目录结构**（`src/包名/`、`tests/`、`pyproject.toml`） | S1 到 S6 的每个项目都照这个结构建 |
| **`compose.yaml`** | S2 加 pgvector，S3 加 Langfuse，一路扩展同一个文件 |
| **`Dockerfile`** | S4 部署时改改就能用 |
| **FastAPI 的骨架**（依赖注入、异常处理、`/health`） | S4 的 U4.3 做异步接口时直接沿用 |
| **测试的写法**（fixture、mock、TestClient） | S3 建评估运行器时同一套思路 |
| **`.env` + `os.getenv` 的密钥管理** | 全程 |

**csvstats 本身的业务代码（CSV 统计）确实用不上了。** 它的价值是让你把这些工程习惯练熟，而不是留下一段可复用的代码。

**具体怎么做**：S1 开始时，不要从零 `uv init`，而是：

```bash
cp -r s0-foundation/csvstats s1-llm-temp
cd s1-llm-temp
# 删掉业务代码，保留结构、配置、测试骨架
rm -rf src/csvstats tests/test_stats.py
mkdir -p src/llm_kit
# 改 pyproject.toml 里的包名
```

**或者更简单**：对着 csvstats 的结构手动建一遍。**手动建一遍记得更牢。**

## 五、共享的东西放哪

有些东西七个阶段都要用（比如数据库连接、日志配置、密钥读取）。

**建一个 `shared/` 包**：

```
shared/
├── pyproject.toml
└── src/shared/
    ├── config.py       # 统一的配置加载（读 .env）
    ├── db.py           # 数据库引擎和 session
    └── logging.py      # 统一的日志配置
```

**什么时候建**：**不要提前建。** 等你第三次复制粘贴同一段代码时再抽出来。

（S1 只有一个包，不需要；S3 开始你会发现 S2 和 S3 都要连数据库，那时再抽。）

## 六、前端是独立的

`s5-frontend/` 不进 uv workspace，它是 Node 生态：

```
s5-frontend/
├── llm-kit-ts/         # U5.1 的产出，独立 pnpm 项目
├── chat-ui/            # U5.2
├── web/                # U5.3-U5.5、U5.7
└── miniapp/            # U5.6
```

**前端和后端通过 HTTP 通信，不共享代码。** 类型可以共享（从 OpenAPI 生成 TypeScript 类型），但那是可选的优化。

## 七、一条命令验证全局

在仓库根目录：

```bash
uv sync                          # 装齐所有阶段的依赖
uv run pytest                    # 跑所有阶段的测试
uv run ruff check .              # 检查所有代码
docker compose up -d             # 起所有服务（db + langfuse + api）
```

**这四条命令能跑通，说明你的项目结构是对的。**

把它们写进 `CLAUDE.md`（U0.10 做的那个文件），agent 就知道怎么验证它的改动。

## 八、常见问题

**`ModuleNotFoundError: No module named 'llm_kit'`**

三个可能：

1. 没在 workspace 的 members 里 → 检查根 `pyproject.toml`
2. 没声明依赖 → 检查 `s2-agent/pyproject.toml` 的 `dependencies` 和 `[tool.uv.sources]`
3. 没 `uv sync` → 跑一下

**各阶段目录下还有自己的 `.venv/`**

说明你在子目录里跑过 `uv init` 或 `uv sync`。**删掉它们**，在根目录跑 `uv sync`。

```bash
find . -name ".venv" -maxdepth 3 -not -path "./.venv" -exec rm -rf {} +
uv sync
```

**要不要一开始就建 workspace**

**不用。** U0.4 时你只有一个项目，直接 `uv init` 就行。**等 S1 开始、有第二个包时再改成 workspace。**

改的时候只要在根目录加一个 `pyproject.toml`，把已有的项目列进 members，然后 `uv sync`。已有的代码不用动。
