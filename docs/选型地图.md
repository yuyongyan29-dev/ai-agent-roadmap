# 技术选型地图：每一层有什么可选，我们选了什么，什么时候该选别的

[技术栈](技术栈.md)那份文档只写「我们选了什么」。这份回答另外两个问题：**这一层市面上还有什么**，以及**什么情况下你该做不同的选择**。面试里「为什么用 X 不用 Y」问的就是这个。

两条原则先说在前面：

- **一个人、一个项目，每层只选一个。** 这份地图是让你知道自己没选的是什么，不是让你都学一遍。
- **迁移成本比选对更重要。** 下面每层都标了「换掉它要多久」。换起来便宜的，选错也没事；换起来贵的（数据库、小程序框架），多想十分钟。

数据来源：本计划核验过的 84 条 2026 年国内外 Agent / AI 应用岗位 JD（方法见[数据可靠性](数据可靠性.md)）。没有 JD 数据支撑的判断会明确标出来。

---

## 一、编程语言

| 语言 | 在 Agent 领域的位置 | 84 条 JD 里 | 什么时候选它 |
|---|---|---|---|
| **Python** | 默认语言。所有模型 SDK、Agent 框架、评估工具都 Python 优先 | 出现最多，多数岗位的硬要求 | **默认选它**，除非团队已经全是别的 |
| **TypeScript** | 前端唯一选择；后端在 Vercel AI SDK、Mastra 这条线上也成立 | 前端 / 全栈岗必备 | 前端和小程序必须；全栈一个人做想少切语言时后端也可以用 |
| **Go** | 平台基建、网关、高并发服务 | 大厂 26 条 + 通用后端 10 条里出现 11 次；海外 14 条 + 创业 21 条里 **0 次** | 目标是大厂平台基建团队 → 见[扩展模块 B](扩展模块-B.md)；做应用层不需要 |
| **Java** | 国内大厂存量系统的主体 | 同上，10 次，同样只在大厂和通用后端 | 只有目标岗位明确要求时才补；Agent 新项目几乎没人用它起步 |
| Rust | 性能敏感的基础组件（uv、Ruff 就是 Rust 写的） | 0 次 | 不在本计划范围 |

**我们的选择**：Python 主、TypeScript 副。**换掉的成本**：语言是最难换的一层，因为它连着整个生态。所以这一层的选择跟着目标岗位走，不跟着个人喜好走。

---

## 二、后端框架

| 框架 | 语言 | 特点 | 什么时候选它 |
|---|---|---|---|
| **FastAPI** | Python | 异步、Pydantic 校验、自动 OpenAPI 文档；Agent 后端的事实标准 | **默认** |
| Django | Python | 全家桶，自带 ORM、后台、认证 | 做的是传统 CRUD 业务系统、需要现成后台；Agent 项目用它偏重 |
| Flask | Python | 极简 | 老项目维护；新项目没理由不用 FastAPI |
| **Next.js Route Handlers / Server Actions** | TS | 前后端一体 | 后端逻辑很薄、主要是转发模型调用时，可以不单独起后端。**本计划 U5.3 就是这么用的**，但重活仍在 FastAPI |
| Hono / Express / NestJS | TS (Node) | Hono 轻、跑在边缘；NestJS 像 Java Spring | 团队是 TS 全栈、后端要部署到 Cloudflare Workers 或 Vercel Functions |
| Gin / Echo | Go | 快、简单 | 平台层网关、高并发 API |
| Spring Boot | Java | 国内大厂存量 | 岗位明确要求 |

**我们的选择**：FastAPI 做重后端，Next.js 做前端和薄的 BFF。**Node 后端怎么部署**：和 Python 一模一样——打成 Docker 镜像走 [U4.9](../units/s4/U4.9-基础设施实操.md) 那条流水线，或者放到 Vercel / Cloudflare 的函数上。`pm2` 只在不用容器、直接在服务器上跑 Node 进程时才需要，本计划不用。

**换掉的成本**：中。业务逻辑如果写在框架无关的模块里（U0.4 教的分层），换框架是重写路由层，几天的事。

---

## 三、前端框架

| 框架 | 特点 | 什么时候选它 |
|---|---|---|
| **Next.js（React）** | 生态最大，Vercel AI SDK 原生支持，Server Component 让密钥不出服务端 | **默认** |
| Nuxt（Vue） | Vue 生态里的 Next.js | 你或团队已经会 Vue；国内中小公司 Vue 占比高 |
| Remix / React Router v7 | 更贴近 Web 标准 | 偏好它的心智模型；生态小于 Next |
| Vite + React（纯 SPA） | 没有服务端 | 纯后台管理界面、不需要 SEO、不需要保护密钥（密钥在独立后端） |
| SvelteKit / SolidStart | 更轻更快 | 个人项目尝鲜；招聘市场小 |

**我们的选择**：Next.js。理由只有一条：React 一次学会，Web、小程序（Taro）、App（Expo）三端复用。**换掉的成本**：组件逻辑可以搬，路由和数据获取要重写，一到两周。

## 四、小程序与 App

| 方案 | 语法 | 特点 | 什么时候选它 |
|---|---|---|---|
| **Taro** | React | 京东开源，一套代码出微信 / 支付宝 / 抖音小程序 + H5 + RN | **默认**，因为复用 S5 的 React |
| **uni-app** | Vue | DCloud 出品，**国内小程序开发里最常见的框架**，生态和插件市场最大，还能出 App | 你会 Vue、或者接手的项目是 uni-app。**这是国内招聘里出现频率不低于 Taro 的选项**，看到不要陌生 |
| 微信原生 | WXML/WXSS | 官方，功能最全最新 | 只做微信一个平台、要用刚发布的新能力 |
| **Expo（React Native）** | React | App 的默认选择，云端打包，OTA 更新 | **默认**，见 U5.8 |
| Flutter | Dart | 性能好、UI 一致 | 团队有 Flutter 经验；一个人学新语言不划算 |
| uni-app x / 原生 | — | 极致性能 | 不在本计划范围 |

**我们的选择**：Taro + Expo，都是为了不学第二套 UI 框架。**如果你的起点是 Vue**，把「Next.js + Taro」整体换成「Nuxt + uni-app」是自洽的，本计划的架构、后端、部署部分全部不变。**换掉的成本**：高。小程序框架一旦定了，换等于重写，所以 U5.0 让你先想清楚。

## 五、数据库

| 类型 | 代表 | 放什么 | 什么时候选它 |
|---|---|---|---|
| **关系型：PostgreSQL** | — | 业务数据、任务状态、会话；加 pgvector 后连向量也放这 | **默认**。一个系统解决结构化 + 向量，少运维一个东西 |
| 关系型：MySQL | — | 同上，但没有 pgvector 这种级别的向量支持 | 公司存量是 MySQL；**84 条 JD 里 MySQL 出现 0 次**，但国内通用后端岗仍普遍要求。SQL 九成相同，Postgres 会了换 MySQL 是一周的事 |
| 嵌入式：SQLite | — | 单机、本地、边缘 | 命令行工具、桌面端、App 本地缓存（U5.8 用 expo-sqlite）；多进程并发写不行 |
| 文档型：MongoDB | — | 结构多变的 JSON | 数据形状真的不固定；Agent 项目里 Postgres 的 JSONB 通常够了 |
| 键值 / 缓存：Redis | — | 可丢的热数据：缓存、限流、锁、队列 | 见 U0.11、U4.9；**不放会导致不一致的状态** |
| **向量：pgvector** | Postgres 扩展 | 百万级以内的向量 | **默认**，见 U2.5 |
| 向量：Milvus / Qdrant / Weaviate | 独立服务 | 千万级以上、需要独立扩缩容 | 你实测 pgvector 在自己的数据量上不够快之后再换，不要提前 |
| 向量：托管（Pinecone、Zilliz） | SaaS | 不想运维 | 海外项目、预算允许 |
| 分析型：ClickHouse / DuckDB | — | 日志、trace、成本明细的聚合查询 | U3.8 成本看板数据量大了以后；DuckDB 本地分析用 |
| 图：Neo4j | — | 关系密集的知识图谱 | 明确需要多跳关系查询；大多数 RAG 不需要 |

**我们的选择**：Postgres + pgvector + Redis，三样解决 S0 到 S6 的全部需求。**换掉的成本**：数据库是除语言外最贵的一层，因为要迁数据。选它的理由不是「最好」，是「一个人能管得过来、并且十万用户以内不用换」。

## 六、缓存、队列、长任务

| 需求 | 我们用 | 别的选项 | 什么时候换 |
|---|---|---|---|
| 缓存 | Redis | Memcached、本地 LRU | 基本不用换 |
| 任务队列 | Postgres 表 + `FOR UPDATE SKIP LOCKED`（U4.3） | Redis 队列、RabbitMQ、Kafka、云厂商消息队列 | 每秒任务数上千、或者需要多消费者组时上专用队列；**之前用 Postgres 的好处是任务状态和业务数据同一个事务** |
| 定时任务 | systemd timer（U4.9） | cron、APScheduler、云函数定时触发 | 多台机器时用云厂商的 |
| 流式推送 | SSE（U4.3） | WebSocket | 需要双向、或者小程序（不支持 SSE，U5.6） |

## 七、对象存储与 CDN

| 选项 | 什么时候选它 |
|---|---|
| **腾讯云 COS / 阿里云 OSS** | 服务器和用户在国内，**默认** |
| **Cloudflare R2** | 用户在海外；出站流量免费，个人项目省钱最多 |
| AWS S3 | 已经在 AWS 上 |
| MinIO（自建） | 本地开发、预览环境 |
| CDN | 图片、落地页静态资源、小程序素材前面加；API 前面不加 |

全部兼容 S3 API，代码只换 endpoint，见 U4.9 步骤 5。

## 八、部署与托管

按「你把多少运维交出去」从少到多排：

| 层级 | 选项 | 适合 | 长任务后端 |
|---|---|---|---|
| **一台云服务器 + Docker** | 阿里云 / 腾讯云轻量服务器、境外 VPS | **本计划默认**，最可控，学到的东西最多 | ✅ |
| Serverless 容器 | 阿里云 SAE、腾讯云 CloudBase 云托管、Fly.io、Railway、Render | 不想管机器；按量付费 | ✅（注意冷启动） |
| 函数计算 | 阿里云 FC、腾讯云 SCF、AWS Lambda、Vercel Functions、**Cloudflare Workers** | 短请求、事件触发、边缘逻辑 | ❌ 有执行时长 / CPU 限制，**不适合跑 Agent 主循环** |
| 前端专用平台 | **Vercel**、Cloudflare Pages、CloudBase 静态托管 | Next.js 前端、落地页 | 前端不涉及 |
| 容器编排 | Kubernetes | 多服务、多团队、大厂 | 84 条 JD 里 K8s 出现 0 次；见扩展模块 B |

**Cloudflare 单独说一句**：Pages + Workers + R2 + D1 是海外个人开发者最省钱的一套，免费额度慷慨。**但国内访问 Cloudflare 网络不稳定**，而且 Next.js 上 Cloudflare 要走 OpenNext 适配层，不是开箱即用。用户在海外选它没问题；用户在国内，它不是你的选项。

**我们的选择**：后端一台服务器 + Docker（U4.0、U4.9、U4.7），前端 Vercel 或 CloudBase（U5.7）。理由是学习价值：在一台机器上亲手搭过全套，之后无论换到哪个托管平台，你都知道它替你做了什么。

## 九、可观测性与 CI

| 层 | 我们用 | 别的选项 |
|---|---|---|
| LLM trace 与评估 | Langfuse 自托管（U3.5） | LangSmith、Arize Phoenix、Helicone、云厂商的 |
| 通用指标与日志 | 结构化 JSON 日志 + 告警 webhook（U4.7） | Grafana + Prometheus + Loki、云厂商日志服务 |
| CI/CD | GitHub Actions（U3.7、U4.9） | GitLab CI、Gitee Go、Jenkins（国内存量） |

埋点遵循 OpenTelemetry GenAI 语义约定，换平台不用重写，这是这一层最重要的决策。

## 怎么用这份地图

**S1 结束时（U1.8）**：给你的主线项目写一份 `TECH.md`，每一层一行：选了什么、为什么、没选的是什么、什么信号出现时会换。**这份文件在 S6 面试准备时直接变成「系统设计」题的答案。**

**看到 JD 里陌生的技术名词时**：先在这里找它属于哪一层、是我们选的那个的替代品还是补充。是替代品就不用慌，你会的那个能讲清楚差异就够；是没覆盖的层，再决定要不要补。

**这份地图也会过期。** 每一行的判断都标了依据，发现不对请按 [CONTRIBUTING.md](../CONTRIBUTING.md) 提 issue。
