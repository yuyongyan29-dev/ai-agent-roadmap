# 从这里开始

这份文件回答一个问题：**打开 VS Code 之后，具体第一步做什么。**

---

## 一、今天的 60 分钟（做完就算正式开始）

### 第 1 步：装 VS Code（10 分钟）

去 [code.visualstudio.com](https://code.visualstudio.com/) 下载安装。

### 第 2 步：用 VS Code 打开这个仓库（1 分钟）

先在 GitHub 上 Fork 本仓库，再把你的 fork clone 到本地（没装 git 的话先跳去 U0.1 装完再回来，或者先点 GitHub 页面上的 `Code → Download ZIP` 解压，等 U0.2 学了 git 再换成 clone）：

```bash
git clone https://github.com/<你的用户名>/ai-agent-roadmap.git ~/ai-agent-roadmap
```

然后菜单 `File → Open Folder`，选 `ai-agent-roadmap` 文件夹。**本教程所有命令都假设仓库在 `~/ai-agent-roadmap`**，放别处就把路径换成你的。

打开后 VS Code 右下角会弹「此工作区有推荐的扩展」，**点「安装」**。这会装上仓库里 `.vscode/extensions.json` 预设的 20 个插件，包括中文界面包、Python 全套、Git 增强、Docker、数据库客户端。不弹的话按 `Cmd+Shift+X` 打开扩展面板，搜索框输入 `@recommended`，逐个装。

装完重启 VS Code，界面变中文。

### 第 3 步：认识三个面板（10 分钟）

只需要先认识这三个，其余以后自然会用到。

| 快捷键 | 面板 | 什么时候用 |
|---|---|---|
| `Cmd+Shift+E` | 资源管理器 | 看文件树，找文件 |
| `` Ctrl+` `` | 终端 | **你 90% 的时间在这里**，跑命令、看报错 |
| `Cmd+Shift+G` | 源代码管理 | 看改了什么、提交、推送 |

再记两个：`Cmd+P` 按文件名跳转，`Cmd+Shift+F` 全局搜索。

### 第 4 步：打开第一个单元（5 分钟）

`Cmd+P`，输入 `U0.1`，回车打开 `units/s0/U0.1-命令行与开发环境.md`。

S0 的 13 个单元每个一个文件，都在 `units/s0/` 里。目录见 [`units/s0/README.md`](../units/s0/README.md)。

按 `Cmd+Shift+V` 打开 Markdown 预览。**建议左边放单元文档，右边放终端**，边看边做。

### 第 5 步：开始 U0.1（剩下的时间）

从「U0.1 命令行与开发环境」的第 1 条开始，一条一条往下做。

## 二、每个单元的固定五步

**主线共 65 个单元，按这个循环逐个推进，39 周就走完了。** 不要发明新流程，照这五步走。

**① 读**（15 分钟）
打开单元文档，先把整个单元通读一遍，**特别是最后的「完成判据」**。你要带着「我最后要交出什么」的目标开始，而不是读一步做一步。

每个单元的每一步都分四段：**这一步在做什么 / 怎么做 / 可能卡在哪 / 背后的逻辑**。「怎么做」交给 agent 协作实现，你亲自验收，「可能卡在哪」不要跳过，「背后的逻辑」第一遍看不懂就做完再回头看。

**② 建目录**
在仓库里建这个单元的工作目录，比如 `s0-foundation/`。复制 `templates/单元笔记模板.md` 到目录里改名成 `U0.1-笔记.md`。

**学完 U0.12 之后，这一步变成开一个 worktree**：`wt-new unit/U1.3-structured-output`。每个单元一个隔离的工作目录，改坏了整个删掉不影响主线。

**③ 做**（这个单元的绝大部分时间）
按文档里的编号步骤逐条执行。每完成一条，在笔记里记一句你实际做了什么——**不是抄步骤，是写你实际遇到了什么**。

**④ 验**
对照「完成判据」逐条检查。**判据没达到就不算完成**，宁可多花半天。在笔记的判据表里填上证据（命令输出、截图路径、文件路径）。

**⑤ 交**
```bash
git add -A
git commit -m "U0.1: 完成命令行与开发环境"
git push
```
然后到你 fork 里的进度表（从 [`周计划.md`](周计划.md) 复制到 `logs/进度.md`）填上这一行，回单元文档把 `- [ ]` 改成 `- [x]`。

## 三、每天怎么安排

每周 20 小时，建议这么切：

| 时段 | 时长 | 做什么 |
|---|---|---|
| 工作日每天晚上 | 2h | 一个时间盒，只推进当前单元 |
| 周六 | 5h | 大块时间，啃硬骨头（通常是当周最难的那个单元） |
| 周日上午 | 1h | 补齐判据、补测试 |
| 周日下午 | 4h | **写周复盘**，复制 `templates/周复盘模板.md` 到 `logs/2026-Wxx.md` |

**周复盘是唯一不能省的一项。** 它是把「做过」变成「会讲」的地方，39 周后你的面试素材全在这里。

## 四、agent 写、你审、你验

这份计划里的代码主要由编码 agent 写。U0.0 会用四小时把这套工作方式建立起来，这里只说规矩。

**每次交给 agent 一个任务，给它三样东西**：目标、约束、验收命令。第三样最重要，没有它 agent 在「看起来做完了」的时候就停，你成了唯一的验证者。

**它做完之后你做三件事**：审 diff（碰了哪些文件、有没有放宽约束）、自己跑验收（它说通过和你看到通过是两件事）、读懂（每个单元「你读懂」那几个问题必须能口头回答）。

**S0 和 S1 阶段的规矩**：agent 写的每一段代码你必须能讲清楚它在做什么、为什么这样写。看不懂就让它解释到你懂，还不懂就让它改简单。自检一句话：**断网了这段代码报错，你能不能自己修。**

**好的提问方式**

```
逐行解释这段代码，假设我完全没学过编程。
  <贴代码>

这段报错是什么意思？先告诉我崩在哪一行、谁调用的它、bug 可能在哪，不要直接改。
  <贴报错>

这段能不能更简单？改完解释为什么更简单。
```

**分界线在 S2。** 从 S2 开始你可以放松对每一行的追问，因为那时你已经能判断它写得对不对。但架构决策——用不用多 Agent、选哪个框架、怎么切分工具——**必须你自己做并写清楚理由**，这些正是面试要问的。**唯一的例外是 U2.1 那 200 行 Agent 循环，要求亲手写。**

## 五、卡住了怎么办

按这个顺序升级，**不要跳级**：

1. **自己撞 30 分钟**。读报错的最后一行，Google 报错原文，看官方文档。这 30 分钟是必要的，你的调试能力就是这么长出来的。
2. **问 AI 要解释**，用上面的提问模板。
3. **降低范围**。写一个 5 行的最小复现，把无关的东西全删掉。**很多时候删到一半你就自己发现问题了。**
4. **跳过，标记，继续**。在笔记里写「TODO: 这里没搞懂 xxx」，先往下走。Todo Tree 插件会把所有 TODO 收集到侧边栏，下次复盘时回来清。
5. **一个单元卡超过 2 天**，说明前置知识缺了。回头看这个单元依赖哪个前置单元，补那个。

## 六、前三天的具体清单

不用想，照做。

- [ ] 用 VS Code 打开本仓库
- [ ] U0.0 步骤 1-3：装 Claude Code，plan mode 让它讲仓库并核对，`greet.py` 三段式走完
- [ ] 建 `s0-foundation/` 目录，复制单元笔记模板

- [ ] U0.1 步骤 1-3：认识终端提示符，装 Homebrew，`brew install git gh uv`

**第一周结束时，你应该有**：一个装好工具的开发环境、一个有 5 个以上 commit 的 GitHub 仓库、一个能跑的 Python 脚本、一篇周复盘。

## 六点五、关于 Claude Code 和 Codex

**U0.0 是第一个单元，只装 Claude Code**，四小时建立三段式和三个保命操作。

**第 6 周的 U0.10 会把这件事做完整**：写 CLAUDE.md 和 AGENTS.md、配权限白名单和沙箱、探索-计划-实现-提交四阶段工作流、用 Git worktree 并行跑多个 agent、双会话交叉 review。

那个单元结束时，你会走通一次完整的流程：一个需求，从提出到合并 PR，12 步全部可复现。**之后 33 周你每天都会用这套流程。**

完整版放在第 6 周而不是第 1 周，是因为 worktree 和多 agent 并行需要你先有一个真实的项目才能练。
