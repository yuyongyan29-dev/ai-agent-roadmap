# 同步到飞书 / Notion（可选）

仓库本身就是完整的交付物，GitHub 和[网页版](https://yuyongyan29-dev.github.io/ai-agent-roadmap/)都能直接读。这份说明只给习惯在飞书或 Notion 里看文档、想在手机上勾进度的人。

**原则**：同步出去的是查看端，代码和判据证据以你自己的仓库为准。不要在飞书里改内容再想办法同步回来，那条路没有工具支撑。

## 生成合并文档

每个阶段合并成一份 Markdown：

```bash
python3 scripts/build_stage_doc.py s0        # 生成 _stage_s0.md
```

它按单元编号排序（U0.10 排在 U0.9 之后，而不是 U0.1 之后），把 `- [ ]` 判据转成飞书原生勾选框，开头加上飞书全文替换需要的 `<title>`。

给 Notion 用就加 `--plain`，不做飞书专用转换，Notion 自己认标准的任务列表语法。

## 导入飞书

**方式一：手动导入**。飞书云文档 → 新建 → 导入 → 选 `_stage_s0.md`。最省事，缺点是每次更新都要删了重导。

**方式二：lark-cli**。装好并登录 [lark-cli](https://github.com/larksuite/lark-cli) 之后，创建：

```bash
lark-cli docs +create --as user --doc-format markdown --content @./_stage_s0.md
```

更新已有文档（整篇替换）：

```bash
lark-cli docs +update --as user --doc <文档URL> --command overwrite \
  --doc-format markdown --content @./_stage_s0.md
```

两个已知坑：

- 整篇替换一个 15 万字以上的文档时，lark-cli 很可能返回 `server time out error`，**但写入实际上成功了**。等十秒再 fetch 一次确认，不要重试。
- `@./文件` 只接受当前目录下的相对路径，传绝对路径会报 `unsafe file path`。

## 一次同步全部七个阶段

```bash
for s in s0 s1 s2 s3 s4 s5 s6; do
  python3 scripts/build_stage_doc.py "$s"
done
```

然后逐个导入。`_stage_*.md` 已经在 `.gitignore` 里，不会误提交。
